## 〇、版本管控硬约束（版本由管理员控制，不可以串）

> "不可以串"含义：① 低版本租户**不能使用**高版本功能（API/前端/菜单三层拦截）；② 版本**只能由管理员（平台管理员 `platform_admin`）分配和调整**，租户侧任何角色无自助变更入口；③ 租户之间数据不串（`tenant_id` 行级隔离）；④ 版本变更全程留痕；⑤ 租户实际可用功能由 **License 授权** 决定（`platform_admin` 导入 License 激活，未导入则降级为基础版）；⑥ **【v1.12 新增】业态之间不串**：`biz_code` 决定业态包，租户只能使用本业态包声明的能力与文案，**跨业态菜单/字段/引擎策略不得泄露**。

### 0.1 防串纵深防御（v1.12 由**五层**扩展为**六层**）

| 层 | 机制 | 现状 | 落地任务 |
|----|------|------|----------|
| ① 版本分配入口 | 仅 `platform_admin` 可调 `assignVersion` + 导入 License（`@SaCheckRole("platform_admin")`） | ✅ 已实现 | T3.1 复核 + T3.10 License 导入 |
| ② API 层拦截 | `@RequireFeature` + `FeatureInterceptor`，版本不足直接抛"当前版本不支持此功能" | ✅ 框架已实现 | T4.1 开关编码对齐 + T6/T7 全部增量接口必须标注 |
| ③ 前端动态渲染 | `/system/edition/features` 下发能力配置，未解锁入口不显示 | ✅ 接口已存在 | T4.2 前端按配置渲染 + 路由兜底拦截 |
| ④ 菜单授权 | `sys_role_menu` 按版本授权模板分配，低版本租户不分配高版本菜单 | ⚠️ 无模板 | T2.2 三版本授权模板脚本 |
| ⑤ 数据隔离 | 全部业务表 `tenant_id` + `TenantLineInnerInterceptor` 自动拼接 | ✅ 框架已实现 | T1.4 新增表逐表检查 |
| ⑥ **业态与通道隔离**（v1.12 新增） | `biz_bundle.feature_flags` + `access_channel` 双重过滤；跨业态菜单/字段/引擎策略不泄露，跨通道接口不放行 | 🆕 待实现 | T10.2/T10.8 三维能力计算 + T13.4 通道适配 + T9.5 验收 |

> 第 ⑥ 层与第 ②③④ 层叠加后构成完整的三维判定：**版本（edition）∩ 业态包（biz_code）∩ License**，再叠加通道（access_channel）与单店覆盖（module_overrides）。《00_管理员操作手册》6.1 仍为五层表述，**待同步升版**。

### 0.2 补充约束

- **兜底原则**：菜单与版本解耦（菜单由角色控制），即使误给低版本租户分配了高版本菜单，② 层 API 拦截仍会拒绝——**②③ 层是防串底线，任何增量功能不得跳过**；
- **到期控制**：使用天数由管理员在租户管理中配置，到期后租户状态转 `EXPIRED`，登录与全部业务接口禁用（防"过期续用"串版本）；
- **留痕**：版本变更必须写入 `sys_tenant_version_log`（INIT/UPGRADE/DOWNGRADE），操作日志全覆盖；
- **降级保护**：降级（DOWNGRADE）时已产生的历史数据保留不删除，仅关闭增量入口；
- **admin 豁免**：`admin` 超管功能开关免检（既有策略），验收用例中不得以 admin 账号验证防串效果，必须用租户内普通角色验证。

### 0.3 三维能力模型（v1.12 新增，设计文档 1.4/1.7/1.8）

租户最终可用能力由**三个维度取交集**得出，任一维未授权即不可见且不可用：

```
有效功能 = feature_flag(edition 默认开启集)
           ∩ biz_bundle(biz_code).feature_flags     —— 业态包未声明的能力不开放
           ∩ License.features                       —— 未授权即不可用（无 License 降级基础版）
           ∪/− sys_tenant.features                  —— 租户级例外（platform_admin 单独加减）
```

| 维度 | 载体 | 新增字段/表 | 落地任务 |
|------|------|------------|----------|
| 业态包 | `sys_tenant.biz_code` → `biz_bundle` | `biz_bundle`（menus/copy/schema_blocks/engine_strategy/feature_flags JSON） | T1.7、T10.2 |
| 版本开关 | `sys_tenant.edition` → `feature_flag` | `feature_flag`（code/biz_code/basic_enabled/advanced_enabled/pro_enabled） | T1.7、T10.3 |
| 访问通道 | `sys_tenant.access_channel` | `access_channel` + `wecom_corp_id`/`wecom_agent_id`/`wecom_secret` | T1.8、T13.2 |
| 单店覆盖 | `tenant_biz_config.module_overrides` | `tenant_biz_config` | T1.7、T10.4 |

> **编码兼容硬约束**：`edition` 存量值为大写全名（`BASIC`/`ADVANCED`/`PROFESSIONAL`，另有 `ENTERPRISE`），需求文档使用小写短码（`basic`/`advanced`/`pro`）。统一由 `EditionFeatureConfig.normalizeEdition(String)` 归一化（`pro`→`PROFESSIONAL`），**不写迁移脚本、不改存量数据**（T10.7）。

### 0.4 双阶段租户识别（v1.12 新增，设计文档 1.8.4）

需求文档 7.2 要求「URL 参数 `?tenant=xxx` / 公众号 AppID 反查」识别租户，与 T1.6 / 设计文档 1.2 硬约束「`tenant_id` 绝不从 URL/参数/前端传入」**表面冲突**。按阶段拆分化解：

| 阶段 | 识别方式 | 可访问数据 | 硬约束 |
|------|---------|-----------|--------|
| **引导态**（登录前） | URL `?tenant=xxx` / 公众号 AppID 反查 / 首页门店选择 | 仅**公开展示态**字段（店名、Logo、海报、活动列表、直播公告） | 走独立白名单 Controller（`/portal/**`）+ 限流；**绝不**写入 `TenantContext`；不复用业务接口 |
| **鉴权态**（登录后） | JWT payload `tenant_id` → TenantContext → 拦截器拼 SQL | 全部业务数据 | **唯一权限来源**，T1.6 硬约束不变 |

- 用户可归属多租户（`user_tenant_bind`，openid 跳租户），登录时必须**显式选定**当前 tenant 再签发 JWT，**禁止按 openid 自动猜测**（T8.9）；
- 引导态参数被篡改的最坏结果仅为「看到别家门店的公开首页」，登录后仍只能操作自己租户数据 → **不构成越权**（防串用例 17）；
- 共用小程序首页**不可空白**（微信审核硬要求），必须提供门店选择/搜索入口（T8.10）。

### M3.5 License 与租户关联（License 驱动租户版本能力）

## 四、开发与落地规范

1. **建表规范**：所有表必须含 `tenant_id` + 租户索引；高级/专业版表一次建齐（建表 ≠ 开放，开放由开关控制）；脚本遵循"先删后建/先删后插"幂等规范。
2. **接口规范**：高级/专业版增量接口**必须**标注 `@RequireFeature("FEAT_XXX")`，同时保留 `@SaCheckPermission`。**v1.12 起基础版接口不再一律豁免**——凡能力已从基础版下移（设计文档 5.1 组 A 的 11 项开关）的存量接口，必须补标 `@RequireFeature` 并同步调整授权模板与菜单回收（T6.8）；仅基础版标配且不下移的接口（收支三表、轻量记账、项目资金流、报销提交与审批）可继续不加开关注解。
3. **菜单落库**：`menu_id` 冲突时顺延但 `perms` 不变；三版本授权模板（T2.2）是唯一授权依据，禁止手工为低版本租户添加高版本菜单。
4. **版本编码**：统一 `BASIC` / `ADVANCED` / `PROFESSIONAL`。存量 `ENTERPRISE` 与《多业态SaaS平台需求规格说明书》引入的 `pro` / `professional` 一律通过 `EditionFeatureConfig.normalizeEdition(String)`（T10.7）归一化为 `PROFESSIONAL`，**双向兼容、不写迁移脚本、不改存量数据**；新代码禁止直接写死版本编码字符串做比较，必须走归一化入口；T4.1 的迁移脚本保留但仅作可选清理手段。
5. **定时任务**：租户级任务执行前校验租户开关（T4.4）；新增任务登记 JobHandler 名与 cron，与设计文档 2.7/3.5 对齐。
6. **留痕**：版本分配/天数变更/租户启停全部写操作日志 + 版本变更日志。
7. **任务状态同步**：当任务需求发生变更时，必须同步更新任务状态标记（✅ 已完成 → 🔄 待重新开发），并在交付状态记录中注明变更内容，方便后续开发跟踪。
8. **业态包规范（v1.12 新增）**：新增一个业态 = 往 `biz_bundle` 插一条数据 + 补文案映射 +（有组队/成团逻辑时）加一个 `ITeamStrategy` 子类。**禁止**在引擎源码、核心表结构、菜单树中出现 `if (bizCode == "...")` 之类的硬编码分支；单店差异一律走 `tenant_biz_config.module_overrides`（T10.4），**禁止 fork 业态包**。
9. **双阶段租户识别规范（v1.12 新增）**：引导态（登录前）只允许访问 `/portal/**` 白名单接口，**绝不写入 `TenantContext`**、绝不返回任何业务数据，且必须限流；鉴权态（登录后）`tenant_id` 唯一来源为 JWT payload，禁止 URL / 请求参数 / 前端传入（延续 0.1 硬约束）。
10. **文案与主题规范（v1.12 新增）**：所有面向用户的业态相关文案必须走 `t('key')` 映射（T10.5），禁止在 Vue / 小程序源码中硬编码「桌游」「拼桌」「团购」等业态词；主题色、圆角、阴影必须走 Design Token 的 CSS 变量（T12.2），禁止硬编码色值。
11. **图片与内容安全规范（v1.12 新增）**：Logo 必须透明底 PNG、成品统一 80×80px；海报输出 750×400 / 750×1000 两种规格，尺寸容差 ±5%、文件 ≤200KB；所有 UGC 图片过 `imgSecCheck`、文本过 `msgSecCheck`（T12.4 / T14.4），审核不通过一律拒绝并留痕。

### 10.4 关键决策与冲突化解

| # | 冲突 / 决策点 | 结论 |
|---|----------------|------|
| 1 | 需求文档用 `pro`，存量系统用 `PROFESSIONAL`/`ENTERPRISE` | `EditionFeatureConfig.normalizeEdition(String)` 作为**唯一归一化入口**，`pro`/`professional`/`ENTERPRISE` → `PROFESSIONAL`；双向兼容，**不迁移存量、不写迁移脚本** |
| 2 | 需求文档平台计费（499/月）与设计文档三版本报价（基础 1980 / 高级 5988 / 专业 12800）矛盾 | **并存**：平台订阅价（设计文档 1.5.1）为 SaaS 入驻价；三版本报价（1.5.2）降为 `fund_control` 业态包的**行业实施价**，不互斥 |
| 3 | 需求 7.2「登录前靠 URL `?tenant=` 识别」与设计文档 1.2「绝不从 URL 识别租户」直接冲突 | **双阶段租户识别**：引导态（登录前，只读公开信息，`/portal/**` 白名单 + 限流，绝不写 `TenantContext`）vs 鉴权态（登录后，JWT `tenant_id` 为唯一权限来源），硬约束不被破坏 |
| 4 | 基础版需要项目预算，但科目三层已下移 | 基础版用**项目级自定义科目** `fee_project_subject`（挂 3201 页内），不依赖 `fee_expense_category`；系统级三层随 `FEAT_SUBJECT_3LAYER` 下移 |
| 5 | 需求文档包年价两处口径不一（4780.8 / 省 1188 与 4790.4 / 省 1198） | 以 **4790** 为结算价（5988 × 0.8 = 4790.4 取整）；设计文档 1.5.1 已标注两处口径差 10 元 |
| 6 | 新增业态是否允许 fork 代码分支 | **禁止**。项目即容器（`project` + `extra_config`）/ 引擎靠策略（`ITeamStrategy`）/ 文案靠映射（`t('key')`）/ 单店靠覆盖（`tenant_biz_config.module_overrides`），引擎源码不得出现 `if (bizCode == ...)` |
