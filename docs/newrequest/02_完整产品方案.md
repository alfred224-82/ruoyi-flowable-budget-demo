> **更新日期**：2026-08-28

## 一、产品定位

### 1.1 目标客户
约50人的小公司，老板关心"钱花哪了、还剩多少、谁在花"，会计已在用金蝶/用友记账，不愿学新系统。

### 1.2 核心定位
**不是替代记账，而是"管住下个月别花超"。** 与金蝶互补：金蝶管已花（记账报税），我们管将花（预算管控）。

### 1.3 三版本定价
| 版本 | 价格 | 核心能力 |
|------|------|---------|
| 基础版 | 299/月（年付2990） | 预算编制+报销管控+老板看板 |
| 高级版 | 599-799/月 | +打卡防作弊+项目利润报表 |
| 专业版 | 999-1499/月 | +人脸比对+多组织+二维导出 |

---

## 二、核心交互架构

**老板定总额 → 系统拆明细 → 财务微调 → 老板确认 → 锁定生效**

- 老板只在大类层定额度（6个大类）
- 系统按"上月实际×系数"自动生成初稿
- 财务在大类限额内微调预算科目
- 锁定后生成版本快照，月中例外走调整审批

详见 ADR-002、ADR-005。

---

## 三、科目三层架构

### 3.1 三层结构
| 层 | 说明 | 谁用 |
|----|------|------|
| 费用科目 | 对接金蝶的具体科目 | 财务 |
| 预算科目 | 管控用的中间科目 | 系统/财务 |
| 费用大类 | 6个左右，老板视角 | 老板/报销人 |

### 3.2 两条映射
- **映射A**：费用科目 ↔ 预算科目（租户级，关键字+财务确认）
- **映射B**：预算科目 → 大类（系统内置，固定）

### 3.3 客户接入
财务导出金蝶科目表 → 导入系统 → 关键字自动匹配 + 人工补完 → 映射A建立。

详见 ADR-005、ADR-008。

---

## 四、预算编制与管控闭环

### 4.1 月初编制闭环
系统生成初稿 → 财务微调 → 老板确认 → 锁定 → 生成版本快照。

### 4.2 管控前置（ADR-003）
报销提交瞬间同步校验：
- **大类硬拦截**：超大类限额 → 直接不让提交
- **预算科目软提示**：暂定科目可能不准，超了给警告但不拦

### 4.3 审批单向（ADR-001）
所有预算变动只有一条路径：**财务提交调整申请 → 老板审批**。老板想加也走同一流程（自动通过但留记录）。

## 五、组织架构预留（ADR-009）

当前简化（公司级），预留扩展点：
- `tenant_id` + `org_id/department_id` 字段
- 额度支持"公司级/部门级"双粒度
- 触发升级：部门额度 → 部门审批 → 组织版本快照 → 多组织

---

## 六、规则引擎（ADR-006）

财务前期配置"大类 + 关键字"规则，报销提交时系统自动匹配科目：
- 发票号码精确匹配 → 关键字精确 → 模糊 → 金额区间 → 人工兜底
- 只有未命中的少数单据需财务手动确认（工作量降90%+）
- 每条报销存匹配依据，支持追溯（ADR-015）

---

## 七、老板看板

### 7.1 结构（移动端优先，ADR-010）
1. **总览**：预算总额/已用/剩余 + 进度条
2. **大类看板**：大类卡片（🟢<80% / 🟡80-100% / 🔴>100%）
3. **下钻**：大类 → 预算科目 → 报销明细
4. **预警**：>85%提醒、>95%警告、>100%超支锁定
5. **问询跟进**：花钱排行 TopN、异常标记、转发财务

### 7.2 每日简报（ADR-016）
老板每日最多1条汇总通知，异常才即时推。

---

## 八、通知体系（ADR-016）

三层：
- **审批人侧**：合并通知（N→1）
- **老板侧**：每日≤1条简报
- **财务侧**：站内信为主，微信只用于"需老板知晓的事"

报销→财务：50人提交 = 财务1条汇总（非50条）。

---

## 九、金蝶/用友导出（ADR-017、ADR-020）

- 不做私有 API，导出**标准凭证 Excel 中间文件**
- 内置 **7 套模板**：通用/金蝶/用友/畅捷通/速达/管家婆/柠檬云
- 每条单据自动生成借贷两行，借贷自动平衡
- 财务选月 + 选模板 + 下载 → 人工拖入对应系统导入

## 十、防假账（ADR-014、ADR-018）

### 10.1 铁三角
**发票验真 + 金额比对 + 支付记录**，比打卡定位可靠100倍。

### 10.2 打卡定位（辅助威慑）
- 按金额/大类触发（大额/差旅/招待）
- 降级为"威慑+辅助"，非定罪证据
- 小额自动通过减少待办

### 10.3 发票后补通道
- 无票可提交，标记"待补" → 限期补票 → 超时异常
- **信用体系**：按时补+分、超时-分，高分免审批、低分禁用后补

详见技术文档「发票验真」章节。

## 十一、系统定位升级：资金管控平台（ADR-019）

从"报销工具"升级为"资金管控平台"，覆盖完整资金流：

### 11.1 支出类
- 报销单（个人消费）
- 付款单（对外付款，如工程尾款）

### 11.2 收入类
- 收款单（项目回款）
- 收入确认（项目经理，三态：待核验/已核验/已驳回）

### 11.3 项目维度（核心）
项目 = 资金汇聚容器，报销单/付款单/收款单/收入确认均挂在项目上。

### 11.4 核算汇总
- 老板看板：大类视角（公司整体）+ 项目视角（哪个赚/亏）
- 利润分析、预算执行、预警

## 十二、项目模块详细设计

### 12.1 项目由谁创建（ADR-019）
**仅老板可建**（或财务代建 + 老板审批）。财务只做辅助确认（科目分配/结算核算），报销人只能选已有项目。

### 12.2 双轨制预算
| 类型 | 编制方式 | 周期 |
|------|---------|------|
| 公司运营预算 | 按月编制（锁定后快照） | 每月 |
| 项目预算 | 按项目立项时确定 | 随项目 |

项目预算自动汇入对应大类，报销时**双扣**（大类 + 项目预算，可配置）。

### 12.3 项目经理角色（ADR-021）
四角色：老板 / 财务 / 报销人 / **项目经理**。
- 项目经理管"项目收入侧"：收入确认、盯项目利润
- 收入确认三态：待核验（不计入实际利润）→ 财务核验 → 已核验/已驳回

### 12.4 付款单 / 收款单
与报销单平级，管"对外付/收的钱"，复用审批/通知/导出逻辑。

### 12.5 烂账标记
- 工程尾款收不回 → 标记风险 → 计提坏账 → 老板独立看板入口
- 不影响其他项目流转

### 12.6 合同变更分步生效（ADR-022）
- 走"变更单 → 老板审批 → 系统叠加"，基线永远保留
- 审批通过即更新"预期"，财务核验到账后才更新"实际"
- 超期未到账（30/60/90天）自动升级风险预警

### 12.7 项目关联规则（ADR-023）
- **按角色硬规则**：项目经理强制关联、普通员工可选、财务兜底
- **按大类软提示**：差旅/材料提示关联，办公/房租不提示
- 不关联 = 默认归"公司级"（project_id=0），老板看板"未归类"池可事后补关联

### 12.8 项目成员跨项目（负载预警）
- 允许跨项目（不拦截），拉人时显示"已在哪些项目"
- 负载权重（手动投入比例）超100%给提示，老板看板展示团队人力分布
- 同一人在不同项目可不同角色

### 12.9 项目分成（ADR-025）
- **老板定比例**（公司模板 → 项目级 → 结算可调）
- 分成基数：按合同额/已确认收入/项目利润/固定金额（一项目可混用）
- 项目经理只能"发起变更申请"，老板审批
- 利润公式：收入 - 报销 - 折旧分摊 - 分成 = 老板净得

### 12.10 设置项权限分层
| 设置项 | 操作者 |
|--------|--------|
| 分成比例 | 老板 |
| 折旧年限/残值 | 财务 |
| 利息/手续费率 | 财务（老板可读） |
| 资产分类标准 | 财务 |

详见技术文档「项目模块」章节。

## 十三、隐形成本处理（详见技术文档 + UI文档）

> **说明**：隐形成本本身是"系统功能"（配置入口、计提规则、利润公式），详见《完整产品方案》本章与《UI设计文档》。
> **本章只算"实现这些功能要花多少人力 + 对发布成本的影响"**，部署/运维的钱（服务器、域名、备案、认证）始终只在《发布成本》文档，绝不混进功能描述。

### 13.1 隐形成本类型
| 类型 | 例子 | 有无单据 | 频率 |
|------|------|---------|------|
| 项目分成 | 合伙人/渠道分润 | 有合同无报销单 | 项目结算 |
| 资产折旧 | 电脑/车辆/设备 | 无 | 每月自动 |
| 工资社保 | 员工工资/社保 | 无 | 每月 |
| 利息/手续费 | 贷款利息/平台抽成 | 有账单 | 每月 |

### 13.2 核心结论（方案A）
- **工资社保走公司级固定成本**，每月1号自动计提，**不分摊到项目**（ADR-024）
- **分成规则老板定比例**（ADR-025）
- **折旧规则财务设、系统自动算**（ADR-026）
- **利息费率财务设参数**（ADR-027）

### 13.3 对发布成本的影响
隐形成本模块**只加人力、不加钱**——纯后端逻辑+定时任务，不新增服务器/域名/备案支出。盈亏平衡仍为1个客户。

## 十五、一句话总结

**报销人选大类+填描述（不懂科目）→ 系统自动匹配科目 → 财务确认兜底 → 大类硬拦截管控 → 老板看板实时看（大类→科目→明细下钻）→ 财务月末一键导出金蝶凭证。**

系统定位：**资金管控平台**——从接活的第一笔钱进来，到最后一笔尾款出去，全程看得见。覆盖支出（报销/付款）、收入（收款/确认）、项目盈亏、隐形成本，老板第一次看到"真实利润 vs 账面利润"。

详见《技术文档》各章节实现细节。
