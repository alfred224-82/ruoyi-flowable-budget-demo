## 一、系统初始化（租户首次登录）

### 1.1 前提条件

**管理员已完成**：
- 数据库初始化（执行M1_01~M5_05全部SQL脚本，其中M5_02~M5_05为预算域增强脚本）
- 后端服务启动（ruoyi-admin、ruoyi-job）
- 前端服务启动（ruoyi-ui）
- 租户已创建并分配版本为基础版（BASIC）
- 租户管理员账号已创建（如zhangsan/123456）

### 1.2 租户管理员登录

**操作步骤**：
1. 访问 `http://localhost:80`（或生产环境域名）
2. 输入租户管理员账号密码（如zhangsan/123456）
3. 登录成功进入后台管理界面

**验收检查**：
- 左侧菜单看到"费用管控"目录
- 展开后看到：项目管理、收入确认、合同变更、付款单管理、收款单管理、烂账管理、凭证导出等菜单
- **不应看到**：部门预算编制、项目利润报表、打卡配置等高级版菜单

### 1.3 创建业务用户

**操作路径**：系统管理 → 用户管理 → 新增用户

**功能说明**：将客户自有财务系统（金蝶/用友/畅捷通等）的会计科目导入系统，自动匹配到预算科目建立映射，供凭证导出与科目级管控使用。

**操作角色**：财务（finance01登录）  
**操作路径**：费用管控 → 财务科目（导入）

**操作步骤**：
1. 点击"导入"按钮，选择来源系统（金蝶/用友/畅捷通/速达/管家婆/柠檬云/通用）

4. 对"未映射"科目点击"映射"，在下拉框选择目标预算科目（仅叶子科目）确认；不再需要的科目可点击"忽略"

## 二、核心业务流程测试

### 2.1 预算编制闭环流程

**流程**：老板定大类预算 → 系统按比例拆科目 → 财务微调 → 老板确认 → 锁定快照

#### 步骤1：老板设定大类预算

**操作角色**：老板（boss01登录）  
**操作路径**：费用管控 → 预算编制 → 新增编制

**操作步骤**：
1. 选择预算期间（如2026-09）
2. 输入各大类预算额度：
   - 差旅招待：50000
   - 采购物料：100000
   - 人员成本：200000
   - 房租物业：60000
   - 办公费用：30000
   - 获客费用：40000
3. 点击"保存"

**验收检查**：
```sql
-- 查看预算编制主表
SELECT id, period, status FROM budget_preparation
 WHERE tenant_id = <租户ID> ORDER BY create_time DESC LIMIT 1;
-- 预期：status='DRAFT'

-- 查看大类预算
SELECT category_name, budget_amount FROM budget_detail
 WHERE preparation_id = <编制ID>;
-- 预期：6条记录，总额=480000
```

#### 步骤2：生成拆分初稿（大类额度拆科目）

**操作角色**：财务（finance01登录）  
**操作路径**：费用管控 → 预算编制 → 选择草稿单 → 第二步"科目拆分" → 点击"生成拆分初稿"

**系统拆分策略**（三级兜底，按优先级依次降级）：
1. **历史实绩比例**：取该大类下各科目近3个月已批报销实绩金额占比分配（口径：已审批+已提交+超预算待审）
2. **财务预设比例**：无历史数据时，按"费用管控 → 拆分比例配置"中预设比例分配（历史实绩比例配置页面，可按大类配置各科目权重）
3. **均分兜底**：两者都没有时，按该大类下叶子科目数量平均分配；尾差自动修正到首行，保证明细合计=大类额度；无叶子科目的大类跳过并在结果中提示（可在拆分比例配置页面维护科目）
4. 确认后覆盖旧明细，仅草稿（Draft）/已驳回（Rejected）状态可生成

**验收检查**：
```sql
-- 查看科目级预算明细（按大类分组）
SELECT d.category_code, s.subject_code, s.subject_name, s.budget_amount
 FROM budget_preparation_detail s
 JOIN budget_preparation d ON s.sheet_id = d.id
 WHERE d.id = <编制ID>;
-- 预期：明细之和=对应大类额度，总金额=各大类额度之和
```

#### 步骤3：财务微调科目

**操作角色**：财务（finance01登录）  
**操作路径**：费用管控 → 预算编制 → 选择编制 → 编辑明细

**操作步骤**：
1. 打开预算编制详情页
2. 在科目级微调金额（如交通费从15000调整为18000）
3. **约束（硬校验）**：系统实时校验明细之和不得突破大类限额——保存单条明细时，同大类已有明细合计+本条超过限额将被拒绝；批量保存时以本次提交的明细列表整体校验。如需调整限额，须回到第一步修改大类额度后重新生成拆分初稿
4. 点击"保存"

**验收检查**：
```sql
-- 验证明细之和=大类限额
SELECT d.category_name, d.budget_amount AS category_total,
 SUM(s.budget_amount) AS subject_total
 FROM budget_detail d
 JOIN budget_preparation_detail s ON d.id = s.detail_id
 WHERE d.preparation_id = <编制ID>
 GROUP BY d.category_name, d.budget_amount;
-- 预期：每行category_total = subject_total
```

#### 步骤4：老板确认并锁定

**操作角色**：老板（boss01登录）  
**操作路径**：费用管控 → 预算编制 → 选择编制 → 确认

**操作步骤**：
1. 查看预算编制详情（大类总额+科目明细）
2. 确认无误后点击"确认并锁定"
3. 系统生成版本快照，状态变为LOCKED

**验收检查**：
```sql
-- 查看编制状态
SELECT period, status, lock_time FROM budget_preparation
 WHERE id = <编制ID>;
-- 预期：status='LOCKED'，lock_time不为空

-- 锁定后不可编辑
-- 尝试编辑明细 → 预期：接口返回"已锁定不可修改"
```

### 2.2 报销管控流程

**流程**：报销人填报销单 → 系统校验大类额度 → 财务审核 → 老板审批 → 计入实际

#### 步骤1：报销人提交报销单

**操作角色**：报销人（employee01登录）  
**操作路径**：费用管控 → 报销管理 → 新增报销

**操作步骤**：
1. 选择费用大类（如"差旅招待"）
2. 输入报销金额（如3000）
3. 输入用途描述（如"北京出差交通费"）
4. 选择关联项目（可选，项目经理必填，普通员工可选）
5. 上传发票图片（或勾选"发票后补"）
6. 点击"提交"

**系统自动校验**：
- **发票验真**：提交时自动执行发票查重（同发票号码/代码重复报销直接拦截）→查验（已接入税务查验接口时校验真伪）→金额比对（发票金额与报销金额不一致时拦截并标记），未接入查验接口时自动降级放行
- **大类额度硬拦截**：如差旅招待剩余<3000，提交瞬间直接拦截并提示"超出大类预算限额"；已用额度口径含已审批+已提交+超预算待审（防止拆单绕过）
- **三级预警**：大类已用比例达85%🟡黄色预警、95%🟠橙色预警、100%🔴红色拦截，触发预警时系统消息自动通知老板与财务角色
- **科目软提示**：如交通费剩余不足，黄色提示但不拦截
- **项目关联规则**：项目经理角色未选项目，400拦截"项目经理必须关联项目"

**验收检查**：
```sql
-- 查看报销单
SELECT id, bill_no, category_name, amount, status, project_id
 FROM fee_expense_bill
 WHERE tenant_id = <租户ID> ORDER BY create_time DESC LIMIT 1;
-- 预期：status='PENDING'

-- 查看大类已用额度
SELECT category_name, budget_amount, used_amount
 FROM budget_detail
 WHERE preparation_id = <编制ID> AND category_name = '差旅招待';
-- 预期：used_amount增加3000（预占）
```

#### 步骤2：财务审核

**操作角色**：财务（finance01登录）  
**操作路径**：费用管控 → 报销管理 → 待审核 → 选择报销单 → 审核

**操作步骤**：
1. 查看报销单详情（金额、发票、用途）
2. 确认/纠偏财务科目（系统自动匹配，财务可手动修改）
3. 如勾选"发票后补"，财务必填审核理由
4. 点击"通过"或"驳回"

**验收检查**：
```sql
-- 查看报销单状态
SELECT status, audit_reason FROM fee_expense_bill WHERE id = <报销单ID>;
-- 预期：status='APPROVED'（财务审核通过）

-- 查看发票后补记录（如有）
SELECT bill_id, estimated_date, status FROM fee_invoice_supplement
 WHERE bill_id = <报销单ID>;
-- 预期：estimated_date=提交日+7天，status='PENDING'
```

#### 步骤3：老板审批

**操作角色**：老板（boss01登录）  
**操作路径**：费用管控 → 报销管理 → 待审批 → 选择报销单 → 审批

**操作步骤**：
1. 查看报销单详情（金额、用途、财务审核意见）
2. 点击"通过"或"驳回"
3. 通过后计入实际支出

**验收检查**：
```sql
-- 查看报销单最终状态
SELECT status, approved_by, approved_at FROM fee_expense_bill WHERE id = <报销单ID>;
-- 预期：status='APPROVED'，approved_by=boss01的user_id

-- 查看大类实际支出

 FROM budget_detail
 WHERE preparation_id = <编制ID> AND category_name = '差旅招待';
-- 预期：actual_amount增加3000（实扣）
```

### 2.4 收入确认三态流程

**流程**：项目经理创建→待核验→财务核验通过/驳回→计入利润

## 四、工作流配置

### 4.1 基础版工作流特点

**基础版固定审批流程**（无需Flowable，状态机控制）：
- **报销单**：报销人提交 → 财务审核 → 老板审批 → 通过
- **付款单**：财务提交 → 老板审批 → 通过
- **收款单**：财务提交 → 财务审核 → 通过
- **项目立项**：老板/财务提交 → 老板审批 → 通过
- **合同变更**：项目经理提交 → 老板审批 → 通过
- **预算编制**：老板提交 → 老板确认 → 锁定

### 4.2 审批人配置

**报销单审批人**：
- 财务审核人：角色=finance的用户（可多人，任一通过即可）
- 老板审批人：角色=boss的用户（单人审批）

**付款单审批人**：
- 老板审批人：角色=boss的用户

**项目立项审批人**：
- 老板审批人：角色=boss的用户

**配置方法**：
```sql
-- 查看角色对应的用户
SELECT u.user_id, u.user_name, r.role_key
 FROM sys_user u
 JOIN sys_user_role ur ON u.user_id = ur.user_id
 JOIN sys_role r ON ur.role_id = r.role_id
 WHERE r.role_key IN ('boss', 'finance') AND u.tenant_id = <租户ID>;
```

## 五、常见问题与排查

### 5.1 报销单提交失败"超预算"

**现象**：报销人提交报销单时提示"超预算，无法提交"

**排查步骤**：
1. 查看大类预算剩余
2. 检查预算编制是否已锁定
3. 检查报销金额是否超过剩余

**解决方案**：
```sql
-- 查看大类预算
SELECT category_name, budget_amount, used_amount, (budget_amount - used_amount) AS remaining
 FROM budget_detail
 WHERE preparation_id = <编制ID>;

-- 如确实超预算，需走预算调整流程
```

### 5.2 项目经理看不到项目

**现象**：项目经理登录后看不到任何项目

**排查步骤**：
1. 检查用户是否绑定manager角色
2. 检查项目成员表是否包含该用户
3. 检查数据范围过滤逻辑

**解决方案**：
```sql
-- 检查用户角色
SELECT r.role_key FROM sys_user_role ur
 JOIN sys_role r ON ur.role_id = r.role_id
 WHERE ur.user_id = <项目经理user_id>;
-- 预期：role_key='manager'

-- 检查项目成员
SELECT * FROM fee_project_member WHERE user_id = <项目经理user_id>;
-- 预期：至少1条记录

-- 如无记录，手动添加
INSERT INTO fee_project_member (tenant_id, project_id, user_id, user_name, role)
 VALUES (<租户ID>, <项目ID>, <user_id>, '赵经理', 'MANAGER');
```

### 5.3 小程序登录后Tab不显示

**现象**：小程序登录后Tab栏为空或显示异常

**排查步骤**：
1. 检查用户角色是否正确
2. 检查角色Tab配置
3. 查看小程序日志

**解决方案**：
```javascript
// 在小程序开发者工具控制台执行
console.log(wx.getStorageSync('app_user_roles'));
// 预期：['boss'] 或 ['manager'] 等

// 检查roles.js的TAB_CONFIG是否包含该角色
```
