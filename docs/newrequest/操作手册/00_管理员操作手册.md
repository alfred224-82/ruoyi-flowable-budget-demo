## 二、创建租户

### 2.1 进入租户管理页面

**操作路径**：登录后台 → 系统管理 → 租户管理

**界面说明**：
- 租户列表页：展示所有租户（租户名称、联系人、版本、状态、到期时间）
- 右上角"新增租户"按钮：创建新租户

### 2.2 新增租户

点击"新增租户"按钮，填写表单：

| 字段 | 说明 | 示例 |
|------|------|------|
| 租户名称 | 公司/组织名称 | 杭州某某科技有限公司 |
| 联系人 | 租户管理员姓名 | 张三 |
| 联系电话 | 手机号 | 13800138000 |
| 用户名 | 租户管理员登录账号（系统自动创建） | zhangsan |
| 密码 | 租户管理员初始密码 | 123456 |
| 授权类型 | 试用/正式（影响使用天数计算） | 试用 |
| 使用天数 | 授权天数（NULL=永久） | 30 |

**提交后系统自动完成**：
1. 创建租户记录（`sys_tenant`，状态=NORMAL，版本=BASIC 或指定版本）
2. 创建租户管理员账号（`sys_user`，绑定租户，分配 boss 角色）
3. 按版本模板复制菜单授权到 `sys_role_menu`（四业务角色 boss/finance/manager/employee）
4. 初始化租户默认数据（项目关联规则、凭证导出模板等）
5. 记录版本变更日志（`sys_tenant_version_log`，changeType=INIT）

**验收检查**：
```sql
-- 查看新创建的租户
SELECT id, company_name, contact_name, edition, status, expire_date
 FROM sys_tenant ORDER BY create_time DESC LIMIT 1;

-- 查看租户管理员
SELECT user_id, user_name, dept_id, tenant_id
 FROM sys_user WHERE tenant_id = <新租户ID>;

-- 查看管理员角色分配
SELECT ur.user_id, r.role_name, r.role_key
 FROM sys_user_role ur
 JOIN sys_role r ON r.role_id = ur.role_id
 WHERE ur.user_id = <管理员user_id>;
```

### 2.3 分配版本

**操作路径**：租户列表 → 选择租户 → 点击"版本分配"按钮（6006权限）

**界面说明**：
- 弹窗选择版本：基础版 / 高级版 / 专业版
- 选择后系统自动：
  1. 更新 `sys_tenant.edition` 字段
  2. 写入版本变更日志（`sys_tenant_version_log`）
  3. 按版本模板重新授权菜单（`sys_role_menu`）
  4. 刷新功能开关缓存

**版本选择建议**：
- **基础版（BASIC）**：50人以下小公司，老板+出纳，核心资金管控
- **高级版（ADVANCED）**：中型企业，财务+老板+项目经理，需要风控增强
- **专业版（PROFESSIONAL）**：集团/多组织，需要多组织预算、人脸核身

**验收检查**：
```sql
-- 查看租户版本
SELECT id, company_name, edition FROM sys_tenant WHERE id = <租户ID>;

-- 查看版本变更日志
SELECT * FROM sys_tenant_version_log WHERE tenant_id = <租户ID>
 ORDER BY create_time DESC;

-- 查看功能开关（后端接口）
-- 访问：GET /system/edition/features?tenantId=<租户ID>
-- 返回：{"edition":"ADVANCED","features":["FEAT_TIME_CLOCK","FEAT_CREDIT_SCORE",...]}
```

### 2.4 配置使用天数

**操作路径**：租户列表 → 选择租户 → 点击"使用天数配置"按钮（6007权限）

**界面说明**：
- 授权类型：试用 / 正式
- 使用天数：数字（如30天、90天、365天）
- 系统自动计算到期日期：`expire_date = NOW() + 天数`
- 勾选"永久有效"：`expire_date = NULL`

**到期检测机制**：
- XXL-JOB定时任务 `tenantExpireCheckJob` 每日00:30执行
- 扫描 `expire_date < NOW()` 的租户
- 状态转为 `EXPIRED`，踢出在线会话
- 到期租户无法登录，所有业务接口返回"租户授权已到期"

**验收检查**：
```sql
-- 查看租户到期时间
SELECT id, company_name, expire_date,
 DATEDIFF(expire_date, NOW()) AS remaining_days
 FROM sys_tenant WHERE status = 'NORMAL';

-- 手动触发到期检测（测试用）
-- 在XXL-JOB管理中心找到tenantExpireCheckJob，点击"执行一次"
```

## 三、租户升级与降级

### 3.1 升级流程（零迁移）

**场景**：基础版租户升级为高级版

**操作步骤**：
1. 管理员登录后台 → 租户管理 → 选择租户 → 版本分配
2. 选择"高级版" → 确认
3. 系统自动完成：
   - 更新 `edition = 'ADVANCED'`
   - 写入版本变更日志（change_type=UPGRADE）
   - 按高级版模板重新授权菜单（新增3217~3223等菜单）
   - 刷新功能开关（解锁FEAT_TIME_CLOCK等9项）

**升级后验证**：
```sql
-- 1. 检查版本
SELECT edition FROM sys_tenant WHERE id = <租户ID>;
-- 预期：ADVANCED

-- 2. 检查版本变更日志
SELECT * FROM sys_tenant_version_log WHERE tenant_id = <租户ID>
 ORDER BY create_time DESC;

-- 3. 检查功能开关（后端接口）
-- GET /system/edition/features
-- 预期：features数组包含FEAT_TIME_CLOCK、FEAT_CREDIT_SCORE等9项
```

**注意事项**：
- 升级过程**无需执行额外SQL脚本**（M1_03高级版表已在初始化时一次建齐）
- 升级过程**数据零迁移**，历史数据完整保留
- 升级后租户登录即可看到新增菜单和功能入口

### 3.2 降级流程

**场景**：专业版租户降级为基础版

**操作步骤**：
1. 管理员登录后台 → 租户管理 → 选择租户 → 版本分配
2. 选择"基础版" → 确认
3. 系统自动完成：
   - 更新 `edition = 'BASIC'`
   - 写入版本变更日志（change_type=DOWNGRADE）
   - 按基础版模板重新授权菜单（回收高版本菜单）
   - 刷新功能开关（关闭高级/专业版功能）

**降级后验证**：
```sql
-- 1. 检查版本
SELECT edition FROM sys_tenant WHERE id = <租户ID>;
-- 预期：BASIC

-- 2. 检查版本变更日志
SELECT * FROM sys_tenant_version_log WHERE tenant_id = <租户ID>
 ORDER BY create_time DESC;

-- 3. 检查历史数据保留
SELECT COUNT(*) FROM fee_employee_credit WHERE tenant_id = <租户ID>;
-- 预期：>0（信用分数据保留，但功能入口关闭）
```

**降级兼容性**：
- 部门级预算启用后降级的历史公司级预算继续有效
- 多组织启用后降级的存量数据默认挂"总部"组织
- 信用分自启用日起累计，降级不回溯历史

### 6.1 防串五层纵深防御

| 层级 | 机制 | 验证方法 |
|------|------|---------|
| ① 版本分配入口 | 仅admin可调assignVersion | 非admin角色调用返回403 |

## 七、常见问题与排查

### 7.1 租户创建失败

**现象**：点击"新增租户"后报错"租户创建失败"

**排查步骤**：
1. 检查数据库连接是否正常
2. 查看后台日志：`logs/sys-error.log`
3. 检查 `sys_tenant` 表是否有唯一键冲突（tenant_code重复）
4. 检查 `sys_user` 表用户名是否已存在

**解决方案**：
```sql
-- 查看已存在的租户
SELECT id, company_name, tenant_code FROM sys_tenant;

-- 查看已存在的用户
SELECT user_id, user_name FROM sys_user WHERE user_name = '<用户名>';
```

### 7.2 版本分配后菜单未更新

**现象**：管理员分配高级版后，租户登录看不到高级版菜单

**排查步骤**：
1. 检查租户版本是否更新
2. 检查菜单授权模板是否包含高级版菜单
3. 检查角色是否正确分配菜单
4. 清除浏览器缓存，重新登录

**解决方案**：
```sql
-- 1. 检查租户版本
SELECT edition FROM sys_tenant WHERE id = <租户ID>;
-- 预期：ADVANCED

-- 2. 检查模板
SELECT COUNT(*) FROM sys_edition_menu_template WHERE edition = 'ADVANCED';
-- 预期：约110条

-- 3. 检查版本变更日志
SELECT * FROM sys_tenant_version_log WHERE tenant_id = <租户ID>
 ORDER BY create_time DESC;
```

### 7.3 租户到期后仍可登录

**现象**：租户已到期但仍能登录系统

**排查步骤**：
1. 检查租户到期日期
2. 检查定时任务是否执行
3. 手动触发到期检测任务
4. 检查拦截逻辑是否生效

**解决方案**：
```sql
-- 1. 检查到期日期
SELECT id, company_name, expire_date, status FROM sys_tenant WHERE id = <租户ID>;

-- 2. 手动触发（XXL-JOB管理中心）

-- 3. 手动更新状态（紧急处理）
UPDATE sys_tenant SET status = 'EXPIRED' WHERE id = <租户ID> AND expire_date < NOW();
```

### 7.4 跨租户数据泄露

SHOW CREATE TABLE fee_project;

-- 2. 检查拦截器配置

### 8.4 版本变更日志表结构

```sql
CREATE TABLE `sys_tenant_version_log` (
  `id` BIGINT NOT NULL AUTO_INCREMENT,
  `tenant_id` BIGINT NOT NULL COMMENT '租户ID',
  `from_edition` VARCHAR(20) COMMENT '原版本',
  `to_edition` VARCHAR(20) COMMENT '目标版本',
  `change_type` VARCHAR(20) COMMENT 'INIT/UPGRADE/DOWNGRADE',
  `operator` VARCHAR(50) COMMENT '操作人',
  `remark` VARCHAR(500) COMMENT '备注',
  `create_by` VARCHAR(64),
  `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_tenant_id` (`tenant_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='租户版本变更日志';
```
