## 一、版本升级（高级版→专业版）

**操作角色**：平台管理员（platform_admin登录）  
**操作路径**：系统管理 → 租户管理 → 选择租户 → 版本分配

**操作步骤**：
1. 选择"专业版（PROFESSIONAL）"
2. 点击"确定"
3. 系统自动完成：
   - 更新 `sys_tenant.edition = 'PROFESSIONAL'`
   - 写入版本变更日志（change_type=UPGRADE）
   - 按专业版模板重新授权菜单（新增3224~3226等菜单）
   - 刷新功能开关（解锁全部16项功能）

**验收检查**：
```sql

SELECT edition FROM sys_tenant WHERE id = <租户ID>;
-- 预期：PROFESSIONAL

SELECT COUNT(*) FROM sys_role_menu
 WHERE role_id IN (SELECT role_id FROM sys_role WHERE tenant_id = <租户ID>)
   AND menu_id IN (3224, 3225, 3226);
-- 预期：3条

-- 3. 检查功能开关（后端接口）
-- GET /system/edition/features?tenantId=<租户ID>
-- 预期：features数组包含全部16项：
-- 高级版9项 + FEAT_FACE_RECOGNITION, FEAT_MULTI_ORG, FEAT_ORG_SNAPSHOT,
```

### 2.1 多组织体系（FEAT_MULTI_ORG）

**功能定位**：集团总部+子公司独立预算体系，组织为租户内二级维度

#### 2.1.1 创建组织树

**操作角色**：财务（finance01登录）  
**操作路径**：费用管控 → 组织管理 → 新增组织

**组织架构示例**：
```
集团总部（tenant_id=1）
 ├── 子公司A（独立预算）
 ├── 子公司B（独立预算）
 └── 总部直属部门
```

**操作步骤**：
1. 点击"新增组织"按钮
2. 输入组织编码：SUB-A
3. 输入组织名称：子公司A
4. 选择父组织：集团总部（parent_id=0）
5. 输入负责人：王总
6. 点击"确定"

**重复创建子公司B**

**验收检查**：
```sql
-- 查看组织树
SELECT id, org_code, org_name, parent_id, ancestors
 FROM fee_org
 WHERE tenant_id = <租户ID>;
-- 预期：3条记录（集团总部+子公司A+子公司B）

-- 验证ancestors字段（祖级列表）
SELECT org_name, ancestors FROM fee_org WHERE org_code = 'SUB-A';
-- 预期：ancestors包含父组织ID链路
```

#### 2.1.2 用户归属组织

**操作角色**：财务（finance01登录）  
**操作路径**：费用管控 → 组织管理 → 选择组织 → 添加成员

**操作步骤**：
1. 选择"子公司A"
2. 点击"添加成员"
3. 选择用户（如赵经理、孙员工等）
4. 设置是否为主组织（is_primary=1）
5. 点击"确定"

**验收检查**：
```sql

SELECT ou.org_id, o.org_name, ou.user_id, u.user_name, ou.is_primary

 JOIN fee_org o ON ou.org_id = o.id
 JOIN sys_user u ON ou.user_id = u.user_id

-- 预期：子公司A下有多个用户

-- 多组织用户（如同时属于总部和子公司A）
SELECT user_id, COUNT(*) AS org_count

```

### 2.2 人脸比对防作弊（FEAT_FACE_RECOGNITION）

**功能定位**：大额/敏感大类提交时触发人脸核身，存疑仅标记不拦截

#### 2.2.1 人脸核身配置

**操作角色**：财务（finance01登录）  
**操作路径**：费用管控 → 人脸核身配置

**配置项**：
| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 大额阈值 | 2000 | 金额≥2000触发人脸核身 |
| 敏感大类 | 差旅招待、获客费用 | 这些大类触发人脸核身 |
| 底照来源 | 系统用户头像 | 与入职底照比对 |

**操作步骤**：
1. 点击"配置"按钮
2. 调整大额阈值：3000（如需要）
3. 选择敏感大类：勾选差旅招待、获客费用
4. 点击"保存"

**验收检查**：
```sql
-- 查看人脸核身配置（如存储在配置表）
SELECT * FROM fee_face_verify_config WHERE tenant_id = <租户ID>;
-- 预期：包含阈值和敏感大类配置
```

#### 2.2.2 大额报销触发人脸核身

**操作角色**：报销人（employee01登录小程序）  
**操作路径**：小程序 → 发起报销

**测试用例1：金额≥2000触发**
1. 选择大类"办公费用"
2. 输入金额2500（≥2000，触发人脸核身）
3. 点击"提交"
4. **系统弹出人脸核身页面**
5. 允许相机权限 → 采集人脸照片
6. 系统与入职底照比对 → 显示相似度
7. 点击"确认提交"

**验收检查**：
```sql
-- 查看人脸核身记录
SELECT bill_id, user_id, amount, trigger_type, face_image_url,
 reference_image_url, result, similarity, is_suspicious, evidence_level
 FROM fee_face_verify_record
 WHERE tenant_id = <租户ID> ORDER BY create_time DESC LIMIT 1;
-- 预期：trigger_type='AMOUNT_THRESHOLD'，evidence_level='strong'

-- 如相似度<阈值（如80%），is_suspicious=1（人脸存疑，进异常池）
```

**测试用例2：敏感大类触发**
1. 选择大类"差旅招待"（敏感大类）
2. 输入金额500（<2000，但大类触发）
3. 点击"提交"
4. **系统弹出人脸核身页面**
5. 完成人脸采集 → 提交成功

**验收检查**：
```sql
-- 查看人脸核身记录
SELECT trigger_type FROM fee_face_verify_record
 WHERE tenant_id = <租户ID> ORDER BY create_time DESC LIMIT 1;
-- 预期：trigger_type='SENSITIVE_CATEGORY'
```

**测试用例3：不触发人脸核身**
1. 选择大类"办公费用"
2. 输入金额1000（<2000，非敏感大类）
3. 点击"提交"
4. **系统不弹出人脸核身页面** → 直接提交成功

**验收检查**：
```sql
-- 查看人脸核身记录（无新增）
SELECT COUNT(*) FROM fee_face_verify_record
 WHERE tenant_id = <租户ID> AND bill_id = <报销单ID>;
-- 预期：0条
```

## 六、常见问题与排查

### 6.1 多组织数据隔离失效

**现象**：子公司A的财务能看到子公司B的数据

**排查步骤**：
1. 检查用户-组织关系是否正确
2. 检查后端数据范围过滤逻辑
3. 查看SQL是否手动拼接了org_id条件

**解决方案**：
```sql
-- 检查用户-组织关系
SELECT ou.org_id, o.org_name, ou.user_id, u.user_name
 FROM fee_org_user ou
 JOIN fee_org o ON ou.org_id = o.id
 JOIN sys_user u ON ou.user_id = u.user_id
 WHERE ou.user_id = <财务user_id>;
-- 预期：只属于子公司A

-- 如属于多个组织，需调整
DELETE FROM fee_org_user WHERE user_id = <财务user_id> AND org_id = <子公司B的org_id>;
```

### 6.2 人脸核身失败

**现象**：小程序人脸核身时无法识别或比对失败

**排查步骤**：
1. 检查用户是否有入职底照（系统用户头像）
2. 检查相机权限是否授权
3. 查看人脸核身记录

**解决方案**：
```sql
-- 查看人脸核身记录
SELECT user_id, result, similarity, is_suspicious
 FROM fee_face_verify_record
 WHERE tenant_id = <租户ID> ORDER BY create_time DESC LIMIT 5;

-- 如result='MISMATCH'且similarity很低
-- 可能原因：底照过旧、光线不足、角度差异
-- 解决方案：更新用户底照（系统用户管理 → 上传头像）
```

### 6.3 二维导出Excel格式错误

**现象**：二维导出Excel第二张Sheet格式异常

**排查步骤**：
1. 检查项目-科目数据是否完整
2. 检查模板配置是否正确
3. 查看后台日志

**解决方案**：
```sql
-- 检查项目科目数据
SELECT p.project_name, ps.category_name, ps.used_amount
 FROM fee_project p
 JOIN fee_project_subject ps ON p.id = ps.project_id
 WHERE p.tenant_id = <租户ID>
 ORDER BY p.project_name, ps.category_name;
-- 预期：数据完整，无NULL值

-- 如数据不完整，先补充项目科目配置
```

### 6.4 规则灰度期间命中率异常

**现象**：灰度期间命中率一直为0或异常高

**排查步骤**：
1. 检查灰度百分比配置
2. 检查规则快照内容
3. 查看灰度期间报销单匹配记录

**解决方案**：
```sql
-- 查看灰度配置
SELECT version_no, grayscale_pct, grayscale_status, hit_rate
 FROM fee_rule_version
 WHERE tenant_id = <租户ID> AND grayscale_status = 'GRAYSCALE';

-- 查看灰度期间报销单匹配链路
SELECT match_trace FROM fee_expense_bill
 WHERE tenant_id = <租户ID> AND create_time > '<灰度开始时间>';
-- 预期：JSON格式，包含匹配方式和规则版本

-- 如命中率异常，可回滚灰度
UPDATE fee_rule_version SET grayscale_status = 'ROLLBACK'
 WHERE id = <版本ID>;
```
