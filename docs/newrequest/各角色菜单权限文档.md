# 资金管控平台 · 各角色菜单权限文档

**版本**：v2.4  
**日期**：2026-08-29  
**来源文档**：`资金管控系统设计文档.md`（三版本功能矩阵）、`资金管控平台新功能详细设计文档.md`（Phase 18 ~ Phase 29）  
**文档定位**：定义五角色（老板 / 财务 / 项目经理 / 报销人 / 管理员）在 **基础版（BASIC）/ 高级版（ADVANCED）/ 专业版（PROFESSIONAL）** 三个商业版本下的菜单树、按钮权限与数据范围，供前端路由开发、`sys_menu` / `sys_role_menu` 数据初始化、小程序页面权限配置使用；其中 `admin` 超管独占租户管理（新增租户、分配版本、设置使用天数），`platform_admin` 为租户内组织管理员角色，负责用户、部门与角色管理（均与 `tenant_id` 绑定，租户自行初始化）；其菜单按商业版本区分  
**说明**：本文档仅规划菜单与权限，不含 SQL 脚本

**端标识约定**：`PC` = PC 管理后台（Vue + sys_menu）；`小程序` = 微信小程序（uni-app，单包多角色，页面级权限）；`内嵌` = 不占独立菜单，嵌在既有页面/表单内。

## 一、角色体系

| 角色 | 角色标识（roleKey） | 核心职责（摘自设计文档 1.6） | 主用端 |
|------|---------------------|------------------------------|--------|
| 老板 | `boss` | 定总额、建项目、审批项目/付款/变更、看板 | 小程序为主 |
| 财务 | `finance` | 编制微调、审核报销、核验收入、导出凭证、隐形成本配置 | PC 为主 |
| 项目经理 | `manager` | 确认收入（三态）、盯利润、发起合同变更 | 小程序为主 |
| 报销人 | `employee` | 填报销单、选项目、补票 | 小程序 |
| 管理员（租户组织管理员） | `platform_admin` | 租户内用户管理（新增/编辑/启停）、部门管理（新增/编辑/删除）、角色管理（新增/编辑/删除，高级版+）；均与 `tenant_id` 绑定，租户自行初始化 | PC |

> 说明：
> 1. `admin` 超级管理员拥有全部菜单且功能开关免检，**独占租户管理**（6000 系列菜单），不参与本文档业务菜单分配；**管理员（`platform_admin`）与其不同**：它是租户内的组织管理员角色，持有用户管理（100）、部门管理（103）菜单（基础版+），高级版起增加角色管理（101）；所有组织管理菜单均与 `tenant_id` 绑定，不持有任何租户业务菜单与租户管理菜单；
> 2. 菜单可见性由角色-菜单关联（`sys_role_menu`）控制，**与版本解耦**；License 版本仅在 API 层（`@RequireFeature`）拦截。版本升级解锁后，**须手动为对应角色分配新增菜单**（见设计文档 5.2 / 6.1）；
> 3. 用户可同时拥有多个角色（如"项目经理"通常兼任"报销人"），最终菜单为各角色菜单的并集；`platform_admin` 角色为租户内组织管理角色，由 `admin` 超管在租户内创建并分配；`admin` 超管独占租户管理（6000 系列），不在业务角色中分配；
> 4. "主用端"仅为产品导向，不限制实际分配：老板/项目经理/报销人在 PC 端同样拥有只读或单据类菜单。

| 角色管理（高级版+） | 在租户内新增/编辑/删除自定义角色，为角色分配菜单权限；基础版仅可使用系统预设角色（boss/finance/manager/employee），不可修改角色定义 |
| 数据初始化 | 租户创建时系统自动初始化：管理员用户（`sys_user`）、默认部门树（`sys_dept`）、预设角色（`sys_role`），均绑定 `tenant_id` |
| 权限边界 | `platform_admin` 不可管理菜单（102）、字典（105）等系统级配置，不可越权访问租户管理（6000 系列） |

**权限边界**：`platform_admin` 不持有任何业务菜单（预算编制/报销/项目/看板等全部 —），不可查看租户业务数据；持有用户管理（100）+ 部门管理（103）（基础版），高级版起增加角色管理（101）。租户管理（6000 系列）由 `admin` 超管独占，通过 Sa-Token 全局放行 + `@SaCheckRole` 双重防护。

## 六、实施说明

1. **菜单挂载**：所有新增页面菜单（2.2）挂到既有目录 `费用管控`（menu_id=3000）下；部门预算编制（3217）亦可挂 `预算管理`（2000）目录，落库时二选一并保持路由唯一；按钮权限（2.4）按父菜单归属挂载。
2. **menu_id 为建议值**：正式落库时如与现网冲突可顺延，权限标识（perms）保持不变（前后端代码以 `perms` 为准）。
3. **组件路径差异**：既有费用管控菜单组件位于 `system/fee/*`，新增页面按设计文档使用 `views/fee/*`（组件路径去 `views/` 前缀）；如需统一目录，可将组件迁移至 `system/fee/*` 下，本文档权限定义不受影响。
4. **版本与菜单解耦**：菜单可见性只由角色控制，高级/专业版增量菜单随版本升级**手动为角色分配**（设计文档 6.1 第③步）；未升级租户即使误分配菜单，API 层 `@RequireFeature` 仍会拦截，前端由 `/system/edition/features` 下发能力配置动态隐藏入口。
5. **数据范围控制**（菜单之外必须实现）：
   - 项目经理的"项目管理/收入确认/合同变更/分成/资产/烂账/项目利润报表"数据查询需按 `fee_project_member`（role=MANAGER/MEMBER/VIEWER）过滤；
   - 高级/专业版组织维度：用户可见范围 = 本组织 + 下级组织（管理员全量）；
   - 财务/老板默认全量可见。
6. **多角色并集**：项目经理通常兼任报销人，菜单与权限取并集；报销单"项目必填"校验按设计文档 23.3 以最高约束角色（MANAGER）为准。
7. **定时任务无菜单**：各版本 JobHandler（含高级版 `creditScoreCalcJob`）由后台运行，不涉及角色菜单；如需可视化监控可复用 XXL-JOB 既有管理菜单（`admin` 超管专属）。
8. **角色权限落地**：
   - `admin` 超管独占租户管理（6000 系列）：通过 Sa-Token 全局放行（`SaPermissionImpl` 中 admin 返回全量角色列表）+ `@SaCheckRole("platform_admin")` 双重防护，admin 自动绕过角色校验；
   - `platform_admin` 为租户内组织管理员：持有用户管理（100）+ 部门管理（103）（基础版），高级版起增加角色管理（101）；所有组织管理数据（`sys_user`/`sys_dept`/`sys_role`）均与 `tenant_id` 绑定，租户创建时自行初始化；不可访问租户管理接口；
   - 本文档规划的 6006 版本分配、6007 使用天数配置按钮细分与 6021 租户详情隐藏页、租户到期每日检测任务为后续落库事项，落库前以 `system:tenant:edit` / `system:tenant:query` 现有权限承载。
9. **租户级克隆角色与菜单授权（v2.4 起，角色菜单与 `tenant_id` 绑定）**：
   - 开通租户时，系统从 M2_01 共享预设角色 9201~9205 克隆出租户专属角色（`sys_role.tenant_id` = 租户ID，`role_key` 保持 boss/finance/manager/employee/platform_admin），并按 `sys_edition_menu_template` 的**角色×版本模板**（`BOSS_BASIC`、`FINANCE_BASIC`、`MANAGER_BASIC`、`EMPLOYEE_BASIC`、`PLATFORM_ADMIN_*` 等）为每个克隆角色授权菜单；
   - 版本变更（`assignVersion`）仅对**本租户**的克隆角色按目标版本模板先删后插，不影响其他租户；
   - 共享预设角色 9201~9205 仅作克隆源与 admin 预览，**不再授权给租户用户**；角色标识（`role_key`）不变，后端审批/通知等按 `role_key` 的逻辑（如 `notifyRole("boss")`）无需修改；
   - 存量租户执行 `docs/newrequest/sql/M2_08_tenant_role_clone_migration.sql` 迁移（克隆角色 + 模板授权 + 用户角色指针改指克隆角色）；
   - 老板基础版菜单严格按“定总额、建项目、审批项目/付款/变更、看板”裁剪（共 23 个菜单节点，含报销审批按钮权限 3041/3045 不挂菜单）。
