# 预算编制管控系统 · 完整产品方案

> 本文档汇总产品设计阶段的所有核心决策，覆盖：产品定位与定价、三层科目架构、编制与管控流程、规则引擎、老板看板、组织架构预留设计、报销人"无发票也能报"的后补通道、防假账证据链与打卡定位、**资金管控平台（项目模块 + 付款单/收款单 + 烂账 + 双轨制预算 + 老板看板项目视角）**。
> 目标客户：**约 50 人规模的小公司老板**；核心版本：**基础版（月费 299，划线价 499）**。
> 配套文档：《预算编制管控系统_技术文档.md》（开发落地）、《架构决策清单 ADR》（硬约束）、《预算编制管控系统_发布成本与后续方案.md》（成本与演进）。

## 一、产品定位与核心思路

### 1.1 目标客户与价值主张

- **客户画像**：50 人左右的小公司，老板自己管钱或由 1 名会计/出纳管账，月付 500 级（实际成交 299/月）。
- **核心痛点**：钱花哪了说不清、利润忽高忽低、Excel 汇总低效、科目口径混乱、审批黑盒、编制与执行脱节、项目赚没赚不知道、烂账收不回来没记录。
- **价值主张**：**"让系统编制预算、老板只管确认"**。老板不参与"编制"动作，只需看大方向、定总额、做判断题。
- **隐藏价值**：防假账（发票验真 + 异常拦截）→ 老板买的是"避险"不是"投资"，决策门槛更低；项目利润看板 → 老板买的是"每个项目赚没赚一目了然"，比纯预算管控有画面感。

### 1.2 三版本定价（SaaS 月付）

| 版本 | 定价 | 主要使用者 | 核心能力 |
|------|------|-----------|---------|
| 基础版 | 299/月（划线 499，年付 2990） | 老板 + 出纳 | 复用上月生成预算、大类管控、老板看板、审批流、**内置金蝶/用友/畅捷通/速达等凭证模板导出、发票验真、无发票后补、项目立项+付款/收款+烂账标记+项目经理收入确认** |
| 高级版 | 599-799/月 | 财务 + 老板 + 项目经理 | 部门级预算、弹性额度、规则引擎自定义、**打卡定位、信用体系、项目经理移动端收入确认+项目利润看板** |
| 专业版 | 999-1499/月 | 集团/多组织 | 多组织、多项目、完整规则引擎与版本快照、**人脸比对防作弊** |

**对外口径**：划线价 499，早鸟成交 299，前 20 家锁价 3 年。金蝶/用友作为"记账工具"锚点，强调**互补不替代**（他们管"事后记账"，我们管"事前预算 + 事中管控 + 事后风控 + 项目盈亏"）。

## 二、核心交互架构：三层分工

> **老板定总额 → 系统拆明细 → 财务微调 → 超了再找老板**

| 角色 | 职责 | 认知负担 |
|------|------|---------|
| 老板 | 看大方向，确认大类总额（如"获客成本 ≤ 3 万"）+ **看每个项目赚没赚** | 极低（几个数字） |
| 系统 | 自动把大类额度拆成预算科目明细 + 自动匹配报销科目 | 零（规则引擎执行） |
| 财务 | 在大类额度内微调明细科目 + **做项目立项/付款/收款的辅助确认** | 中等（无需请示老板） |
| 报销人 | 选大类 + 填金额描述（+ 发票/后补）+ **选关联项目** | 极低（手机填） |
| 项目经理 | **按月/按阶段确认项目收入**（填确认收入金额+依据）→ **看自己负责项目的实时利润** | 低（只管自己项目） |

**核心约束**：明细科目总额不得超过老板定的大类限额；超额必须走"调整申请 → 老板审批"。

### 2.1 系统定位升级：从"报销系统"到"资金管控平台"

```
                  ┌─────────────┐
                  │  资金管控平台  │
                  └──────┬──────┘
                         │
          ┌──────────────┼──────────────┐
          ▼              ▼              ▼
    ┌────────────┐  ┌────────────┐  ┌────────────┐
    │  支出类     │  │  收入类     │  │  核算汇总   │
    │ 报销单     │  │  收款单     │  │ 预算执行    │
    │ 付款单     │  │ 回款单     │  │ 项目利润    │
    │ (个人消费)  │  │ (收回的钱)  │  │ 烂账预警    │
    └─────┬──────┘  └─────┬──────┘  └─────┬──────┘
          │               │               │
          └─────┬─────┬──┴──────┬────┬────┘
                ▼     ▼          ▼      ▼
          ┌─────────────────────────────┐
          │        ★ 项目（Project）      │  ← 每笔钱都挂在某个项目下
          │  合同额 / 预算 / 已收 / 已付  │
          │  预估利润 / 烂账标记          │
          └─────────────────────────────┘
```

**报销单只是"支出类"中的一个子类**（个人消费，不关联项目或可选关联）。付款单（对外付钱）和收款单（收回钱）**必关联项目**。这是 ADR-019 的核心：系统不止管"花出去的钱"，还管"谁收的钱、有没有收不回来"。

## 三、科目三层架构与映射

### 3.1 三层科目

| 类型 | 使用者 | 颗粒度 | 示例 |
|------|--------|--------|------|
| 费用科目 | 会计/金蝶 | 细（几十条） | 管理费用-办公费-打印纸 |
| 预算科目 | 预算编制 | 中（十几条） | 办公费 |
| 费用大类 | 老板 | 粗（5-8 个） | 日常运营 |

### 3.2 两条映射、一张表

```
费用科目（细） ──映射A──→ 预算科目（中） ──映射B──→ 费用大类（粗）
   会计用的                     编制用的                    老板看的
```

| 映射 | 方向 | 用途 | 配置方 |
|------|------|------|--------|
| 映射A | 费用科目 → 预算科目 | 实际费用发生后归入预算科目做对比 | 平台（后台）+ 财务确认 |
| 映射B | 预算科目 → 大类 | 编制汇总给老板看总额 | 平台（内置，固定） |

**大类是三个角色的共同语言**：报销人选它、财务确认后自动带出、老板定它的额度。

### 3.3 客户侧接入（极低成本）

1. 客户导出费用科目表（Excel）→ 5 分钟；
2. 平台用**关键词别名库 + 人工补完**匹配到预算科目；
3. 预算科目 → 大类由系统内置自动带出；
4. 使用中新增科目，财务/平台补一条规则即可。

**规则引擎是平台的武器，不是客户的功能**（基础版对客隐藏，仅高级/专业版开放配置）。

## 四、预算编制与管控流程（核心闭环）

### 4.1 统一审批方向（单向上报）

> **砍掉"老板直接改预算"，统一为"财务提交调整申请 → 老板审批"。**

所有预算变动只有一条入口，确保编制环节不被架空、变动可追溯。

**审批流统一**：
- 预算编制确认：财务（系统生成初稿）→ 老板确认 → 锁定生效；
- 预算调整申请：财务/老板发起 → 老板审批 → 更新额度；
- 报销审批：报销人 → 财务 → 老板（基础版默认老板一人批）；
- **项目立项：老板创建（或财务代建+老板审批）→ 自动生成项目预算初稿 → 财务微调 → 老板确认 → 锁定**（项目预算也是一条审批链）。

### 4.2 月初编制阶段（有节奏闭环）

```
Day 1  系统自动生成预算初稿（上月实际 × 系数 / 近 3 月均值）
Day 1-2 财务在大类额度内微调明细科目（明细之和 = 大类限额）
Day 2-3 老板收到"本月预算已就绪"通知 → 确认 / 打回
Day 3  老板确认 → 预算锁定 → 生成版本快照 → 报销管控开始
```

### 4.3 项目中预算（双轨制，跟着项目走）

```
项目立项时：
  老板新建项目 → 填合同额/客户/周期 → 系统按行业模板生成项目预算初稿
  → 财务微调（差旅3000/住宿2000/材料10000） → 老板确认
  → 项目预算锁定 → 自动汇入对应大类（差旅招待大类 +5000）
  → 通知财务"新项目已立项，大类已占用"

项目执行中：
  报销单关联该项目 → 同时双扣：大类额度 + 项目预算额度
  付款单（工程尾款）关联该项目 → 扣项目预算 + 记对外付款
  收款单（客户回款）关联该项目 → 记收入，影响项目利润

项目结束后：
  关闭项目 → 财务做最终核算（实际收支 vs 预算）→ 显示盈亏
```

**双轨制说明**：
- **公司运营预算**（固定，按月编）：房租、工资、日常办公——这些和具体项目无关，老板每月定一次。
- **项目预算**（动态，按项目编）：差旅、住宿、材料、外包——每个项目立项时确定，自动汇入对应大类。
- 老板看板**两个视角分开显示，最终汇总到同一个大类**：大类卡片显示"公司运营 X + 项目占用 Y = 总额 Z"。

### 4.4 管控前置到报销提交瞬间

报销人提交即校验，**大类做硬拦截（报销人选的，100% 准），预算科目做软提示（暂定，财务后续修正）**：

- ✅ 都没超 → 正常提交走审批；
- ⚠️ 超了但可弹性 → 标记预警，附"需老板追加额度"提示；
- ❌ 超太多（超阈值） → 直接拦截，不让提交。

财务审批时确认/修改费用科目 → 系统重新校验一次（事后纠偏，不影响流程）。

### 4.5 无发票后补通道（核心新增：不让流程卡死）

> **问题：员工可能没法及时提供发票（先垫付、后补票），如果强制要求发票才能提交，流程直接卡死，员工不报了、老板觉得系统不好用、财务也烦。工程尾款等"拿不到发票"的费用更没有发票。**
>
> **方案：不是"没有发票就不能报"，而是"没有发票也能报，但要受约束"。两条通道并行。**

```
报销提交时：
  │
  ├── 有发票 → 正常通道（OCR验真 → 自动匹配 → 财务审核 → 通过）
  │
  └── 无发票 → 后补通道（标记"待补发票" → 走审批 → 额度预占 → 限期补票 → 超时处理）
```

**后补通道规则：**

| 规则 | 设计 |
|------|------|
| 提交标记 | 无发票时，勾选"发票后补" + 选预计补票日期（默认7天，可改） |
| 审批加严 | 财务审核时**必须填审核理由**（为什么允许后补）；**一律需老板审批**（不管金额大小） |
| 额度处理 | 审批通过 → 大类额度**预占**（"已承诺未核销"，非实扣）；补票完成 → 预占转实扣；超时未补 → 预占释放 + 标记异常 |
| 老板看板 | 大类卡片区分"已用(实扣)/预占(待补)/剩余可用"，超85%预警时一并提示预占金额 |
| 信用体系 | 按时补票+2分、逾期-5分、连续3次按时+10分奖励；<50分禁止无发票报销 |

**为什么这样设计**：流程不卡死（员工永远能报），但每一步都有管控（老板必须知情、财务必须留痕、信用分约束诚信）。诚实的员工信用分涨了越来越方便，爱钻空子的被逐步限制。

**对推广的影响**：
- 员工接受度 ✅ 大幅提升——"没发票也能报，不用自己垫着等"
- 老板接受度 ✅ 有管控——"我批了才知道，而且有期限、有信用"
- 会计工作量 ⚠️ 略增——多了"待核销"池，但系统自动OCR验真，财务只点确认

## 五、组织架构（预留设计）

> 当前小公司不搭建组织架构，预算按**公司级**编制；从设计之初预留扩展能力，避免后期重构。本项目模块是"组织架构预留"（ADR-009）的**先行启用**——项目维度是当前最划算的扩展，比部门维度更早产生价值。

### 5.1 当前简化（基础版）

- 无部门层级，预算 = 公司整体预算；
- 大类额度 = 公司级总额度；
- 报销直接归属大类，不挂部门；
- **新增：项目维度** = 资金汇聚的容器，报销单/付款单/收款单都挂在项目下。

### 5.2 后续扩展点（高级/专业版）

| 阶段 | 扩展能力 |
|------|---------|
| 1 | 部门额度（大类额度支持公司级 / 部门级双粒度） |
| 2 | 部门级审批流 |
| 3 | 组织版本快照（部门合并/拆分时新旧版本隔离） |
| 4 | 多组织（集团总部 + 子公司独立预算体系） |

**预留原则**：核心表均带 `tenant_id` + `org_id/department_id`；映射、审批流以租户隔离；科目/架构采用"模板 + 租户覆盖"。

> **与 ADR-019 的关系**：本项目模块是 ADR-009 的先行启用——项目维度是当前最划算的数据汇聚容器扩展，比部门维度更早产生价值（小公司老板关心"哪个项目赚钱"远早于"哪个部门花钱"）。

## 六、规则引擎设计

- **科目别名库**：大类下挂预算科目，预算科目配关键词（推广/广告/展会…），自动匹配客户费用科目；
- **匹配机制**：关键词匹配（MVP）+ 财务确认（兜底）+ AI 语义（后期可选）；
- **租户隔离**：每条映射带 `tenant_id`，缓存按租户隔离；
- **影响分析 + 灰度**：改规则前评估受影响预算，灰度发布（专业版）。

## 七、老板看板设计

> 实时查看费用使用情况：**先大类 → 下钻预算科目 → 带出报销单明细**，并新增**项目视角**（每个项目赚没赚、钱花在哪、有没有烂账）。

### 7.1 四层下钻（大类视角）

1. **总览屏**：本月预算总额 / 已用 / 剩余（进度条）+ 超支预警数量；**区分"实扣/预占"**（预占用虚线/斜纹展示）
2. **大类卡片**：每个大类一张卡，状态分 🟢(<80%) / 🟡(85-100%, 即将超) / 🔴(>100%, 已超)；显示"已用X / 预占Y / 剩余Z"
3. **预算科目层**：点击大类下钻，看各预算科目已用/限额；显示待补发票数
4. **报销单明细**：点击预算科目，带出责任人、金额、用途、发票信息（方便老板问询）

### 7.2 项目视角（新增核心Tab）

```
老板看板 - 项目Tab：
  ┌────────────────────────────────────────────────┐
  │  进行中项目（3个）                                │
  │                                                  │
  │  客户A网站开发 ★★★★★                              │
  │    合同额：100,000   项目预算：15,000             │
  │    已收：   60,000   已付：   6,500              │
  │    预算使用：6,500/15,000 = 43% 🟢               │
  │    预估利润：60,000-6,500 = 53,500（87%）         │
  │    状态：🟢 正常                                  │
  │    收尾：尾款 40,000 待收（预计下月回）            │
  │                                                  │
  │  客户B推广 ★★★☆☆☆ 🔴                            │
  │    合同额：50,000    项目预算：8,000              │
  │    已收：   0       已付：   8,200（超预算！）     │
  │    预估利润：-8,200（亏损）🔴                     │
  │    状态：🔴 超支+尾款未回                         │
  │    操作：⚠️ 标记烂账风险                         │
  │                                                  │
  │  客户C装修 ★☆☆☆☆☆ 🟡                            │
  │    合同额：80,000    项目预算：25,000             │
  │    已收：   50,000   已付：  18,000              │
  │    预估利润：32,000（64%）                         │
  │    状态：🟡 尾款 30,000 逾期中（催款中）          │
  │    操作：📋 查看收支时间线                       │
  └────────────────────────────────────────────────┘
```

**点击任意项目 → 下钻到收支时间线**：合同 → 首付款 → 进度款 → 验收 → 付款单（工程尾款）→ 收款单（回款）→ 每笔的收款方/金额/日期/发票状态，全链路可追溯。

### 7.3 烂账/风险区域（新增）

```
  ⚠️ 风险预警区（独立展示，不混在大类里）：
     ├── 🔴 客户B推广：项目预算已超支，尾款80,000未收回
     ├── 🟡 客户C装修：尾款30,000逾期45天，催款中
     └── 🟢 暂无其他风险
     
     点击"客户B" → 标记烂账：
       原因：对方失联，多次催款无响应
       建议方案：坏账 / 继续跟进 / 法律途径
       → 老板选"计提坏账准备 8000" → 影响项目利润 → 看板实时更新
```

### 7.4 预警机制

| 级别 | 触发 | 通知方式 |
|------|------|---------|
| 提醒 | 大类 > 85% | 看板标黄 + 微信 |
| 警告 | 大类 > 95% | 看板标红 + 微信 + 短信 |
| 超支 | 大类 > 100% | 红闪 + 多通道 + 锁定新报销 |
| 项目超支 | 项目预算 > 100% | 看板标红 + 微信（项目视角） |
| 项目亏损 | 预估利润 < 0 | 看板标红 + 微信（项目视角） |
| 烂账标记 | 手动标记 | 看板独立区域 + 微信 |

### 7.5 增强建议

- **环比对比 + 预计全月**（按日均消耗推算月底）；
- **花钱排行**（谁在花，方便问责）；
- **异常标记**（单笔/累计异常自动圈出）；
- **后补监控**：待补发票倒计时、逾期异常单独标红区；
- **操作克制**：老板仅可追加大类、锁定、标记关注、转发财务；**不改明细科目**；
- **移动端优先**（微信小程序，3 秒看全、5 秒决策）；
- **项目维度**：老板可"新建项目"（核心决策权）→ 看板项目Tab → 下钻收支时间线 → 标记烂账 → 计提坏账。

## 八、报销人"无发票也能报"的设计细节

### 8.1 触发条件（按费用类型差异化）

| 费用类型 | 是否要求发票 | 后补期限 | 说明 |
|---------|------------|---------|------|
| 差旅/住宿/招待（高风险） | 必填，但可"后补" | 7天 | 必须走后补通道，老板必批 |
| 采购 | 必填，但可"后补" | 7天 | 同上 |
| 打车/出行 | 可后补 | 7天 | 高风险类型 |
| 办公小额（<500） | **不需要发票** | — | 直接走正常通道，不进后补池 |

### 8.2 关联项目（新增：报销单必填项目选择）

```
报销人提交时新增步骤：
  ① 选大类（差旅招待）
  ② 填金额 + 描述
  ③ ★ 选关联项目（下拉，只显示"进行中"的项目，如"客户A网站开发"）
  ④ 传发票（或勾选"后补"）
  
系统自动：同时扣 大类额度 + 该项目预算额度
```

**报销人只能"选已有项目"，不能自建。** 下拉列表只显示状态=进行中的项目，已关闭/已烂账的不显示。

### 8.3 信用等级与权限

| 等级 | 条件 | 无发票报销权限 |
|------|------|---------------|
| 🟢 优秀 | ≥80分 | 免老板审批（只财务审），补票期限延长至14天 |
| 🟡 正常 | 50-79分 | 正常流程（老板审批，7天期限） |
| 🔴 受限 | <50分 | **禁止无发票报销**，必须上传发票才能提交 |

### 8.4 财务端处理（待核销池）

```
财务工作台待办分类：
  ├── 待审核（正常）     → 有发票，直接审
  ├── 待审核（后补）     → 无发票，需审核理由
  ├── 待核销（补票中）   → 员工已补票，验证发票
  └── 异常（超时未补）   → 需处理：催/豁免/驳回/标记
```

财务对超时单的处理选项：**催办 / 豁免（需老板确认）/ 驳回（预占释放）/ 标记异常（进审计记录）**

### 8.5 补票操作（极简，小程序）

```
员工补票：我的报销 → 找到"待补票" → 点"补传发票" → 拍照上传
  → OCR识别金额 → 比对报销金额(差>10%→异常) → 发票验真 → 通过则预占转实扣
```

### 8.6 实现要点

- 新增加密字段表：`invoice_status`、`estimated_invoice_date`、`actual_invoice_date`、`credit_score_change`
- `invoice_supplement`（补票记录：发票图片、OCR结果、验真结果、补票时间）
- `employee_credit`（员工信用分、当前分、等级、历史记录）
- `credit_rule`（信用分规则配置：加减分值、阈值）
- 定时任务：补票提醒（每天）、逾期标记（每天）、信用分计算（每周）

## 九、防假账证据链与打卡定位

> **定位精度是物理上限（相邻宾馆30米、GPS误差50米分不清），但你不靠定位防假账——你靠发票。** 这一节解决"怎么判断他确实应该去这里了"。

### 9.1 防假账铁三角（P0，必须做）

报销单**强制要求上传发票**（系统自动识别，员工只需拍照）→ 系统 OCR 识别 → 调用发票查验接口验真 → 发票金额 vs 报销金额自动比对 → 不一致直接拦截标记异常。

| 证据强度 | 手段 | 防什么 |
|---------|------|-------|
| 🔴 强 | 发票验真（税务局接口） | 假发票、虚开 |
| 🔴 强 | 金额比对（发票金额 vs 报销金额） | 多报、少报 |
| 🔴 强 | 支付记录截图（校验收款方） | 虚报、冒领 |
| 🟡 中 | 打卡定位+拍照 | 证明"确实在外勤状态"（非防假账） |
| ⚪ 弱 | 员工自填描述 | 唯一不可信来源 |

**结论：假发票一验便知（比打卡强100倍）；相邻建筑区分不了定位才是"该用发票不用定位"的铁证。**

### 9.2 打卡定位的正确角色（P1，威慑辅助）

打卡**不是定罪证据，是外勤证明**：能证明"员工那天确实在外勤状态"，不能证明"具体哪家宾馆"。按规则触发（差旅招待/金额≥500/历史异常≥2次），定位精度>50米标记"定位存疑"但不拦截。

### 9.3 证据链分级存储

每条报销单存 `evidence_level`（strong/medium/weak），老板看板异常筛选支持"发票异常/定位存疑/人工标记"多维标记。

### 9.4 推广话术

> **老板最怕的不是"员工去了隔壁宾馆"，而是"员工根本没去，发票是假的"。**
> 我们的系统：发票拍照 → 自动验真 → 金额比对 → 异常标记。假发票直接拦住，不用你操心。
>
> 升级版（加项目）：**"从这张订单的钱进来，到那笔尾款的钱出去，全程你都能看到。每一分钱花在哪、谁收的钱、有没有收不回来的，老板一眼看完。"**

## 十、项目模块详细设计（★ 新增核心）

### 10.1 项目创建：权限边界（用户最关心的问题，★ 更新ADR-021~023）

| 操作 | 老板 BOSS | 财务 FINANCE | 报销人 EMPLOYEE | **项目经理 MANAGER** |
|------|----------|-------------|----------------|---------------------|
| 创建/审批项目 | ✅ 应该建 | 代建+提交批 | ❌ | ❌ |
| 编辑项目预算 | ✅ | 建议(提申请) | ❌ | ❌ |
| 关闭/结算项目 | ✅ | 操作(老板批后) | ✅(自己项目) | ❌ |
| **确认项目收入** | 看所有 | ✅ 可**核验**(通过/驳回) | ❌ | ✅ 可建(**待核验**，自己负责项目) |
| **收入核验(财务)** | ✅ | ✅ 通过/驳回 | ❌ | ❌(不能审别人的) |
| **发起合同变更** | ✅(批) | ❌ | ❌ | ✅(自己项目，提交→老板批) |
| 查看项目列表 | ✅ | ✅(所有) | ✅(自己参与) | ✅(只自己负责/参与) |
| 关联项目到报销 | ❌ | 可选(默认) | ✅(只能选自己有权限的) | ❌(不能填报销) |
| 查看项目利润 | ✅(所有) | ✅(所有) | ❌ | ✅(自己负责，含待核验🟡) |
| 填报销单 | ❌ | ✅(自己也能报) | ✅ | ❌ |
| 项目关联规则配置 | ✅(开关) | ❌ | ❌ | ❌ |

**核心原则**：项目 = "钱从哪来"的经营决策，只有老板有这个决策权（接什么活、预算给多少）。**项目经理是"钱回来多少"的经营确认人**，专门负责收入确认和盯利润——不让收入确认塞给报销人（员工随便填不准）或老板（老板只看结果不看过程）。

**收入确认三态（★ ADR-021，不是"项目经理填了就算"）：**
- 🟡 **待核验**：项目经理手动建 → 提交 → 状态变🟡 → **财务还没点头**
- ✅ **已核验**：财务在"收入核验"列表点"核验通过" → **财务核对过银行流水/金蝶，确认属实** → **才计入项目利润**
- ❌ **已驳回**：财务核验不通过（与账务对不上）→ 打回项目经理 + 填原因 → **不算**

**合同变更分步（★ ADR-022，不是"改个数字"）：**
- 变更走"变更单 → 老板批 → 系统叠加增量"，**基线保留，不回溯历史**
- 审批通过后合同额+delta、项目预算+delta（仅影响未来）
- 钱没到 → 状态="待收款确认🟡" → 老板看板**纸面利润 vs 实际利润分开显示**
- 超期未到账 → 自动升级预警（🟡收款逾期 → 🟠长期未到 → 🔴疑似烂账）

**未归类/公司级（★ ADR-022）：**
- 报销不选项目 = 默认归"公司级"(project_id=0) = 只扣大类，不扣任何项目
- 老板看板多一列"未归类"，让老板知道"有X块钱花出去了但不知道归哪"

**项目关联规则（★ ADR-023，按角色分不是按单子分）：**
- 项目经理 → **必须选**（不选不让提交）
- 普通报销人 → **可选**（差旅/采购/获客类有黄色提示建议选，人员/办公类不提示）
- 财务 → **可选**（默认公司级）
- 配置灵活：支持"某大类所有角色强制关联""某项目严格模式"等开关

**特殊情况：老板太忙，想让财务代建**
→ 财务代建项目：填写项目信息+预算 → 提交**老板审批** → 老板确认/修改 → 立项生效。等同于"财务填表，老板拍板"。

**项目经理的特殊性**：项目经理**不填报销单**（花销归报销人）、**不做预算决策**（经营确认归项目经理、预算额度归财务+老板）、**不能看其他项目**（只看自己负责项目的收支+利润）。收入确认**必须附依据**（合同编号/发票号/回款单号），**无依据=待核验**，财务不点"核验通过"就不算数。**他不能审核别人的付款/收款单**（对外付钱老板必须批）。

### 10.2 项目字段设计（PC端创建）

```
新建项目表单：
  ├── 项目名称：客户A网站开发
  ├── 客户名称：XX科技有限公司
  ├── 合同额：100,000
  ├── 项目周期：2026-09 ~ 2026-11
  ├── 项目经理：张三（可选）
  └── 项目预算（按大类分配，自动汇入对应大类）：
       差旅招待：3,000
       住宿：2,000
       材料采购：10,000
       其他：0
  
  提交 → 老板审批 → 立项生效：
    → 创建 project 记录
    → 按填的预算生成 project_subject（从全公司科目继承后可改）
    → 项目预算自动汇入对应大类（差旅招待 +5000）
    → 大类总额自动增加
    → 通知财务"新项目已立项，预算已分配，大类已占用"
```

### 10.3 付款单（★ 新增：对外付钱）

```
付款单字段（比报销单多几个）：
  ├── 基本信息：付款单号、付款方（我方）、收款方（对方）、付款金额、付款日期
  ├── 项目关联：★ 必选（下拉，只显示进行中项目）
  ├── 付款类型：工程尾款 / 材料款 / 服务费 / 租金 / 其他
  ├── 发票情况：有/无/后补（工程尾款大概率是后补或没有）
  ├── 合同/验收单（可选附件）
  └── 审批流：★ 一律需老板审批（不管金额大小）→ 复用报销审批引擎

操作：
  提交付款单 → 老板审批 → 通过 → 扣该项目预算 + 记"对外付款" → 通知财务
  
目的：老板能看到"我付了谁多少钱"，不只是"我花了什么"
```

**付款单和报销单的关系**：大多数日常报销不关联项目（是个人消费），但所有对外的钱（付款/收款）都关联项目。付款单审批人**一定是老板**——对外付钱老板必须知道。

### 10.4 收款单（★ 新增：收回钱）

```
收款单字段：
  ├── 基本信息：收款单号、付款方（对方）、收款方（我方）、收款金额、收款日期
  ├── 项目关联：★ 必选
  ├── 收款类型：项目回款 / 退款 / 其他
  └── 回单（银行回单/微信截图，可选）

操作：
  提交收款单 → 财务审核 → 通过 → 记"项目收入" → **联动+1条收入确认(verify_status=已核验，财务即核验人)** → 影响项目利润 → 老板看板实时更新

**收入确认三态（★ ADR-021，核心新增逻辑）：**

| 状态 | 谁创建 | 谁改变 | 是否计入利润 |
|------|--------|--------|------------|
| 🟡 待核验 | 项目经理手动建 | 财务 approve→已核验 / reject→已驳回 | ❌ 不计入 |
| ✅ 已核验 | 收款单联动(财务建即核验) | 无 | ✅ 计入 |
| ❌ 已驳回 | — | 财务驳回时填原因 | ❌ 不计入 |

**项目经理手动建（不走审批流，但进三态机）：**
  手机端 → 项目收入 → 新建 → 选项目(只能选自己负责的) → 填金额+日期+依据类型(合同/发票/回款单)+依据编号
  → 提交 → 状态=🟡待核验 → 通知财务"有1条待核验收入确认，X元，依据XX"
  → 财务在PC"收入核验"列表点"核验通过/驳回" → 改变项目利润

**老板看板纸面 vs 实际（★ ADR-022，合同变更钱没到时也分开显示）：**
  纸面预估利润 = 合同额 - (已核验收入 + 待核验收入) - 支出   ← 含未到账的，显示🟡待核验X元
  实际利润     = 合同额 - 已核验收入 - 支出                ← 只有财务确认过的

**合同变更分步生效（★ ADR-022，变更≠改数字）：**
  手机端/PC → 发起变更单 → 关联项目+变更类型+原因+合同额/预算变更+依据附件
  → 老板审批(必须) → 通过后：合同额+=delta + 项目预算+=delta(仅未来) + 状态=待收款确认🟡
  → 财务到账后 → 该变更状态自动=已闭环
  → 不修改初始合同额(基线保留)，已发生报销/付款不变(不回溯)
  → 超期未到账 → 🟡收款逾期→🟠长期未到→🔴疑似烂账(进风险区)

**未归类/公司级默认（★ ADR-022）：**
  报销不选项目 → 默认归"公司级"(project_id=0) → 只扣大类，不扣项目
  老板看板多一列"未归类：X元(可点查看/补关联)"
  财务可在报销单详情"补关联"（改project_id→生成操作日志）

```


### 10.5 烂账标记（★ 解决"烂账需要一个口子给老板看"）

```
标记烂账路径（项目卡片 → 点击"标记风险/烂账"）：
  1. 选择风险类型：对方失联 / 质量纠纷 / 价格没谈拢 / 烂尾 / 其他
  2. 填写说明（文字，如："对方失联，多次催款无响应，已逾期60天"）
  3. 选择处理方案：坏账 / 继续跟进 / 法律途径
  4.（可选）计提坏账准备：输入金额 → 影响项目利润 → 看板实时更新
  
系统动作：
  → 项目状态变为"🔴 风险/烂账"
  → 进入老板看板"风险预警区"独立展示
  → 留完整时间线（合同→付款→收款→逾期→失联→标记风险）
  → 不影响其他项目的大类额度（烂账是"这个项目亏了"，不是"公司整体超支"）
```

**关键点**：烂账**不是**"报销单未完成"——它是项目维度的风险标记，和报销单是两个东西。报销单走完流程就是"已完成"，烂账是项目层面的额外状态。

### 10.6 老板向项目预算"加钱"的逻辑

```
老板看板项目卡片 → 点击"项目预算已用X/限额Y，要加吗？"
  → 老板选"追加到XX大类"（如差旅招待 +2000）
  → 系统生成一条预算调整申请 → 老板审批（自己批自己）→ 项目预算更新 + 大类额度更新
  
不是"老板直接改数字"，是"走调整申请 → 自己审批 → 留记录"。
和 ADR-001 一致：即使是老板自己，加钱也要走申请流。
```

## 十。内置常用财务系统凭证模板导出（★ 落地点：财务Side，卖点）

> **老板视角**："我不用管导出，财务一键就能出凭证到金蝶。"
> **财务视角**："导出Excel我确认一下就能导入，比手工做凭证快10倍。"
> **对外话术**："导出到金蝶/用友，一键出文件，我人工导入就行，不用两边手填。"

### 11.1 为什么做"Excel文件+内置模板"而不是"直接对接任何财务软件"

系统**不写任何一家财务软件的对接代码**（金蝶、用友、畅捷通……每家接口都不同，要签约、要环境、要维护，不划算），只产出一份**标准 Excel 中间凭证文件**，由财务打开文件、选对应模板、拖进自家财务系统导入一次。原因：

| 方案 | 成本 | 风险 | 结论 |
|------|------|------|------|
| 直连某家私有API | 高（版本差异+环境不可控+需签约） | 升级即废、客户切换成本高 | ❌ |
| 人工导出Excel+选模板导入 | 低（POI生成+模板配置） | 无 | ✅ |
| 专用XML/CSV | 中 | 各系统导入菜单路径各异 | ❌ |

**核心逻辑**：系统负责"算对数据 + 出标准格式文件 + 按模板对齐列"，导入是财务的本职动作。财务是最终把关人，让他导入一遍比系统写死准确（避免借贷方向/辅助核算填错）。对50人小公司，财务每月导1-2次，手动导入1分钟完全可以接受。

**内置模板清单（后台维护，客户零配置）**：

| 模板名称 | 适用财务系统 | 列头差异处理 |
|------|------|------|
| 通用（默认兜底） | 所有系统 / 无辅助核算 | 基础7列：凭证日期/摘要/科目编码/借方/贷方/项目/客户 |
| 金蝶系列（精斗云/云星辰/星空） | 金蝶 | 科目编码用"."分隔（如6602.01.0000）、辅助核算列按金蝶规范摆放 |
| 用友系列（U8/T+/好会计） | 用友 | 末级编码、辅助核算列（部门/项目/客户）按用友规范 |
| 畅捷通好会计 | 畅捷通 | 启用辅助核算时带项目/客户列 |
| 速达 | 速达 | 按速达导入模板列顺序映射 |
| 管家婆 | 管家婆 | 按管家婆凭证导入模板列顺序映射 |
| 柠檬云财税 | 柠檬云 | 按柠檬云导入模板列顺序映射 |

财务在"导出凭证"页面**选月 + 选模板 + 选范围 → 三因子组合 → 下载Excel**，三步搞定，零学习成本。

### 11.2 导出什么（覆盖全部单据）

```
导出范围（PC端"财务 → 导出凭证"）：
  ├── 全部（默认）：已审批报销单 + 付款单 + 收款单 + 收入确认
  ├── 仅报销单：日常零散报销快速导出
  ├── 按项目筛选：单个项目结账
  ├── 按月份：跨月调整时补导
  └── 按角色：可单独导出"项目经理确认的收入凭证"
  选月 + 选模板 + 选范围 → 三因子组合 → 下载Excel

> 收入确认凭证借贷方向：借：银行存款(1002) / 贷：主营业务收入(6001) 或 应收帐款(1122)，按模板自动生成。项目经理填的收入是凭证的借方数据来源之一。
```

### 11.3 Excel标准凭证结构（7列）

```
凭证日期 | 摘要 | 科目编码 | 借方 | 贷方 | 项目 | 客户
2026-08-05 | 报销-客户A差旅 | 6602010000 | 1200 | | 客户A网站开发 | XX科技
2026-08-05 | 报销-客户A差旅 | 2221010000 | | 1200 | 客户A网站开发 | XX科技
2026-08-10 | 付款-工程B尾款 | 2202010000 | 32000 | | 工程B | 
2026-08-10 | 付款-工程B尾款 | 6602010000 | | 32000 | 工程B | 
每条单据自动生成2行（借+贷），借贷自动平衡。

带出的"项目+客户"列 → 金蝶启用"项目辅助核算"后自动归集到对应项目。
```

### 11.4 借贷方向规则（自动生成，不用财务手填）

| 单据 | 借方 | 贷方 | 说明 |
|------|------|------|------|
| 报销（费用类） | 费用科目（6602） | 银行存款（1002） | 花出去的钱 |
| 付款单（对外付） | 成本费用科目 | 银行存款 | 付出去的钱 |
| 收款单（客户回） | 银行存款 | 主营业务收入/应收 | 收回来的钱 |
| 坏账计提（可选） | 信用减值损失（6603） | 坏账准备（2431） | 财务动作 |

**科目编码来源**：沿用现有 `subject_mapping`（财务配置的"描述→科目编码"），报销单自动匹配借方；贷方按单据类型从固定字典取。

### 11.5 模板机制（内置默认 + 客户可增）

```
模板 = 一套「描述关键词 → 科目编码」映射 + 借贷方向 + 辅助核算设置 + 列头定义
内置模板：以上7套由平台后台统一维护（YAML/JSON配置），客户零配置，开箱即用。
客户自定义：高级版/专业版可在内置模板基础上新增/修改（新增模板=后台加一个配置条目）。

导出时选模板 → 系统按该模板的「列头定义」拼Excel → POI写入凭证行
与预算映射 subject_mapping 共用同一借贷方向引擎，不用重复配置。
```

### 11.7 对定价与推广的影响

- **内置凭证模板导出是基础版标配卖点**（不是高级版才有的），降低客户"上了另一个系统"的心理门槛——不管家用金蝶、用友、畅捷通还是速达，"你们直接出凭证文件，我选对应模板导入就行，不用两边手填"。
- 首次**出文件**免费做（技术文档ADR-020），内置7套模板零边际成本，新客户沿用。
- 话术升级（三层"省心"叠加）：
  - 第一层（老板）："从第一笔钱进来到最后一笔尾款出去，全程看得见。"
  - 第二层（财务）："出凭证到金蝶/用友/畅捷通，选模板导入就行，不用两边手填。"
  - 第三层（老板+项目经理）："每个项目都有人管收入，**老板随时看赚没赚，项目经理按月确认回款进度**。"
  - 两个同时打动老板的支点：**项目利润看板**（第三层）+ **凭证一键导出**（第二层），会计省心→主动推荐，老板省心→持续付费。

## ## 十一、★ 新增：项目经理完整角色 + 收入确认三态 + 合同变更分步 + 未归类/公司级 + 项目关联规则

> 本章是产品方案新增章节，承载 ADR-021~023 的产品侧落地。涵盖：项目经理不只是"能看项目利润"，而是有完整的收入确认三态（待核验→财务核验→已核验才算数）；合同变更分步生效（预期收入 vs 实际到账分开算）；未归类/公司级默认（不卡流程不污染数据）；项目关联按角色硬规则（项目经理必须选、行政不用选、差旅提示选、财务兜底）。

### 11.1 角色完整定义（四角色权限矩阵，更新）

| 功能 | 老板 BOSS | 财务 FINANCE | 报销人 EMPLOYEE | **项目经理 MANAGER** |
|------|----------|-------------|----------------|---------------------|
| 查看大类看板 | ✅ | ✅ | ❌ | ❌ |
| 查看项目利润 | ✅（所有） | ✅（所有） | ❌ | ✅（**自己负责/参与的**） |
| **创建/审批项目** | ✅ | 代建+提交批 | ❌ | ❌ |
| **确认项目收入** | 看所有 | 核验所有（通过/驳回） | ❌ | ✅（**自己负责项目的**，待核验→提交） |
| **填报销单** | ❌ | ✅（自己也能报） | ✅ | ❌ |
| **关联项目到报销** | ❌ | 可选（默认） | ✅（只能选**自己有权限的**） | ❌（不能填报销） |
| 付款/收款审核 | 批 | 审+可联动收入 | ❌ | ❌（不能审核别人的） |
| 科目映射 | ❌ | ✅ | ❌ | ❌ |
| 凭证导出 | ❌ | ✅ | ❌ | ❌ |
| 预算总额决策 | ✅ | 建议权 | ❌ | ❌ |
| 烂账标记 | ✅（看+标记） | ✅（操作） | ❌ | ✅（自己项目的） |
| 信用分管理 | ❌ | ✅（配置） | 只看自己 | ❌ |
| 项目关联规则配置 | ✅（开关） | ❌ | ❌ | ❌ |

**项目经理的特殊性（边界收紧）：**
- 他**不填报销单**（花销归报销人）、**不做预算决策**（额度归财务+老板）、**不能看其他项目**（只能看自己负责/参与的）。
- 收入确认**不走审批流**（他自己填、自己看），但**必须附依据**（合同编号/发票号/回款单号），无依据 = "待核验"状态，财务不点"核验通过"就不算数。
- 他**不能审核**别人的付款/收款单（对外付钱老板必须批，跟他无关）。
- 他**不能建项目**（只有老板能建/批）。

### 11.2 收入确认三态（核心新增逻辑）

```
项目经理的操作（不走路审批，但进三态机）：

  项目经理手机端 → 项目收入 → 新建收入确认
    → 选项目（只能选自己负责的）
    → 填确认收入金额 + 确认日期
    → 选依据类型（合同节点 / 发票 / 回款单 / 其他）
    → 填依据编号（合同号/发票号/回款单号）
    → 提交 → 状态 = 🟡「待核验」

  ┌──────────┐     财务核验(PC端"收入核验"列表)     ┌───────────┐
  │ 待核验 🟡  │ ────────────────────────────────→ │ 已核验 ✅  │
  │ (项目经理填)│  点"核验通过"(核对银行流水/金蝶)    │ (财务确认) │
  └──────────┘ ◄───────────────────────────────────└──────────┘
  │                                                    │
  │                                    点"核验不通过"   │
  │                                            ┌───────┴───────┐
  └───────────────────────────────────────────→ │ 已驳回 ❌     │
                                               │ (打回+填原因) │
                                               └──────────────┘

★ 只有「已核验✅」的收入才计入项目利润。
  「待核验🟡」只出现在项目经理自己的待办里，老板看板显示"XX待核验"。
  「已驳回❌」不计入，项目经理需补据重提。
```

**老板看板项目卡片区分三态：**

```
客户A网站开发
  合同总额：130,000（初始100K + 变更30K，待收款确认）
  
  ┌ 已核验收入：80,000 ✅（财务已确认 60K + 待核验 20K）
  ├ 待核验收入：20,000 🟡（项目经理提的，财务未核验）
  └ 已驳回：0
  
  已到账：80,000
  未到账（待收款确认）：50,000
  
  支出：12,000
  
  ★ 预估利润（纸面，含待核验）：130,000 - 80,000 - 12,000 = 38,000
  ★ 实际利润（仅已核验+已到账）：80,000 - 80,000 - 12,000 = -12,000
  
  → 老板一眼看到："纸面赚3.8万，但实际只落袋-1.2万，还有2万待核验、5万没到账"
```

### 11.3 合同变更分步生效（增量叠加，不回溯历史）

```
变更单创建（项目经理发起 or 老板发起）：
  关联项目 + 变更类型（合同额增加/预算增加/综合）
  + 变更原因（客户追加移动端适配）
  + 合同额变更（原100K → 新130K，+30K）
  + 预算变更（按大类：差旅+2K，材料+5K）
  + 依据附件（补充协议/客户邮件/新需求文档）

→ 老板审批（必须）

审批通过后系统：
  ✅ 合同额：100,000 → 130,000（基线保留，叠加变更）
  ✅ 项目预算：15,000 → 20,000（按大类追加）
  ✅ 大类额度自动增加（差旅+2K）
  ✅ 生成变更记录（可审计，不可删）
  ❌ 已发生的报销/付款：不变（按当时的项目预算扣的）
  ❌ 已确认收入：不变（后续按新合同额确认）

老板看板：
  项目卡片显示「变更X次 + 变更金额 + 状态(待收款确认/已闭环/逾期)」
  合同额显示「初始100K + 变更+30K = 当前130K」
```

**与收入确认的联动：** 变更后合同额变大了，项目经理后续确认收入时上限从10万变成13万（不会再被"超合同额"拦截）。已确认的不动，未确认的按新上限。

**逾期升级（和烂账同一套）：**
- 变更单 > 30天未收款确认 → 🟡 收款逾期
- 变更单 > 60天 → 🟠 长期未到账
- 变更单 > 90天 → 🔴 疑似烂账风险（老板看板标记"变更待跟进"）

### 11.4 未归类 / 公司级默认

```
报销人提交时：
  选大类 + 填金额 + ★ 选关联项目（下拉，显示进行中项目）
  
  如果这笔不该归任何项目（买办公用品/交房租/团建）：
  → 不选项目 → 默认归「公司级」= project_id=0（隐形项目，不出现在列表）
  → 只扣大类额度，不扣任何项目预算
  
系统按大类给引导（不强制）：
  · 差旅招待/采购/获客 → 🟡 没选项目？建议选一下（可跳过）
  · 人员成本/房租/办公 → 不提示
  
财务事后可补关联：
  报销单详情 → 点"关联项目" → 选对应项目 → 保存
  → 该笔从"未归类"移到"该项目"
  → 生成操作日志（原项目→新项目，修改人+时间）
  
老板看板：
  大类卡片下多一行「未归类：1,200（3笔，可点查看）」
  → 点进去 → 可逐笔指定项目 / 忽略
```

### 11.5 项目关联规则（按角色分，三層控制，见 ADR-023）

| 层级 | 逻辑 | 实现 |
|------|------|------|
| **第一层·角色级（硬）** | 项目经理必须选、普通员工可选、财务可选、老板不报 | 报销提交接口按 role 判断 project_id 必填性 |
| **第二层·大类级（软）** | 差旅/采购/获客建议关联、人员/办公不提示 | 前端按 category 给绿色勾/黄色叹号/无提示 |
| **第三层·财务兜底（终审）** | 项目经理没选→拦截打回；普通员工没选→标记建议+可放行；财务没选→通过 | 财务审核列表加"未关联项目"标记列 + 一键补关联 |

**配置灵活（管理员可开关）：**
- 默认：项目经理强制 + 其他可选 + 差旅类提示
- 可开启：某大类"所有角色强制关联" / 某项目设"严格模式"（该项目下所有报销必须关联）

## 十五、★ 新增：隐形成本处理（项目分成 + 资产折旧 + 工资社保 + 利息）

> **问题**：前面讨论的成本（报销、付款、收款）都是"有人填报销单"的模式。但还有一类成本**没有报销单、没有申请人**——它们按月自动发生，不卡流程，但实打实吃利润。如果系统不管，老板看板上的利润永远是"纸上富贵"。
>
> 这四类隐形成本：**项目分成**（给合伙人/渠道的）、**资产折旧**（电脑/车的）、**工资社保**（员工的）、**利息**（经营贷月息）。共同特征：非"某人填报销→审批→扣额度"，而是"系统定期记账→扣减利润"。

### 15.1 总体策略：新增「固定成本/分摊」模块

不走报销单，走**"记账分录"**——财务或老板每月/每项目手动或系统自动录入一笔成本，直接挂到项目或公司级。四类成本的处理方式各有侧重：

| 成本类型 | 有无单据 | 发生频率 | 处理方式 | 谁设参数 |
|---------|---------|---------|---------|---------|
| 项目分成 | 有合同无报销单 | 项目结算时 | 手动录入/系统按收款自动算 | **老板** |
| 资产折旧 | 无单据 | 每月自动 | 系统按月自动计提 | **财务** |
| 工资社保 | 有薪资表无报销单 | 每月自动 | 系统按月自动计提 | **老板设+财务维护** |
| 利息 | 有银行扣款 | 每月自动 | 手动/自动录入 | **财务** |

### 15.2 项目分成（Project Profit Sharing）

**录入与审批**：

```
项目经理发起 → 老板审批 → 财务标记"已支付"（关联付款单或直接记账）
分成记录字段：项目 / 分成对象 / 分成基数类型 / 分成比例 / 分成金额 / 状态 / 依据
分成基数三种模式：
  · 按合同总额：分成 = 合同额 × 比例（简单合作）
  · 按已确认收入：分成 = 已核验收入 × 比例（按实际到账分）
  · 按项目利润：分成 = (收入 - 支出 - 折旧) × 比例（深度合作共担风险）
一个项目内不同对象可用不同基数（张三按利润35%，渠道商按合同额10%）
```

**三层配置（ADR-023 扩展）**：

| 层级 | 内容 | 操作者 |
|------|------|--------|
| 公司级默认模板 | 默认比例20%、默认基数"按合同总额"、常见角色预设 | **老板** |
| 项目级配置 | 每个项目独立设（张三35%/渠道商10%） | **老板** |
| 结算时调整 | 项目做完了老板觉得该多给 → 改比例 → 重新计算 | **老板** |

**权限**：项目经理可"发起分成申请"（提比例+填金额），但**不能自己批准**；最终比例只有老板能定。防止"又当运动员又当裁判"。

### 15.3 资产折旧（Asset Depreciation）

**录入方式**：财务在PC端录入公司资产清单 → 系统按月自动折旧。

```
资产表字段：名称 / 类别(电子设备·办公家具·交通工具·办公设备) / 原值 / 残值 / 使用年限 / 归属(公司级/某项目) / 已折旧月数
折旧规则（财务在"折旧规则"页设）：电子设备3年5%、办公家具5年5%、交通工具5年10%、办公设备10年5%，直线法
每月1号定时任务：遍历资产表 → 按分类标准算月折旧额 → 生成折旧记录 → 更新资产已折旧金额

归属分摊：
  公司级 → 计入"公司运营成本"，不扣任何项目
  某项目100% → 全计该项目
  某项目60%+另一项目40% → 按比例分摊
```

**老板看板体现**：固定成本卡片新增"资产折旧：X"（项目维度显示"该项目分摊折旧：X"）。

### 15.4 工资与社保（方案A：公司级成本）

> **方案A确认**：工资社保默认是**公司级成本**，不分到具体项目，只在公司运营成本里体现。简单清晰，符合大多数50人小公司实际——老板看"每个项目自己净赚多少"更干净。

```
员工薪资表（staff_salary）：员工ID / 姓名 / 月薪基数 / 社保公司部分(基数×比例) / 公积金公司部分 / 其他补贴 / 状态(在职/离职)
每月1号定时任务：遍历在职员工 → 每人生成一条 salary_record → 全部标记为"公司级成本" → 不关联任何项目
                                                ↑
                          方案A：默认不摊到项目，只在公司总成本体现
```

**提成（可选，P1开启，不强制）**：
```
开启后：项目回款到账 → 按"回款×提成比例"生成提成 → 可设到公司级或某项目
提成是另一套逻辑（和工资分开），MVP默认关闭
```

**权限矩阵**：

| 操作 | 老板 | 财务 | 项目经理 | 报销人 |
|------|------|------|---------|--------|
| 设薪资标准 | ✅ | ✅ | ❌ | ❌ |
| 录/调社保公积金比例 | ❌ | ✅ | ❌ | ❌ |
| 查看人力成本 | ✅ | ✅ | ❌ | ❌（仅自己） |
| 查看自己薪资 | ✅ | ✅ | ❌ | ✅自己 |

### 15.5 利息与费率

```
利息/贷款参数（财务设）：贷款金额 / 年利率 / 还款方式(等额本息/先息后本) / 起始日
 → 每月生成一条"利息费用"记录 → 计入公司运营成本
平台手续费/税率（财务设）：固定参数，录入即可
```

### 15.6 老板看板最终利润公式

```
项目利润（方案A） = 项目已确认收入
                  - 项目报销/付款
                  - 项目分摊折旧
                  - 项目分成
                  - （可选）该项目应摊人力成本(P1)

公司总支出 = 所有项目支出 + 公司级人力成本 + 公司级折旧 + 利息 + 手续费 + 税费
           = 项目支出 + 固定成本（人力+折旧+利息+手续费+税费）

老板看板：
  📥 总收入（所有项目已核验收入之和）
  📤 总支出
    ├── 项目支出（按项目展开）
    └── 固定成本
        ├── 人力成本：XX,XXX（公司统一承担）
        ├── 资产折旧：XX,XXX
        ├── 项目分成：XX,XXX
        ├── 利息费用：XX,XXX
        └── 平台手续费：XX,XXX
  ─────────────────────
  💰 公司毛利：总收入 - 总支出
```

**关键设计**：方案A下，人力成本不进"单个项目利润"（避免老板看每个项目时纠结"我的团队算谁的"），只在**公司总览**里作为固定成本体现。项目利润 = 纯项目收支，老板看得清爽。**P1**可开启"按项目分摊人力"，但MVP不做。

| 阶段 | 周期 | 核心交付 |

**验证方式**：先找 10 家目标客户深度访谈，覆盖不同行业，探明价格敏感度与科目模板代表性；用原型 + 老板看板演示验证"一键确认 + 下钻 + 项目利润一眼看"接受度。

- 老板从"打开 → 看懂 → 确认"不超过 3 分钟；
- 月中调整占比 < 20%（说明月初编制质量高）；
- 无发票后补通道使用率 < 30%（说明大部分员工还是有发票的）；
- **项目立项耗时 < 5 分钟**（老板点开 → 填合同额 → 选预算 → 提交 → 通过）；
- **老板能 3 秒看出"哪个项目赚钱、哪个在亏、有没有烂账"**。
