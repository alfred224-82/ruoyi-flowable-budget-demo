## 一、总体架构

### 1.1 技术选型（Java 8）

| 层 | 选型 | 说明 |
|----|------|------|
| 语言/框架 | Java 8 + Spring Boot 2.7.18 | 最后支持 Java 8 的版本 |
| ORM | MyBatis-Plus 3.5.x | 多租户拦截器 |
| 前端 PC | Vue3 + Element Plus | 财务/管理员重操作 |
| 前端小程序 | uni-app | 编译微信小程序 |
| 数据库 | MySQL 8.0 | 共享表 + tenant_id |
| 缓存 | Redis 7 | 映射规则/额度/access_token |
| 对象存储 | 腾讯云 COS | 发票/合同/照片 |
| 消息推送 | 微信订阅消息（RestTemplate） | 预警通知 |

### 1.2 分层

```
Controller → Service → Manager → Mapper（MyBatis-Plus）
                     ↓
               TenantContext（ThreadLocal，存 tenant_id + role）
                     ↓
               MyBatis-Plus 多租户拦截器（自动拼 tenant_id 条件）
```

### 1.3 多租户隔离（ADR-007、M-2、M-3）

- 共享表 + `tenant_id` 列
- JWT payload 含 `tenant_id` + `role`
- 过滤器链：验签 JWT → TenantContext.set → 拦截器拼 SQL
- **绝不**从 URL/参数/前端取 tenant_id（防篡改）

## 二、核心业务模型

### 2.1 三层科目 + 两条映射（ADR-005）

```
费用科目 →[映射A]→ 预算科目 →[映射B]→ 大类
```

- 映射A：租户级，关键字 + 财务确认，走草稿→发布（ADR-008）
- 映射B：系统内置，固定

### 2.2 预算/映射双版本（ADR-002、ADR-008）

- 预算版本锁定后存**快照**（mapping_snapshot），映射修改不影响已锁定版本
- 映射发布前做**影响分析**

### 2.3 审批单向（ADR-001）

- 调整申请统一接口：`/api/budget/adjust/apply`
- 老板直接加额度也走此接口（自动通过但留记录）

### 2.4 管控前置（ADR-003）

- 提交 API 内同步校验大类额度
- 大类超 → 拦截；预算科目超 → 警告

## 三、关键流程时序

### 3.1 编制闭环
系统初稿 → 财务微调 → 老板确认 → 锁定 → 快照

### 3.2 报销管控
提交 → 自动匹配科目 → 大类校验 → 财务审核 → 确认科目 → 计入实际

### 3.3 映射变更
草稿修改 → 影响分析 → 发布 → 新版本号（不影响已锁定预算）

## 四、多租户登录与小程序角色分流

> 对应 ADR-001~027 及 M-1~M-6。三个小程序角色：**老板 / 项目经理 / 报销人**（财务走 PC）。

### 4.1 三个角色登录后分流

**原则**：登录只做一次，角色从 Token 取，前端按角色渲染 TabBar 与首页；**不按角色拆成多个小程序**（M-1）。

**登录链路（uni-app）**：

```
App.onLaunch()
  └── 读本地缓存 token
        ├── 有 → GET /api/me → {role, tenantId, name}
        │       → 存 globalData + storage
        │       → 按 role reLaunch 对应首页
        └── 无 → wx.login() → code
                  → POST /api/login {code}
                  → 后端查 user（WHERE openid=? AND tenant_id=?）
                  → 返 JWT（payload: tenantId + role）
                  → 存缓存 → 按 role 跳首页
```

> openid 在租户内唯一即可；同一微信用户在不同公司 = 两条 user 记录（不同 tenant_id）。

**角色 → 页面映射（前端动态 TabBar）**：

```js
// roleMenus.js
export const ROLE_TABBAR = {
  BOSS:    ['/pages/boss/home','/pages/project/list','/pages/approve/list','/pages/my/index'],
  MANAGER: ['/pages/project/my','/pages/income/confirm','/pages/approve/list','/pages/my/index'],
  EMPLOYEE:['/pages/home/index','/pages/expense/create','/pages/expense/mine','/pages/my/index']
}
```

`App.vue` 的 `onShow` 根据 `globalData.role` 调 `uni.setTabBarItem` 动态换文案/图标（或自定义 TabBar 组件 v-if 渲染）。

**后端三重防护**：
1. JWT → tenant_id + role → TenantContext（ThreadLocal）
2. MyBatis-Plus `TenantLineInnerInterceptor` 自动拼 `AND tenant_id=?`
3. 接口级 `@RequireRole(BOSS)` 方法拦截（M-6）

### 4.2 同域名多公司划分（M-2、M-3）

**单域名 + JWT tenant_id 逻辑隔离，不分子域名、不部署多套**：

```
https://api.yourdomain.com  →  Nginx  →  单 Spring Boot 实例
Authorization: Bearer <JWT>
JWT payload: { uid:123, tenantId:"t_companyA", role:"BOSS" }
```

过滤器链：验签 → TenantContext.set → 拦截器拼 SQL → 业务代码零感知。

**第二家公司入驻**：
- 老板 PC「开通新公司」→ 建 `tenant`（生成 t_companyB）→ 复制系统模板（科目树/映射/角色）
- 该公司首个用户扫码 → 走「绑定到租户」流程（手机号+邀请码）
- 此后该老板 JWT 带 t_companyB，数据全为公司B

**同一用户跨公司（M-4）**：
- user 表允许两条（同 openid、不同 tenant_id）
- 登录命中多 tenant → 前端弹「选择公司」浮层 → 选定刷新 token
- 切换公司 = 重新选 tenant

**大客户物理隔离预留（M-5）**：预留动态数据源开关——普通租户共享库+列隔离；VIP 命中"独立 schema"→ 动态切换 DataSource；业务 SQL 因 TenantContext 已透传无需改动。

### 4.3 部署要点（腾讯云）

- 后端：轻量应用服务器（2核4G）/ CVM，跑 Spring Boot Jar
- DB：云数据库 MySQL（或自建）
- 缓存：云数据库 Redis
- 存储：COS（发票/合同/照片）
- 域名 + 免费 DV SSL + ICP 备案（备案免费，域名按年付费）
- 详见《发布成本》文档

## 七、开发纪律（引用 ADR）

- ADR-001：调整额度只走申请接口，禁止直改字段
- ADR-003：校验同步执行，不异步后置
- ADR-004：报销表单不含费用科目必填
- ADR-007：所有表/查询带 tenant_id，拦截器统一处理
- ADR-008：映射修改禁止直改已发布映射
- ADR-014：发票验真 P0，打卡 P1
- ADR-016：通知合并，禁止每事件一条
- ADR-018：后补通道 + 信用分
- ADR-019~023：资金管控平台 + 项目模块
- ADR-024~027：隐形成本（工资社保方案A/分成/折旧/利息）
- **M-2/M-3/M-6：tenant_id 取自 JWT，不信任前端；方法级角色拦截**

## 八、非功能性

- **安全**：JWT + @RequireRole + tenant_id 拦截 + 操作日志
- **性能**：映射规则 Redis 缓存、额度校验原子操作
- **可观测**：Spring Boot Actuator + 关键业务日志
- **Java 8 兼容**：不使用 record / switch 表达式 / var / List.of（用 Lombok @Data、传统 switch、Collections.singletonList、RestTemplate）
