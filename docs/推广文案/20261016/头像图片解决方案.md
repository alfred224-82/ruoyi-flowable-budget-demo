修正方案：服务端预生成 + srcset 自动选档

重点是别让前端拿到原图。用户上传头像后，服务端立即生成 sm/md/lg 三档 WebP，原图只归档不下发。

<img src="a1_md.webp"
srcset="a1_sm.webp 80w, a1_md.webp 120w, a1_lg.webp 200w"
sizes="56px" width="56" height="56"
loading="lazy" decoding="async">

浏览器按屏幕密度和实际显示宽度自动挑档，不需要 JS 判断。三个容易踩的坑：

sizes 必须写——不写浏览器按 100vw 猜，会选偏大的档，等于白做
width/height 写死——否则图片加载完页面跳动（CLS）
首屏头像别 lazy——改 fetchpriority="high"，懒加载反而让首屏更慢

老浏览器用 <picture> + type="image/webp" 降级到 JPEG。


给你的落地工具


#!/usr/bin/env bash
# ============================================================
# 头像批量处理脚本
# 用法：./gen_avatars.sh 输入目录 输出目录
# 依赖：ImageMagick (magick) + libwebp (cwebp)
#   Ubuntu/Debian: sudo apt install imagemagick webp
#   macOS:         brew install imagemagick webp
# ============================================================
set -e
IN=${1:-./avatars_orig}
OUT=${2:-./avatars_out}
mkdir -p "$OUT"

# 三档尺寸：sm 顶栏小图 / md 列表常用 / lg 个人中心大图
SM=80
MD=120
LG=200

for f in "$IN"/*.{jpg,jpeg,png,JPG,JPEG,PNG}; do
[ -e "$f" ] || continue
name=$(basename "${f%.*}")

# -resize 用 ^ 填充 + -gravity center -extent 居中裁正方形
# （头像多为圆形，非正方形原图直接缩放会被拉变形）

# WebP 三档
magick "$f" -resize "${SM}x${SM}^" -gravity center -extent "${SM}x${SM}" \
-strip -quality 80 "$OUT/${name}_sm.webp"
magick "$f" -resize "${MD}x${MD}^" -gravity center -extent "${MD}x${MD}" \
-strip -quality 80 "$OUT/${name}_md.webp"
magick "$f" -resize "${LG}x${LG}^" -gravity center -extent "${LG}x${LG}" \
-strip -quality 80 "$OUT/${name}_lg.webp"

# JPEG 兜底（不支持 WebP 的老浏览器）
magick "$f" -resize "${MD}x${MD}^" -gravity center -extent "${MD}x${MD}" \
-strip -interlace Plane -quality 82 "$OUT/${name}_md.jpg"

echo "✓ $name  $(du -h "$f" | cut -f1) → sm/md/lg 已生成"
done

echo ""
echo "产物清单："
du -sh "$OUT"
ls -1 "$OUT" | wc -l | xargs echo "文件数："
avatars_out/ 里 16 个文件已经处理好了，可以直接上传使用。gen_avatars.sh 是批量脚本，以后新增头像跑一遍就行（需 ImageMagick + libwebp）。

脚本里有个关键细节：用 -resize 80x80^ -gravity center -extent 80x80 做中心裁正方形，而不是直接缩放——你的原图是 1328×1776 竖构图，直接缩会被拉变形。

一个容易走错的方向
别只压质量不缩尺寸。​ 实测同一张图 400px 压到最优也要 6 KB，而 120px 只要 2 KB——缩尺寸带来的收益远大于调质量参数。很多人拿 TinyPNG 把原图从 2.9MB 压到 800KB 就觉得解决了，其实还是慢 300 倍。

另外头像这种小图不建议上 AVIF，编码慢、收益对不上耗时，WebP 已经够了。真正需要 AVIF 的是大尺寸宣传图。
