# 多租户小程序推广分销与激励方案

## 一、整体架构

- 系统是多租户 SaaS 模式，每个门店/商家是一个租户
- 所有租户共用**同一个小程序**
- 通过小程序码携带参数区分租户和身份
- 各租户数据完全隔离

---

## 二、版本适用范围（重要）

**本方案（推广码、拉新奖励、归因、活动首单识别等全部规则）仅适用于「小微版」。**

| 版本套餐 | 是否启用本套推广分销规则 |
|---------|------------------------|
| **小微版** | ✅ **启用**（完整生效） |
| 基础版 | ❌ 不生效 |
| 高级版 | ❌ 不生效 |
| 专业版 | ❌ 不生效 |

### 规则说明

- 上述四个版本（小微版、基础版、高级版、专业版）为系统的**套餐/版本**概念，与"租户"是两个维度
- **租户**决定"哪个门店"，**版本**决定"这个门店能用哪些功能"
- 推广分销功能仅在租户当前购买的版本为**小微版**时开放；其他版本下，本方案涉及的页面、接口、规则均**不生效**
- 后续若某版本需要启用，按此文档对齐即可（本规则可平滑扩展）

### 版本校验点（需在系统中落地）

| 校验时机 | 判断逻辑 |
|---------|---------|
| 生成推广码 | 当前租户版本 == 小微版 才允许 |
| 扫码归因 | 当前租户版本 == 小微版 才记录推广关系 |
| 拉新奖励发放 | 当前租户版本 == 小微版 才触发 |
| 老板后台相关配置项 | 仅小微版可见、可配置 |

> 说明：版本判断建议在后端统一封装为「功能开关」，以版本为维度控制本套规则的整体开/关，避免各处散落判断逻辑。后续整合到总需求时，可归入「套餐与功能权限」章节。

## 三、推广码规则

### 3.1 码的类型

| 类型 | 参数 | 用途 |
|------|------|------|
| 门店码 | `t=租户ID` | 贴店里，扫码进该店首页 |
| 个人推广码 | `t=租户ID&r=角色&u=用户ID` | 个人专属，扫码归因到具体人 |

参数尽量精简（微信小程序码 scene 限 32 字符），例如：
`t=001&r=c&u=23`（tenant=001, role=coach, uid=23）

### 3.2 码的有效期

- **永久有效**，不做过期、续期逻辑
- 离职/禁用：后台把该人状态关掉，扫码不再归因

### 3.3 码的生成

- 每人首次点"生成推广码"时调接口生成，之后一直用同一个
- 码图片可保存到手机相册，用于发朋友圈、私聊、打印

## 四、角色与权限

| 角色 | 管理后台 | 推广码 | 说明 |
|------|---------|--------|------|
| 老板 | ✅ 有 | ✅ 有 | 后台管理门店、查看数据、发放奖励 |
| 教练 | ❌ 无 | ✅ 有 | 小程序内"我的推广码"页面下载 |
| 助教 | ❌ 无 | ✅ 有 | 同上 |
| 顾客 | ❌ 无 | ✅ 有 | 同上，顾客也有自己的推广码 |

**所有角色（含顾客）都有推广码，规则统一。** 角色只用于权限与奖励类型区分。

无后台的角色（教练/助教/顾客）直接在小程序内"我的推广码"页面查看、保存自己的码。

## 五、推广归因规则

1. 用户扫码 → 解析 `tenant_id + role + user_id`
2. **谁最后扫码业绩归谁**：顾客扫了谁的码，从那一刻起直到下一次扫别人的码之前，这段时间内的所有消费业绩都归这个人
3. 每次扫码即"交接点"，交接之前的业绩已锁定，**不回溯修改**
4. 消费发生时取"当时的推广人"

### 举例

```
Day1：扫 教练A 的码 → 推广人 = 教练A
  ├─ Day1 消费 200 → 算教练A
  └─ Day2 消费 300 → 算教练A
Day3：扫 助教B 的码 → 推广人 = 助教B
  ├─ Day3 消费 150 → 算助教B
  └─ Day5 消费 400 → 算助教B
```

### 边界情况

| 情况 | 处理 |
|------|------|
| 从未扫过码直接消费 | 无推广人，归"自然流量" |
| 扫了码未消费又扫别人的码 | 以最后一次为准 |
| 同一码反复扫 | 推广人不变 |
| 推广人已被老板禁用 | 禁用前的消费照常算；禁用后新扫码不再归因 |

## 六、业绩与奖励规则（核心）

### 6.1 基本原则

- **注册不算业绩**，只有顾客到店产生**真实消费**才算
- 消费记录关联到当时扫码的推广人
- **能奖励的只有"拉新"**：推广人带来的顾客**首次消费（拉新成功）**才触发一次奖励
- **其他活动不给推广人额外奖励**：顾客后续参加店内各种活动、享受活动优惠，都属于正常消费，**不再给推广人发奖励**，只有活动内的优惠给到顾客本人

### 6.2 员工的奖励（教练/助教）—— 同样走拉新规则

- 员工推广**同样只有一条固定规则：拉新**（与顾客一致）
- 规则本身固定不变，**唯一可变的是"老板后台配置的奖励内容"**
- 奖励形式：**现金 / 钱**（与顾客的"优惠券"区分）
- 满足条件的拉新，**由系统直接发放**到员工账户，无需老板逐笔手动确认
- 发放结果**需通知到员工的小程序**（消息中心 / 弹窗提示）
- 奖励内容（如每拉一个新客奖多少）在**老板后台统一配置**

#### 发放流程

```
顾客首次消费（拉新成功）→ 系统判定满足拉新条件
  → 系统按老板后台配置的奖励内容自动计算
  → 自动发放奖励到员工账户（仅此一次）
  → 员工小程序收到通知："你拉新的顾客已消费，获得推广奖励 ¥XX"
  → 员工在小程序内查看 / 提现
```

> 该顾客后续的二次消费、参加店内活动消费等，**不再给推广人发奖励**，只享受活动本身的优惠。

#### 员工小程序内展示

```
消息
  · 你拉新的顾客已消费，获得推广奖励 ¥50

我的推广
  · 本月推广：12 人
  · 已消费（拉新成功）：5 人
  · 累计奖励：¥150
```

### 6.3 顾客（普通用户）的奖励 —— 拉新（规则固定）

- 顾客推广**只有一条固定规则：拉新**
- 规则本身固定不变，**唯一可变的只有"老板设置的奖励内容"**
- 奖励形式：**优惠券**，由**系统直接发放**到顾客的小程序账户
- 拉新条件、奖励内容均在老板后台配置

#### 规则说明

| 项目 | 说明 |
|------|------|
| 推广规则 | 固定为"拉新"一条规则，不可变 |
| 奖励形式 | 优惠券（如 8 折券、送礼品券等） |
| 发放方式 | **系统自动直接发放**到顾客小程序 |
| 可变项 | **仅老板后台设置的奖励内容**（折扣力度、送什么） |

> 员工奖励 vs 顾客奖励：
> - **规则相同**：都走"拉新"，都系统自动发放，奖励内容都由老板后台配置
> - **唯一区别是奖励形式**：员工拿**现金**，顾客拿**优惠券**

#### 6.4 奖励结算流程（统一）

```
顾客首次消费（拉新成功）→ 系统记录消费 + 关联推广人
  → 判定满足拉新条件
  → 按角色取老板后台配置的奖励内容：
      ├─ 推广人是员工（教练/助教）→ 系统自动发放现金奖励
      │   → 通知员工小程序
      └─ 推广人是顾客 → 系统自动发放优惠券
          → 通知顾客小程序

顾客后续消费（非拉新）→ 正常享受店内活动优惠
  → 推广人不获得额外奖励
```

> **两条线：**
> - **拉新奖励线**：首次消费触发，给推广人（员工现金 / 顾客优惠券），仅一次
> - **活动优惠线**：顾客任何消费都可享受店内活动优惠，给顾客本人，与推广奖励无关

## 七、活动与首单识别规则

### 7.1 活动类型

| 活动类型 | 优惠力度 | 说明 |
|---------|---------|------|
| 首次活动 | 大（如 8 折、立减 50、送礼品） | 限**首次到店消费的顾客** |
| 常规活动 | 小（如 9.5 折、满减） | 所有顾客通用 |

### 7.2 首客判断依据

- **以手机号为准**
- 顾客在小程序授权/下单时**绑定手机号**
- 系统用手机号判断：这个号码**是否已经享受过本次活动**

### 7.3 判断逻辑

```
顾客扫码进店 → 准备下单 / 参加活动
  ↓
系统查：该手机号在本次活动中是否有消费记录？
  ├─ 无 → 首客 → 享受首次活动优惠
  └─ 有 → 老客 → 只能享受常规优惠
```

### 7.4 与推广码的关系

**判断的是"有没有享受过活动"，不是"扫了谁的码"。** 手机号是核心维度，换码、换推广人都不影响"已享受活动"的事实。

| 场景 | 优惠 | 业绩归属 |
|------|------|---------|
| 顾客A 扫教练甲码 → 首次消费 | 首单 8 折 | 归教练甲 |
| 顾客A 第二次扫助教乙码 → 消费 | 仅常规优惠 | 归助教乙 |
| 顾客A 换扫顾客C码再来 | 仅常规优惠 | 归顾客C |

**首单判定（管优惠）与推广业绩（管归属）两条线独立，互不干扰。**

> 补充：**店内所有活动都只有"给顾客的优惠"，不产生对推广人的额外奖励。** 推广人能拿奖励的唯一来源是"拉新"（见 6.1）。

### 7.5 规则要点

| 规则 | 说明 |
|------|------|
| 手机号唯一识别 | 同一手机号 = 同一顾客 |
| 按活动判断 | 每个活动独立判断"是否首次" |
| 已享受不可重复 | 手机号命中即不再给首单优惠 |
| 与推广码独立 | 换码不影响首客资格 |
| 业绩仍归扫码人 | 首单判定只管优惠，不管归属 |

## 八、消费回传通知

### 8.1 两类通知

| 角色 | 触发 | 发放方式 | 通知方式 | 内容 |
|------|------|---------|---------|------|
| 员工（教练/助教） | 推广的顾客**产生消费、满足拉新条件**时 | 系统自动发放现金 | 小程序内通知 | "你拉新的顾客已消费，获得推广奖励 ¥XX" |
| 顾客 | 推广的顾客**产生消费、满足拉新条件**时 | 系统自动发放优惠券 | 小程序内通知 | "你推广的顾客已消费，获得优惠券 XX" |

### 8.2 通知目的

- 让员工/顾客即时知晓推广产生的结果
- 促使推广人主动联系顾客（教练约课、顾客推荐下次活动），提升复购

## 九、前端页面需求

### 9.1 员工（教练/助教）

小程序内"我的推广码"页面：
- 展示自己的小程序码（可长按保存）
- 展示推广数据（带来多少人、多少人已消费、拉新成功数）
- 展示奖励：累计奖励金额 / 已发放
- **接收奖励发放通知**（系统自动发放后推送）

### 9.2 顾客

小程序内"我的推广码"页面：
- 展示自己的小程序码（可长按保存）
- 展示拉新数据（拉来多少人、多少人已消费）
- **系统自动发放的优惠券直接到账**，并在小程序内通知

### 9.3 老板管理后台

- 查看所有推广人的推广数据
- 查看消费记录及归因
- 按天 / 周 / 月统计业绩
- **统一配置拉新奖励内容**（唯一可变项）：
  - 员工拉新奖励（如每拉一个新客奖多少现金）
  - 顾客拉新奖励（如折扣力度、送什么优惠券）
- 配置首单活动力度
- 禁用 / 启用某个人的推广码

## 十、关键规则汇总

| 规则 | 说明 |
|------|------|
| **版本适用** | **仅「小微版」启用，基础版/高级版/专业版不生效** |
| 一店一码 | 每个租户有门店码 |
| 一人一码 | 每个角色有个人推广码 |
| 全员统一 | 老板/教练/助教/顾客都有推广码 |
| 码永久有效 | 不设置过期 |
| 扫码归因 | 谁最后扫码，业绩归谁，实时更新 |
| 历史不回溯 | 交接前业绩已锁定 |
| 注册不算业绩 | 必须产生真实消费 |
| 奖励仅拉新 | **只有拉新成功给推广人发奖励**，仅此一次 |
| 活动只优惠 | 店内其他活动只给顾客本人优惠，不给推广人额外奖励 |
| 全员走拉新 | 员工、顾客都只有"拉新"一条固定规则 |
| 奖励内容可配 | **仅老板后台可配置奖励内容**（员工现金、顾客优惠券） |
| 系统自动发放 | 拉新成功系统直接发放，并通知对应小程序 |
| 员工奖励现金 | 拉新成功系统自动发放，通知员工小程序 |
| 顾客奖励优惠券 | 拉新成功系统自动发放，通知顾客小程序 |
| 首单按手机号 | 防重复薅羊毛 |
| 优惠/业绩分离 | 首单判定与推广归属互不影响 |
| 奖励/活动分离 | 拉新奖励给推广人，活动优惠给顾客，互不影响 |
| 消费回传 | 微信订阅消息通知推广人 |
| 租户隔离 | 各租户数据独立 |
