# 多租户 SaaS 平台（小微版）需求文档 V3.7

> **版本**：V3.7（小微版 · 最终归档版）  
> **说明**：本文档为**单一归档文件**，正文为完整需求，附录 A 为五角色菜单骨架。
> 所有已确认结论均已沉淀，作为开发与评审的**最终技术基线**。

## 〇、版本边界与核心原则

### 0.1 小微版定位
本需求仅适用于**小微版**。
- **核心目标**：帮助个体户 / 小微企业主**算清账**（赚了多少、花了多少、剩多少）。
- **不涉及**：专业财务概念（会计科目、借贷记账、固定资产折旧、税务申报等）。

### 0.2 财务模型（极简）
- **单一业务类型**：系统只有**「固定支出」**一种成本归集方式。
- **标签化分类**：房租、水电、工资、油费等均为**标签（Tag）**，仅用于分类和筛选，**非财务科目**。
- **版本隔离**：与企业版（含预算、固定资产模块）在数据结构上**物理隔离**，不存在升级兼容关系。

### 0.3 合规模型（轻量）
- 仅做**轻量语音合规**：录音开关、转写留痕、敏感词命中、留存到期。
- **不做**实时监听、人工全盘质检或法务级审计。

### 0.4 推广模型（极简）
- **小程序端**：老板、员工、顾客均可见「我的推广码」。
- **奖励类型**：本版本**仅支持"拉新奖励"**，不做多级分销、不做层级返佣。
- **配置权**：**仅老板**可配置拉新奖励规则；Admin 仅控制平台功能总开关。

### 0.5 首页与角色定位
系统根据角色身份自动跳转至对应首页，职责严格分离。

| 角色 | 默认首页 | 核心职责 |
|---|---|---|
| **Admin** | 平台驾驶舱 | 平台治理、License、字典、大盘监控 |
| **租户管理员** | 企业概览（工作台） | **配置自检**（原子数据 / 周期 / 合规） |
| **老板** | 经营驾驶舱 | **经营决策 + 业务异常处理 + 拉新奖励配置** |
| **员工** | 工作台 | 任务执行 + 我的推广码 |
| **顾客** | 发现页 | 消费预约 + 我的推广码（邀请有礼） |

**职责边界铁律：**
1. **租户管理员**：只关心"配置对不对"，**不处理**业务待办与预约异常，**不配置推广奖励**。
2. **老板**：只关心"生意好不好"，**全权处理**业务待办与异常，**唯一**拥有拉新奖励配置权。
3. **员工 / 顾客**：仅查看本人推广记录与奖励，**不可配置**。

## 一、租户与行业初始化

1. **租户创建**
   - Admin 创建租户时，**单选**行业类型（旅游 / 研学 / 桌游 / 足浴等）。
   - 行业一旦确定，**租户不可更改**。
2. **原子数据初始化**
   - 系统根据行业自动初始化原子示例数据：
     - **旅游**：项目（杭州一日游 / 云南七日游）、房间（大巴车 / 集合点）、角色（导游 / 司机）。
     - **桌游**：项目（剧本列表）、房间（房间号）、角色（DM）。
   - 租户管理员**无**"初始化"按钮，仅可编辑 / 删除 / 复制示例数据。

## 二、License 管理（Admin 平台级）

**1. 功能定位**
License 是平台控制租户功能访问权限的核心机制。小微版功能（如固定支出、语音合规、推广码）均受 License 约束。

**2. 核心流程**
1. **Admin 定义 License 模板**：定义"小微版"包含的功能包。
2. **Admin 签发 License**：为具体租户绑定模板，设置有效期（如 1 年）。
3. **租户激活**：租户管理员登录后，系统校验 License 有效性。

**3. 约束逻辑**
- **功能开关**：租户管理员的菜单受 License 控制，无权限则菜单隐藏。
- **首页展示**：租户管理员的「企业概览」首页需展示 License 状态（剩余天数、是否已过期）。

**4. License 到期处理机制（硬性约束 · 逃生通道）**

核心原则：**业务冻结，管理逃生**——License 到期后业务功能全停，但保留**唯一的"逃生通道"**供租户自救。

1. **Web 端行为**

   | 角色 | License 有效 | License 到期后 |
   |---|---|---|
   | **租户管理员** | 正常访问所有菜单 | ✅ **允许登录**，但**仅能访问"上传 License"页面**，其余菜单、按钮、API 全部禁用；登录后**强制跳转**至该页面 |
   | **老板 / 员工** | 正常访问 | ❌ **禁止登录**，登录页提示"企业服务已到期，请联系企业管理员更新 License" |

2. **小程序端行为**（老板 / 员工 / 顾客一律受限）
   - ❌ **禁止进入任何业务页面**。
   - 启动 / 登录时由路由守卫拦截，弹窗提示：
     > "当前企业服务已到期，无法使用。请联系企业管理员更新 License。"
   - 拦截期间**不可预约、不可查看活动、不可查看数据**，仅保留"退出登录 / 关闭"。

3. **"上传 License"页面（逃生通道）**
   - **页面定位**：系统级强制页面，**非普通菜单项**，不依赖任何业务数据。
   - **核心功能**：展示当前 License 状态（已过期）、上传新 License 文件 / 输入 License Key、提交激活。
   - **约束**：即使数据库配置异常，该页面也必须可访问；提交后由 Admin 后台（或自动）激活，激活后恢复全部菜单。

4. **Admin 侧状态**
   - Admin「租户列表」中该租户标记为 **"已到期 / 待续费"**。
   - Admin 可手动为该租户**强制续期**或**重置 License**。

5. **边界与数据**
   - **数据保留**：到期后所有历史数据（订单、支出、录音、推广记录）**物理保留**，续期后立即可用。
   - **无只读模式**：到期期间**不开放**任何业务数据的只读查询，确保数据合规与商业逻辑闭环。

6. **统一提示文案**
   - **登录页（老板 / 员工）**："企业服务已到期，无法使用。请联系企业管理员更新 License。"
   - **小程序（全员）**："当前企业服务已到期，无法使用。请联系企业管理员更新 License。"
   - **租户管理员（上传页）**："您的服务已到期，请上传新的 License 以恢复使用。"

7. **开发落地（路由守卫逻辑）**
   1. 角色 = `TENANT_ADMIN` 且 License 无效 → 仅放行 `/license-upload`，拦截其余全部路由。
   2. 角色 = `BOSS` / `STAFF` 且 License 无效 → 拦截全部路由，跳转登录页并提示。
   3. 请求来自小程序且 License 无效 → 返回 `403 + 到期错误码`，由小程序弹窗提示。

## 三、全局字典管理（Admin）

### 3.1 字典范围
Admin 维护全局只读字典，作为系统计算的物理基准。
- 时间单位字典（天 / 周 / 月 / 季 / 年）
- 行业类型字典
- 通用枚举字典（预约失败原因、消息类型等）

### 3.2 字典初始化脚本
**需求描述：**
- 系统上线及版本升级时，**必须提供全局字典的初始化 / 升级脚本**。
- 脚本负责将时间单位、行业类型等基础枚举写入数据库。
- **约束**：脚本需保证**幂等性**，且**版本受控**。

### 3.3 时间单位换算约定（用于算法）
- 1 周 = 7 天
- 1 月 = 30 天（财务通用算法）
- 1 季 = 90 天
- 1 年 = 365 天

### 3.4 字典约束
- 字典数据**仅 Admin 可维护**，租户管理员不可修改。
- 字典作为算法基准，一旦被租户数据引用，**禁止物理删除**（只能禁用）。

## 四、租户管理员配置

### 4.1 企业概览（首页）
租户管理员登录后的默认页面，仅展示**配置态信息**，**不包含业务待办**。

1. **企业基本信息**：公司名称、行业、创建时间、**License 有效期与状态**。
2. **配置健康度（自检）**：
   - **原子数据完整度**：检测项目、房间、角色是否已初始化。
   - **周期规则状态**：检测是否存在可用的周期规则供老板记账。
   - **语音合规状态**：检测是否已按行业要求配置语音开关。
3. **系统公告**：平台发布的通知、版本更新。
4. **快捷入口**：跳转至标签管理、周期规则管理、预约策略等配置页面。

### 4.2 原子资源管理
- 管理项目、房间、角色、员工库。
- 确保原子数据准确，供老板编排 Activity。

### 4.3 固定支出配置

#### 4.3.1 标签管理
- 租户管理员定义企业特有的费用分类。
- **操作**：新增 / 编辑 / 停用标签（如：#房租 #水电 #工资 #油费 #平台年费）。
- **性质**：扁平结构，仅用于展示和报表筛选。

#### 4.3.2 周期规则管理（核心）
- **逻辑**：租户管理员基于 Admin 定义的**时间单位**，通过**"数字 + 单位"**的方式自定义周期规则。
- **操作**：
  1. 选择单位（天 / 周 / 月 / 季 / 年）。
  2. 输入数字（如：1、2、15、3...）。
  3. 设置展示名称（如"1 个月""15 天""1 个季度"）。
  4. **保存**规则。
  5. 设置状态（启用 / 停用）。
- **作用**：生成老板端下拉框的**可选值**，只有**启用**状态的规则对老板可见。

### 4.4 语音与合规配置

#### 4.4.1 语音开关
- 按 Activity 类型开启 / 关闭语音采集。
- 行业默认：旅游默认关，桌游 / 咨询类可默认开。

#### 4.4.2 敏感词管理
- 继承 Admin 提供的平台敏感词底库。
- 允许追加本企业特有的敏感词。

#### 4.4.3 录音留存设置
- 设置租户内录音文件的留存时长。
- **约束**：不能超过 Admin 设定的全局上限（如 90 天）。

#### 4.4.4 转写留痕开关
- 控制是否将顾客语音转写为文本，用于检索和合规检查。

## 五、老板端 — 经营、异常与推广

### 5.1 经营驾驶舱（首页）
老板登录后的默认页面，核心为经营数据与**业务异常处理中心**。

1. **经营数据**：
   - 今日 / 本月营收、支出、净利润。
   - 成本构成（按标签展示）。
2. **业务待办与异常处理中心**（**核心入口**）：
   - **预约冲突**：展示时间或资源冲突的预约，需老板人工干预。
   - **预约失败**：接收 RESERVATION_FAILED 通知，点击"重新预约"自动带入原参数并高亮冲突点。
   - **语音合规命中**：查看敏感词命中记录。
   - **固定支出异常**：如大额支出未配置周期等提醒。

### 5.2 推广管理 — 拉新奖励配置

#### 5.2.1 适用范围
- 小程序端：**老板、员工、顾客**均可见「我的推广码」。
- Web 管理后台：**仅老板**可配置奖励规则。

#### 5.2.2 核心模型：单一拉新奖励
- 奖励对象：**被成功邀请的新客**（或被邀请后完成首单）。
- 奖励来源：**推广人（员工 / 顾客）**获得奖励。
- **不做**：多级分销、层级返佣、员工与顾客差异化奖励配置。

#### 5.2.3 老板端配置（极简）
老板在「推广管理 → 拉新奖励配置」中仅需配置以下项：
1. **开关**：是否开启拉新奖励。
2. **奖励形式**（单选或组合）：固定金额（现金 / 余额）、抵扣券、积分。
3. **触发条件**（二选一）：新客首次绑定（扫码后完成注册 / 绑定）、新客首单（完成第一笔交易）。
4. **奖励上限**（可选）：单推广人月度 / 累计奖励上限。

#### 5.2.4 推广码展示与归属
- **员工 / 顾客**：小程序「我的」页面展示个人专属推广码 / 二维码。
- **绑定逻辑**：新客首次扫码 → 绑定推广人 → 触发条件达成 → 发放奖励。
- **冲突处理**：默认"首次绑定优先"，老板可后台人工调整。

#### 5.2.5 数据留痕
- 系统记录：扫码日志、绑定关系、奖励发放记录。
- 老板端可查看：拉新排行榜、奖励明细（用于线下结算或核销）。
- 员工 / 顾客端：仅可查看**本人**的推广记录与奖励。

#### 5.2.6 边界与约束
- **租户管理员**：无推广菜单，不参与奖励配置。
- **Admin**：仅控制平台级功能开关，不干涉具体奖励金额与规则。
- **财务隔离**：奖励发放与小微版财务模块（固定支出）物理隔离，仅作为营销成本记录。

### 5.3 活动 / 预约管理
- **Activity 类型**：老板编排（定死项目 / 人 / 房）、顾客自建（生成 CUSTOM_BOOKING）。
- **预约策略开关**（租户管理员控制）：允许多 Staff、允许多 Room、允许顾客自建。
- **异常处理**：预约失败通过消息铃铛通知，支持一键重新预约。

### 5.4 固定支出管理
- **录入流程**：
  1. **选标签**：选择租户管理员定义的标签（如"房租"）。
  2. **选周期**：选择租户管理员定义的**周期规则**（如"1 个月"）。
  3. **填金额**：输入该周期内的总金额（如 3000）。
  4. **填名称**：输入描述（如"9月人民路店房租"）。
- **权限**：老板**只能选择**，不能创建 / 修改标签或周期规则。

### 5.5 成本自动分摊算法（核心）

> **原则：只有周期，自动分摊。**

1. **计算基准**
   - 系统不区分"一次性支出"还是"周期性支出"。
   - 所有支出统一通过**周期**折算为**日成本**。

2. **计算公式**
   - **周期天数** = 周期规则数值 × 时间单位换算天数
     - *例：周期规则"3 个月" = 3 × 30 = 90 天*
   - **日成本** = 支出金额 ÷ 周期天数
     - *例：9000 元 / 90 天 = 100 元 / 天*
   - **月度成本** = 当月每日成本之和
     - *例：9 月（30 天）= 100 × 30 = 3000 元*

3. **自动分摊的体现**
   - **买车 / 装修等大额支出**：老板选择**长周期**（如"1 年"或"2 年"），系统自动分摊到每一天，**无需人工填写"分摊月数"**。
   - **房租等常规支出**：老板选择**短周期**（如"1 个月"），系统按月折算。

4. **硬性约束**：**系统中不存在"分摊月数"字段。**

### 5.6 经营报表
- **净利润公式**：净利润 = 总营收 − 员工提成 − 固定支出总额（系统自动汇总）。
- **报表维度**：按**标签**展示成本构成，按**时间**（日 / 月 / 年）展示趋势。

### 5.7 语音合规记录（只读）
- **敏感词命中记录**：时间、关联活动、命中的脱敏片段。
- **录音留存清单**：录音文件、关联活动、预计自动删除时间。
- **顾客异议处理**：顾客发起的录音删除申请及处理状态。

## 八、Admin 平台管理范围

1. **管理边界**：
   - **管**：平台大盘、License、全局字典（含初始化脚本）、合规底线、审计日志、推广码功能总开关。
   - **不管**：租户内的员工名单、具体收支金额、预约记录、录音内容、推广奖励配置。
2. **数据隔离**：Admin 仅能通过租户列表进入**管理视图**（查看配置状态），不能进入**业务视图**（查看老板账本）。

## 九、设计原则汇总

1. **菜单抽象**：菜单不随行业变化，仅文案和角色具象化。
2. **原子化**：Project / Staff / Room 为原子，规则在 Activity 层声明。
3. **权限分离**：Admin 定标准，租户管理员定规则，老板定数据。
4. **财务极简**：单一固定支出池 + 标签分类，去财务化。
5. **算法统一**：所有成本通过"周期"折算为日成本，自动分摊。
6. **配置下放**：周期规则由租户管理员定义，适应不同经营习惯。
7. **版本隔离**：小微版与企业版财务模块物理隔离。
8. **合规轻量**：仅做必要留痕与敏感词检查。
9. **首页即身份**：首页直接反映角色核心职责。
10. **职责边界**：租户管理员管配置自检，老板管经营与异常，员工 / 顾客看推广码。
11. **字典受控**：全局字典通过初始化脚本统一管理，禁止租户篡改。
12. **推广单一**：仅老板可配置拉新奖励，不做多级分销与层级返佣。

## 七、首页与职责边界（铁律）

| 角色 | 默认首页 | 核心职责 |
|---|---|---|
| **Admin** | 平台驾驶舱 | 平台治理、License、字典、大盘监控 |
| **租户管理员** | 企业概览（工作台） | **配置自检**（原子数据 / 周期 / 合规） |
| **老板** | 经营驾驶舱 | **经营决策 + 业务异常处理 + 拉新奖励配置** |
| **员工** | 工作台 | 任务执行 + 我的推广码 |
| **顾客** | 发现页 | 消费预约 + 我的推广码（邀请有礼） |

**职责边界铁律：**
1. **租户管理员**：只关心"配置对不对"，**不处理**业务待办与预约异常，**不配置推广奖励**。
2. **老板**：只关心"生意好不好"，**全权处理**业务待办与异常，**唯一**拥有拉新奖励配置权。
3. **员工 / 顾客**：小程序端均可查看"我的推广码"，仅查看本人推广记录与奖励，**不可配置**。
4. **Admin**：只管平台级，不碰租户具体业务数据；字典通过初始化脚本统一管理。
