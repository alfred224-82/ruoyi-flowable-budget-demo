## 一、系统初始化（从0开始构建）

### 1.1 数据库准备

**前提条件**：
- MySQL 8.0+ 已安装并启动
- 已创建数据库 `ry-flowable-plus`（或自定义名称）
- 已导入 RuoYi-Flowable-Plus 基础表结构（`sql/ry-flowable-plus.sql`）

**执行顺序**（v1.16，严格按序号，不可颠倒）：

> **推荐方式**：平台采用「一套系统 + 建表一次建齐、版本靠菜单模板 + 功能开关区分」策略。**共享部署（一套库服务多版本多业态）**时，直接按专业版全量口径执行《专业版/sql/00_执行顺序.sql》（36 个脚本，阶段一~十五），一次建齐全部表与菜单，再靠版本分配 + 开关控制开放。若为**单版本独立部署**，按对应版本目录的《00_执行顺序.sql》执行（系统管理 26 脚本 / 基础版 34 脚本 / 高级版 45 脚本 / 专业版 36 脚本 / ★小微版 32 脚本，累计制）。
>
> ★**小微版为独立产品线**（tenant_type=micro），其脚本集含 M15_01~M15_14 + M16_01~M16_03 + 平台底座子集，与企业版脚本不互相部署。共享部署时，小微版脚本需额外执行（M15_09~M15_13 为 v1.14 新增，M16_01~M16_03 为 v1.16 新增·推广分销专属）。

## 二、创建租户

### 2.1 进入租户管理页面

**操作路径**：登录后台 → 系统管理 → 租户管理

**界面说明**：
- 租户列表页：展示所有租户（租户名称、联系人、版本、状态、到期时间）
- 右上角"新增租户"按钮：创建新租户

### 2.2 新增租户

点击"新增租户"按钮，填写表单：

| 字段 | 说明 | 示例 |
|------|------|------|
| 租户名称 | 公司/组织名称 | 杭州某某科技有限公司 |
| 联系人 | 租户管理员姓名 | 张三 |
| 联系电话 | 手机号 | 13800138000 |
| 用户名 | 租户管理员登录账号（系统自动创建） | zhangsan |
| 密码 | 租户管理员初始密码 | 123456 |
| ★**产品线（tenant_type）** | ★v1.14 必选：micro（小微版）/ enterprise（企业版） | enterprise |
| ★**版本档位（version_type）** | ★v1.14 必选，级联于 tenant_type：micro→[micro_lite,micro_pro]；enterprise→[basic,advanced,pro] | basic |
| **业态包（biz_code）** | ★v1.12 必选：fund_control（资金管控）/ boardgame（桌游）/ fresh_food（生鲜） | fund_control |
| **访问通道（access_channel）** | ★v1.12 必选：wechat（微信小程序+公众号）/ wecom（企业微信）/ open_api（开放平台） | wechat |
| 授权类型 | 试用/正式（影响使用天数计算） | 试用 |
| 使用天数 | 授权天数（NULL=永久） | 30 |

> **★新建租户级联（v1.14）**：选产品线(tenant_type) → 级联版本档位(version_type) → 级联行业模板（小微版专属）→ 预览默认角色配方。级联接口：`GET /system/edition/version-options?tenantType=micro|enterprise`、`GET /system/edition/industry-options?tenantType=micro`、`GET /system/edition/default-role-preview?versionType=micro_pro`。
>
> **业态包与通道说明**：`biz_code` 决定业态能力集与文案（`biz_bundle` 引擎加载 menus/copy/schema_blocks/engine_strategy/feature_flags）；`access_channel` 决定登录方式与消息通道。两者与版本（edition）共同构成**三维能力模型**。企微密钥（wecom_*）加密存储、接口返回脱敏。

**提交后系统自动完成**：
1. 创建租户记录（`sys_tenant`，状态=NORMAL，版本=BASIC 或指定版本，写入 biz_code / access_channel）
2. 创建租户管理员账号（`sys_user`，绑定租户，分配 boss 角色）
3. 按版本模板复制菜单授权到 `sys_role_menu`（基础版仅 boss/employee 2 角色；高级版起四业务角色）
4. 初始化租户默认数据（项目关联规则、凭证导出模板等）
5. 记录版本变更日志（`sys_tenant_version_log`，changeType=INIT）

**验收检查**：
```sql
-- 查看新创建的租户
SELECT id, company_name, contact_name, edition, status, expire_date
 FROM sys_tenant ORDER BY create_time DESC LIMIT 1;

-- 查看租户管理员
SELECT user_id, user_name, dept_id, tenant_id
 FROM sys_user WHERE tenant_id = <新租户ID>;

-- 查看管理员角色分配
SELECT ur.user_id, r.role_name, r.role_key
 FROM sys_user_role ur
 JOIN sys_role r ON r.role_id = ur.role_id
 WHERE ur.user_id = <管理员user_id>;
```

### 2.3 分配版本

**操作路径**：租户列表 → 选择租户 → 点击"版本分配"按钮（6006权限）

**界面说明**：
- 弹窗选择版本：基础版 / 高级版 / 专业版
- 选择后系统自动：
  1. 更新 `sys_tenant.edition` 字段
  2. 写入版本变更日志（`sys_tenant_version_log`）
  3. 按版本模板重新授权菜单（`sys_role_menu`）
  4. 刷新功能开关缓存

**版本选择建议**（v1.14）：
- ★**小微版·免费档（micro_lite）**：个体商户初步体验，仅推广发布/店铺管理/活动浏览页，永久免费，无预约/结算/报表
- ★**小微版·收费档（micro_pro）**：正式经营门店，全经营（预约/结算/收支/报表/定价/推广/顾客管理/防爽约），试用 7 天免费 / 首月 299 / 月付 499 / 包年 4790
- **基础版（BASIC）**：50 人以下小公司/门店，仅 boss + employee 2 角色，轻量记账 + 项目资金流 + 全量业态能力（max_roles=2）
- **高级版（ADVANCED）**：中型企业，4-6 角色，承接下移的 11 类资金管控重能力 + 部门预算/打卡/信用/利润报表 + 企业微信通道（max_roles=6）
- **专业版（PROFESSIONAL）**：集团/多组织/多账套，不限角色，多组织预算 + 人脸核身 + 多账套 + 开放平台 API + 企微双通道（max_roles=NULL）

> ★**小微版与企业版分属两条产品线**（`tenant_type` 区分），不互相升级/降级。小微版内 lite→pro 升级 = `UPDATE version_type` + 刷新菜单缓存，零数据迁移。

**验收检查**：

```sql
-- 查看版本变更日志
SELECT * FROM sys_tenant_version_log WHERE tenant_id = <租户ID> ORDER BY create_time DESC;

-- 查看三维能力（后端接口，经 normalizeEdition 归一化）
-- GET /system/edition/features?tenantId=<租户ID>
-- 返回：{"edition":"ADVANCED","bizCode":"fund_control","accessChannel":"wecom","features":[...],"copy":{...}}
```

### 2.4 配置使用天数

**操作路径**：租户列表 → 选择租户 → 点击"使用天数配置"按钮（6007权限）

**界面说明**：
- 授权类型：试用 / 正式
- 使用天数：数字（如30天、90天、365天）
- 系统自动计算到期日期：`expire_date = NOW() + 天数`
- 勾选"永久有效"：`expire_date = NULL`

**到期检测机制**：
- XXL-JOB定时任务 `tenantExpireCheckJob` 每日00:30执行
- 扫描 `expire_date < NOW()` 的租户
- 状态转为 `EXPIRED`，踢出在线会话
- 到期租户无法登录，所有业务接口返回"租户授权已到期"

**验收检查**：
```sql
-- 查看租户到期时间
SELECT id, company_name, expire_date,
 DATEDIFF(expire_date, NOW()) AS remaining_days
 FROM sys_tenant WHERE status = 'NORMAL';

-- 手动触发到期检测（测试用）
-- 在XXL-JOB管理中心找到tenantExpireCheckJob，点击"执行一次"
```

## 三、租户升级与降级

### 3.1 升级流程（零迁移）

**场景**：基础版租户升级为高级版

**操作步骤**：
1. 管理员登录后台 → 租户管理 → 选择租户 → 版本分配
2. 选择"高级版" → 确认
3. 系统自动完成：
   - 更新 `edition = 'ADVANCED'`（经 normalizeEdition 归一化）
   - 写入版本变更日志（change_type=UPGRADE）
   - 按高级版模板重新授权菜单（**承接下移菜单 2001~2003/3204/3205/3208/3209/3211~3216/3310~3324** + 原生增量 3217~3223）
   - 刷新功能开关（解锁组 A 11 项 + 组 B 9 项 + FEAT_WECOM），max_roles 2→6

**升级后验证**：
```sql
-- 1. 检查版本
SELECT edition FROM sys_tenant WHERE id = <租户ID>;
-- 预期：ADVANCED

-- 2. 检查版本变更日志
SELECT * FROM sys_tenant_version_log WHERE tenant_id = <租户ID>
 ORDER BY create_time DESC;

-- 3. 检查功能开关（后端接口）
-- GET /system/edition/features
-- 预期：features 含组 A 11 项（FEAT_BAD_DEBT/FEAT_LINK_RULE/FEAT_INVOICE_SUPPLEMENT/FEAT_HIDDEN_COST/
--       FEAT_BOSS_DASHBOARD/FEAT_VOUCHER_EXPORT/FEAT_SUBJECT_3LAYER/FEAT_BUDGET_PREPARE/
--       FEAT_EXPENSE_CONTROL/FEAT_RULE_ENGINE_BASE/FEAT_INVOICE_VERIFY）+ 组 B 9 项 + FEAT_WECOM
```

**注意事项**：
- 升级过程**无需执行额外SQL脚本**（M1_03高级版表已在初始化时一次建齐）
- 升级过程**数据零迁移**，历史数据完整保留
- 升级后租户登录即可看到新增菜单和功能入口

### 3.2 降级流程

**场景**：专业版租户降级为基础版

**操作步骤**：
1. 管理员登录后台 → 租户管理 → 选择租户 → 版本分配
2. 选择"基础版" → 确认
3. 系统自动完成：
   - 更新 `edition = 'BASIC'`
   - 写入版本变更日志（change_type=DOWNGRADE）
   - 按基础版模板重新授权菜单（回收高版本菜单）
   - 刷新功能开关（关闭高级/专业版功能）

**降级后验证**：
```sql
-- 1. 检查版本
SELECT edition FROM sys_tenant WHERE id = <租户ID>;
-- 预期：BASIC

-- 2. 检查版本变更日志
SELECT * FROM sys_tenant_version_log WHERE tenant_id = <租户ID>
 ORDER BY create_time DESC;

-- 3. 检查历史数据保留
SELECT COUNT(*) FROM fee_employee_credit WHERE tenant_id = <租户ID>;
-- 预期：>0（信用分数据保留，但功能入口关闭）
```

**降级兼容性**：
- 部门级预算启用后降级的历史公司级预算继续有效
- 多组织启用后降级的存量数据默认挂"总部"组织
- 信用分自启用日起累计，降级不回溯历史

## 五、三维能力模型与平台运营（v1.12 新增）

### 5.1 三维能力模型

**有效功能 = `feature_flag(edition 默认集)` ∩ `biz_bundle(biz_code).feature_flags` ∩ `License.features` ∪/− `sys_tenant.features`**

| 维度 | 载体 | 管理员操作 |
|------|------|-----------|
| 版本（edition） | `feature_flag` 按 edition 读默认开启集 | 租户管理 → 版本分配 |
| 业态包（biz_code） | `biz_bundle` 按业态过滤能力与文案 | 业态包管理 |
| License | 签发时按 `features` 精细增减 | License 管理 |
| 单店覆盖 | `sys_tenant.features` / `tenant_biz_config` | 租户详情 → 能力微调 |

- 计算入口：`LicenseServiceImpl#getTenantActiveFeatures`；接口 `GET /system/edition/features` 返回 `{ edition, bizCode, accessChannel, features, copy }`
- 三维取交集：构造「License 有 + 业态包无」或「业态包有 + 版本无」，功能均不可用（防串第⑥层）
- 版本编码归一化：`normalizeEdition(String)` 将 `pro`/`professional`/`ENTERPRISE` → `PROFESSIONAL`（大小写不敏感），**不写迁移脚本、不改存量数据**

### 5.2 业态包管理（biz_bundle）

**操作路径**：平台运营 → 业态包管理

- 内置三包：`fund_control`（资金管控）/ `boardgame`（桌游）/ `fresh_food`（生鲜）
- 每包声明 `menus` / `copy`（文案）/ `schema_blocks`（页面区块）/ `engine_strategy`（组队引擎策略）/ `feature_flags`
- **新增业态包只需插数据 + 加文案，不动核心表结构（零 DDL、零核心代码改动）**
- 本地缓存 + 变更失效；`IBizBundleService#getBundle(bizCode)`

**验收检查**：
```sql
SELECT biz_code, biz_name, engine_strategy FROM biz_bundle;
-- 预期：3 条内置业态包
```

### 5.3 功能开关管理（feature_flag 34 项）

**操作路径**：平台运营 → 功能开关管理

- 开关从 `EditionFeatureConfig` 静态集合迁到 `feature_flag` 表驱动；`EditionFeatureConfig` 保留为兜底常量（表缺失时启用并告警）
- **34 项分组**：组 A 11 项（下移能力）+ 组 B 9 项（高级版原生）+ 组 C 6 项（通道/多账套/开放 API）+ 组 D 7 项（专业版）+ ★组 E 1 项（小微版专属：`FEAT_PROMOTION_DISTRIBUTION` 推广分销，basic/advanced/pro 三列均 = 0，仅小微版启用）
- `platform_admin` 可启停开关，**不可改版本归属**（以免串版本）；启停即时生效（缓存刷新）

**验收检查**：
```sql
SELECT flag_group, COUNT(*) FROM feature_flag GROUP BY flag_group;  -- 合计 34（组 A 11 + B 9 + C 6 + D 7 + ★E 1）
SELECT feature_code, default_editions FROM feature_flag WHERE feature_code = 'FEAT_BUDGET_PREPARE';
-- 预期：default_editions 含 ADVANCED/PROFESSIONAL，不含 BASIC（已下移）
```

### 5.4 单店覆盖（tenant_biz_config）

`module_overrides` JSON 覆盖模块开关/文案/字段可见性；合并优先级 = 租户覆盖 > 业态包默认；**禁止 fork 业态包**；提供 JSON Schema 校验（非法 JSON 被拦截）。单店改文案/隐藏字段不影响同业态其他租户。

### 5.5 访问通道管理（access_channel）

| 通道 | 版本 | 说明 |
|------|------|------|
| wechat | 基础版+ | 微信小程序 + 公众号（共用小程序，平台 AppID，`?tenant=` 引导态） |
| wecom | 高级版+ | 企业微信自建应用 + OAuth 免登 + 通讯录同步（`FEAT_WECOM`） |
| open_api | 专业版 | 开放平台 RESTful + 签名鉴权 + 配额限流 + Webhook（`FEAT_OPEN_API`） |

- 消息 Provider 抽象（`IMessageProvider`）：微信模板消息 / 公众号客服消息 / 企微应用消息三通道，按 `access_channel` 自动分发，切换通道业务代码零改动
- 主体独立与收款分离：`tenant_payment_config` 支持租户自有商户号（收款直达）或平台代收分账

### 5.6 License 管理

**操作路径**：平台运营 → License 管理

- `sys_license` 关联 `tenant_id`（M3_05）；签发时可指定 `features` 精细增减能力

## 七、防串安全验证

### 7.1 防串六层纵深防御（v1.12 由五层扩展，v1.16 用例扩充至 34 条）

| 层级 | 机制 | 验证方法 |
|------|------|---------|
| ① 版本分配入口 | 仅 admin/platform_admin 可调 assignVersion | 非授权角色调用返回 403 |

| ⑥ 业态与通道隔离 | biz_bundle 三维交集 + access_channel 通道鉴权 | 跨业态/跨通道访问不可见且接口被拒 |

## 八、常见问题与排查

### 8.1 租户创建失败

**现象**：点击"新增租户"后报错"租户创建失败"

**排查步骤**：
1. 检查数据库连接是否正常
2. 查看后台日志：`logs/sys-error.log`
3. 检查 `sys_tenant` 表是否有唯一键冲突（tenant_code重复）
4. 检查 `sys_user` 表用户名是否已存在

**解决方案**：
```sql
-- 查看已存在的租户
SELECT id, company_name, tenant_code FROM sys_tenant;

-- 查看已存在的用户
SELECT user_id, user_name FROM sys_user WHERE user_name = '<用户名>';
```

### 8.2 版本分配后菜单未更新

**现象**：管理员分配高级版后，租户登录看不到高级版菜单

**排查步骤**：
1. 检查租户版本是否更新
2. 检查菜单授权模板是否包含高级版菜单
3. 检查角色是否正确分配菜单
4. 清除浏览器缓存，重新登录

**解决方案**：
```sql
-- 1. 检查租户版本
SELECT edition FROM sys_tenant WHERE id = <租户ID>;
-- 预期：ADVANCED

-- 2. 检查模板
SELECT COUNT(*) FROM sys_edition_menu_template WHERE edition = 'ADVANCED';
-- 预期：约110条

-- 3. 检查版本变更日志
SELECT * FROM sys_tenant_version_log WHERE tenant_id = <租户ID>
 ORDER BY create_time DESC;
```

### 8.3 租户到期后仍可登录

**现象**：租户已到期但仍能登录系统

**排查步骤**：
1. 检查租户到期日期
2. 检查定时任务是否执行
3. 手动触发到期检测任务
4. 检查拦截逻辑是否生效

**解决方案**：
```sql
-- 1. 检查到期日期
SELECT id, company_name, expire_date, status FROM sys_tenant WHERE id = <租户ID>;

-- 2. 手动触发（XXL-JOB管理中心）

-- 3. 手动更新状态（紧急处理）
UPDATE sys_tenant SET status = 'EXPIRED' WHERE id = <租户ID> AND expire_date < NOW();
```

### 8.4 跨租户数据泄露

**现象**：租户A能看到租户B的数据

**排查步骤**：
1. 检查业务表是否包含tenant_id字段
2. 检查TenantLineInnerInterceptor是否生效
3. 检查SQL是否手动拼接了tenant_id条件
4. 查看后台日志确认SQL执行过程

**解决方案**：
```sql
-- 1. 检查表结构
SHOW CREATE TABLE fee_project;
-- 预期：包含tenant_id字段和idx_tenant_id索引

-- 2. 检查拦截器配置
-- 查看 ruoyi-framework/src/main/resources/mybatis-config.xml
-- 预期：plugins中包含TenantLineInnerInterceptor

-- 3. 测试SQL
-- 使用租户A账号登录，执行：
SELECT * FROM fee_project WHERE tenant_id != <租户A的tenant_id>;
-- 预期：返回空（拦截器自动拼接tenant_id条件）
```
