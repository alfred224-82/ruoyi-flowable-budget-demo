## 一、项目概述

### 1.1 产品定位
小微版是面向小型商户（桌游店、旅游团、按摩店等）的轻量级经营管理系统，核心能力包括：
- 活动发布与报名管理
- 座位编排与选座
- 员工排班与打卡
- 推广分销与激励
- 结算分账与经营报表
- H5/小程序双端覆盖

### 1.2 核心约束
1. **全平台一个微信小程序**，appid 不进任何业务判断
2. **手机号为唯一身份锚点**
3. **V1 零支付合规**——全系统无支付接口，仅支持线下收款
4. **角色可见性硬隔离**（`tenant_type_scope`）
5. **三层控制模型**（角色模板天花板 ∩ 页面装修排版）
6. **防爽约/黑名单**（仅 micro_pro）
7. **通用评价与点赞体系**（M17，仅 micro_pro，开关 `FEAT_RATING`）

### 1.3 公网访问地址

|---|---|

| PC / Boss | https://www.xiaozhangben.com.cn/#/ |

## 二、核心业务模型

### 2.1 房间与位置
每个房间可设置"有无位置"两种状态：
- **无位置**：不启用选座，参与者按人数参与（适用于买菜、自由力量区、散客拼场等）
- **有位置**：启用选座功能，Boss 在背景图上配置具体座位布局

房间绑定租户，租户有行业描述，系统根据行业判断是否需要排位置。

### 2.2 选座交互
- **空闲座位**：显示座位号 + 加号标识
- **已占座位**：显示占座人头像 + 小字座位号
- **点击头像**：仅显示该用户姓名
- **活动锁定后**：所有座位变为只读，不可操作
- **不使用颜色区分状态**，用图标和文字表达

### 2.3 图片配置
- **房间背景图**：创建房间时上传（房间级），用于 Boss 配置座位布局
- **活动海报**：创建活动时上传（活动级），用于顾客端活动展示
- **海报支持上传 1~6 张**，最少 1 张，最多 6 张
- **手机端查看海报**时支持左右横滑切换，底部显示当前第几张 / 共几张
- **第一张为封面**，活动列表中展示封面
- **PC / Boss 端**以缩略图排列展示，可点击切换

### 2.4 时间字段
全系统时间统一精确到秒（年-月-日 时:分:秒），手机端、PC 端、Boss 端三端一致。

## 三、账号体系与登录

### 3.1 账号层级
平台只管理到"租户"这一层，不碰租户内部角色。

| 层级 | 角色 | 由谁创建 | 说明 |
|------|------|----------|------|
| 平台层 | 租户 Admin | 平台 Admin | 平台创建租户时一并创建租户 Admin 账号 |
| 租户层 | Boss（老板） | 租户    | 租户 Admin 在内部创建 Boss  账号 |
| 租户层 | 员工（司机/导游/助教） | 租户 Admin 或 Boss | 内部代建并分发凭证 |
| 租户层 | 顾客 | 租户 Admin 或 Boss | 内部代建并分发凭证 |

平台 Admin 只负责创建租户、分配租户号、创建租户 Admin 账号，不负责租户内部的 Boss / 员工 / 顾客账号。

### 3.2 登录流程

**Boss 手机端登录（手动选租户）：**
Boss 在手机端无预置租户信息，首次登录需手动输入平台提供的租户号并确认，系统据此拉取该租户下的门店列表；在门店列表中点选目标门店卡片，进入该门店登录页输入 Boss 凭证完成登录。

**员工 / 顾客手机端登录（扫码带租户）：**
员工与顾客的账号账号由租户 Admin 或 Boss 创建并生成带租户 ID  二维码，扫码后系统自动识别租户及所属门店，直接跳转登录页，无需手动输入租户号。

### 3.3 角色与权限

| 角色 | 能力 |
|------|------|
| 租户 Admin | 全权管理（建 Boss / 员工 / 顾客、配置租户功能开关、管理行业功能开关） |
| Boss | 由租户 Admin 授权，最终版 |

## 二十六、开发规范

### 26.1 身份与角色规范
1. 手机号为唯一身份锚点
2. appid 不参与身份与权限判定
3. 标准角色集全版本共用，**禁止新增新增角色 code**
4. 平台管理员只做角色映射，**禁止**分配 `system:menu:*` 或 `system:role:edit`
5. `sys_menu.client_type` 为菜单端过滤唯一依据

### 26.2 V1 零支付规范
1. 全系统禁止集成支付 SDK
2. 「确认发放」改为「标记已线下发放」
3. 顾客端禁止在线支付入口
4. 资金流全程不在平台过手
5. V2+ 必须采用微信支付服务商模式（**禁止平台统一收款码**）

### 26.3 模块化页面与 XXL-JOB 规范
1. 小程序页面=单一页面壳+区块配置，加角色不加页面只加配置
2. 块组件只增不改
3. XXL-JOB 租户级任务必须 `@TenantJob`，一个 Handler 服务全量租户
4. 平台级任务必须 `TenantHelper.clear()` 或 `@TenantIgnore`

### 26.4 分档与角色硬隔离规范
1. `tenant.version_type` 分档差异只体现在 `role_template` 菜单范围
2. lite→pro 升级=UPDATE+刷新缓存，**禁止 DDL 与数据搬迁**
3. `sys_role.tenant_type_scope` 为角色产品线归属唯一标记，可选角色列表**必须**按 `tenant_type` 数据源层过滤

### 26.5 防爽约与黑名单规范
1. 仅 `micro_pro` 生效
2. 主动取消不计入 `no_show_count`
3. 满 3 次自动拉黑
4. 唯一出口为老板手动移出
5. 移出后 `no_show_count` 保留不清零
6. 按 `tenant_id` 隔离

### 26.6 任务状态标注规范
1. 四态（✅/🟡/🔄/🆕）
2. 按 SQL/BE/PC/MP 四赛道取证
3. 桩实现不计为赛道完成
4. 需线上环境验收的动作不计 ✅
5. 第二章为唯一权威状态源

### 26.7 推广分销与激励规范
1. 仅小微版启用，由 `FEAT_PROMOTION_DISTRIBUTION` 整体开/关
2. 推广码永久有效、一人一码
3. 归因只认最后一次扫码
4. 奖励只给拉新且仅一次
5. 员工现金延续 V1 零支付
6. 首单判定与推广归属两条线独立

### 26.8 通用评价与点赞规范
1. 评价针对用户非角色
2. `scene` 区分场景，一套表管全部
3. 仅 micro_pro 启用
4. 禁止自己评价自己
5. 同一订单不可重复评价
6. 图片走 `imgSecCheck`
7. 综合评分可聚合所有场景
8. 老板可屏蔽但后台保留原始数据

## 二十九、安全合规与平台监管

### 29.1 租户 Admin 合规协议签署
1. 租户 Admin 首次打开系统时，强制弹出合规协议页面，无法跳过
2. 协议内容由平台方提供，涵盖：不涉及违法宣传、不发布违规活动、活动安全责任自负、平台有权停止违规活动和租户
3. 必须勾选"已阅读并同意"并点击确认，否则无法进入系统
4. 签署记录永久留存：签署人、租户号、签署时间、IP、协议版本号
5. 协议版本更新后，仅对新创建租户生效；旧租户已签署的版本维持不变，无需重新签署

### 29.2 顾客端投诉
顾客登录后，在「我的」页面中找到「投诉 / 反馈」入口，提交时须先选择投诉渠道，分两路。

**渠道一：投诉给 Boss（门店内部事务）**
1. 受理范围：活动中涉及"人"的问题——服务态度差、迟到早退、安排不合理、设施损坏、打人骂人、偷东西等，以及消费争议
2. 上述情况平台不 入，由门店 Boss 在「异常处理」模块中接收、处理与回复。涉及违法犯罪的建议用户直接报警
3. 提交方式：选择关联活动（必选）→ 选择「投诉给 B 给 Boss」→ 填写投诉内容（文字）→ 可选上传图片图片（最多 3 张，允许从相册选择）→ 提交
4. 无额外校验门槛，直接提交

**渠道二：投诉给平台 Admin（活动内容的违法违规）**
1. 受理范围：仅限活动在系统中发布 / 挂载的可查证素材，平台 Admin 可直接查看原文核实。包括但不限于：活动海报（图片）、活动宣传音频 / 视频、活动文字描述、规则说明、活动名称、标签、分类、活动页面上挂出的任何宣传素材
2. 提交要求：关联活动（必选）→ 投诉类别（必选）→ 文字描述（必填，最少 20 字）→ 取证照片（至少 1 张，调用摄像头现场拍摄，不允许从相册选择）→ 提交
3. 平台不受理的情况：活动中个人之间的言语冲突、辱骂、打架斗殴、盗窃、人身伤害，以及其他任何需要执法部门介入的事件。此类情况请投诉给 Boss 或直接报警
4. 流向：直达平台 Admin 内部消息中心，由平台介入监管处理

两条渠道共用同一份投诉记录字段：投诉人（匿名可选）、所属租户、关联活动、投诉渠道（Boss / 平台）、投诉内容、取证照片、提交时间。

### 29.3 平台 Admin 监管能力
1. 消息中心：查看所有投诉，支持按时间 / 租户 / 活动筛选
2. 活动详情查看：点击投诉涉及的活动，查看完整信息（海报、时间、参与人员、创建人、创建时间）
3. 操作留痕查询：该租户下所有活动的创建、修改、锁定、解锁、人员编排等操作日志
4. 停止活动：将活动置为「已停止」状态，顾客端不再展示
5. 停止租户：暂停整个租户，所有账号（Boss、员工、顾客）均无法登录

### 29.4 停止租户后的登录与恢复
1. Boss / 其他账号：登录时提示「账号已被暂停，请联系平台管理员」，无其他入口
2. 租户 Admin：登录时提示 license 已暂停，页面仅保留「更新 license」入口，其余功能全部隐藏
3. 租户 Admin 输入平台发放的新 license 码 → 验证通过 → 系统强制跳转至登录页要求重新登录
4. 重新登录时的协议检查：版本不同（协议已更新）→ 强制弹出新协议，必须签署后才能进入系统；版本相同（协议未变）→ 直接登录，无需重签
5. 不存在「拿新 license 跳过签协议」的漏洞，每次重新登录必经协议版本比对

### 29.5 平台 Admin 自身操作的审计
平台 Admin 的停止活动、停止租户、发放新 license 等操作本身也必须留审计日志。

### 29.6 活动留痕要求（强制）
1. 所有租户创建的活动必须留痕，平台 Admin 可查询
2. 留痕内容：活动基本信息、状态变更记录、参与人员列表、关联投诉记录
3. 留痕数据() 数据租户不可删除，仅平台 API 可管理
4. 数据保留策略：活动结束后至少保留，具体时长由平台方定
