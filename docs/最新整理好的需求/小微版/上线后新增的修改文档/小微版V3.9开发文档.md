## 一、M26 房间座位布局与选座（10 项任务，✅）

> **来源**：V3.9 §一.1、§一.2、§一.3、§三.1~§三.5  
> **范围**：房间「有位置/无位置」二态；Boss PC 拖拽定位配置座位；顾客小程序按位置选座；活动锁定后座位只读。  
> **约束**：① 座位坐标以背景图百分比存储（0~1），前端按容器实际尺寸换算像素，保证 PC / 手机 / 平板三端渲染一致；② 预置人员（导游/司机）用 `is_preset=1` 标记，橙色渲染，不参与顾客选座；③ 背景图上传前置校验（格式/大小/尺寸），不合规拒绝并提示原因；④ 复制布局仅限 Boss 角色（`@SaCheckPermission("micro:room:copyLayout")`）；⑤ **计价单位改为下拉框**：`service_item` 的计价单位字段由纯文本改为下拉选择（小时/天/月/年），默认值「小时」；后续费用统计/结算均按此单位计算。典型场景：旅游大巴按「天」计价（按小时不合理），会议室可按「小时」计价，长期包场可按「月/年」计价。

**M26_01 建表要点**（示例，实际脚本按《SQL 落地规范》幂等生成）：

```sql
-- 房间座位布局（一个房间一份，UNIQUE(tenant_id, room_id)）
CREATE TABLE `room_seat_layout` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `tenant_id` BIGINT NOT NULL DEFAULT 1,
  `room_id` BIGINT NOT NULL COMMENT 'FK→service_item.id (category_type=space)',
  `bg_image_url` VARCHAR(500) NOT NULL COMMENT '背景图 OSS URL',
  `bg_image_source` VARCHAR(10) NOT NULL DEFAULT 'UPLOAD' COMMENT 'UPLOAD=Boss 自传 / PRESET=平台默认模板',
  `layout_width` INT NOT NULL DEFAULT 1920,
  `layout_height` INT NOT NULL DEFAULT 1080,
  `template_id` BIGINT DEFAULT NULL COMMENT '若来自模板，记录模板 id（复制后脱钩）',
  -- BaseEntity 审计列（create_by/create_time/update_by/update_time/tenant_id）
  UNIQUE KEY `uk_tenant_room` (`tenant_id`, `room_id`)
```

### 3.4 操作日志切面（示例）

```java
@Aspect
@Component
@RequiredArgsConstructor
public class SeatOperationLogAspect {
    private final IActivitySeatOperationLogService logService;

    @Around("@annotation(seatOp)")
    public Object around(ProceedingJoinPoint pjp, SeatOperation seatOp) throws Throwable {
        Long activityId = extractActivityId(pjp.getArgs());
        String before = snapshot(activityId);
        Object result = pjp.proceed();
        String after = snapshot(activityId);
        logService.record(activityId, seatOp.value(), before, after);
        return result;
    }
}

@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface SeatOperation {
    OperationType value();
}
```

### 5.5 固定支出每月分摊计算口径（T30.6，v1.14 新增）

**背景缺陷**：M20_06 为 `monthly_fixed_cost` 增加 `period_rule_id` 时声明「boss 选择标签后自动带出周期规则，按周期分摊金额」，但聚合层（驾驶舱 / `/micro/cost/monthSum` / 周报月报 profitSummary / 异常中心）仍按**全额**计入生效月——一笔 5 年 50 万的合同在「本月成本构成」直接显示 ¥500,000.00，严重失真盈亏指标。

**分摊公式**：

```
每月分摊成本 = 总额 ÷ 周期总月数
周期总月数换算：YEAR×12 / QUARTER×3 / MONTH×1（精确）；WEEK×7÷30 / DAY÷30（近似，按 30 天/月）
示例：5 年 50 万 → 500000 ÷ (5×12) = 500000 ÷ 60 = 8333.33 /月（HALF_UP 保留 2 位）
```

**覆盖月口径**（支出项计入哪些月份的成本构成）：

| 场景 | 覆盖区间 | 每月计入金额 |
|------|---------|---------|
| 关联周期规则且周期总月数 > 1 | [生效月, 生效月 + ⌈周期总月数⌉ - 1] | 总额 ÷ 周期总月数 |
| 关联周期规则但周期总月数 ≤ 1 / 规则失效 | 仅生效月 | 全额 |
| 无周期规则且 is_recurring=1 | 生效月起每月 | 全额 |
| 无周期规则且 is_recurring=0 | 仅生效月 | 全额 |

**实现要点**：

- BE `MonthlyFixedCostServiceImpl` 新增 `listActiveInMonth(month)` / `countActiveInMonth(month)` 作为**唯一口径点**（内部 `periodTotalMonths()` / `monthlyAmount()` / `coversMonth()` 静态计算）；`sumCurrentMonth()` 委派 `listActiveInMonth` 累加 `monthlyAmount`。
- `MonthlyFixedCostVo` 新增回填字段 `monthlyAmount`（每月分摊成本，无规则时等于 amount）/ `amortizeMonths`（分摊月数，0=不分摊）；`categoryName` 改优先取 `fixed_cost_tag` 标签名（tagCode / id 双键兼容存量），修复构成条直接显示裸标签编码（如「0001」）的问题。
- `BossDashboardServiceImpl.fillCostComposition`（monthFixedCostTotal + costComposition）/ `fillTodos` 异常计数、`ExceptionCenterServiceImpl` 固定支出异常推导、`MicroReportController.profitSummary`、`/micro/cost/monthSum` 全部改经 Service 口径点聚合，禁止各处自行 sum(amount)。
- FE PC 驾驶舱「固定支出」改「固定支出（月分摊）」+ 构成卡片头注「金额 = 总额 ÷ 周期月数（月分摊）」；PC 固定支出列表「金额」列改「总额」+ 新增「每月分摊」列（amortizeMonths>0 时 tooltip 显示总额与分摊月数）+ 表单周期提示改月数口径（`UNIT_MONTHS_MAP`：YEAR×12/QUARTER×3/MONTH×1，与后端一致）；MP bossHome 构成卡 / cost 列表同步标注「月分摊」。

```sql
-- 临时游客账号（30 天有效期，到期自动废弃）
CREATE TABLE IF NOT EXISTS `temp_visitor_account` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `tenant_id` BIGINT NOT NULL DEFAULT 1 COMMENT 'FK→sys_tenant.tenant_id',
  `phone_last4` VARCHAR(4) NOT NULL COMMENT '手机号后 4 位，如 1234',

  `status` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '0=有效 1=已补全 2=已废弃',
  UNIQUE KEY `uk_tenant_phone` (`tenant_id`, `phone_last4`),
  INDEX `idx_expire` (`expire_time`),
  INDEX `idx_status` (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='临时游客账号（T31.3）';

  `user_id` BIGINT PRIMARY KEY COMMENT 'PK=FK→sys_user.user_id',

  `id_card` VARCHAR(18) DEFAULT NULL COMMENT '身份证号（脱敏存储）',
  `birthday` DATE DEFAULT NULL,
  `gender` TINYINT(1) DEFAULT NULL COMMENT '1=男 2=女',

  `is_complete` TINYINT(1) NOT NULL DEFAULT 0 COMMENT '0=未完善 1=已完善',
  INDEX `idx_is_complete` (`is_complete`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='游客信息补全表（T31.3）';
```

4. **幂等性**：同一手机号再次扫码 → BE 查询到已有有效临时账号 → 直接返回 JWT + isNewAccount=false，不重复创建。
5. **账号过期**：30 天后临时账号 expire_time < now() → XXL-JOB 定时任务 `tempVisitorCleanupJob` 自动将 status 改为 DELETED（2），该账号无法再登录（需重新扫码生成新账号）。
6. **Boss 补全信息**：Boss 登录 PC → 「顾客管理」→ 筛选「临时游客」→ 找到「游客8000」→ 点击「补全信息」→ 填写真实姓名「张三」、身份证号「110101199001011234」、生日、性别、地址 → 提交 → `visitor_profile` 插入记录 + `temp_visitor_account.status=1` + `sys_user.nick_name` 改为「张三」。
7. **游客自助完善**：临时游客登录 MP → 「我的」→ 顶部提示条「请完善个人信息」→ 点击 → 填写同 Boss 端字段 → 提交 → 同步更新 `visitor_profile` + `is_complete=1` → 提示条消失。
8. **短信限流**：同一手机号当日第 4 次请求发送验证码 → 后端拒绝 → 前端提示「今日验证码发送次数已达上限（3 次）」。
9. **图片验证码防刷**：连续 5 次输入错误图片验证码 → Redis 记录失败次数 → 第 6 次起要求等待 30 秒后再试（防止机器批量注册）。
10. **二维码参数完整性**：扫描任意活动海报二维码 → 解析 scene → 验证 t（tenant_id）、a（activity_id）、u（visitor）、p（phone_last4）四参数均存在且非空。
11. **游客主动升级**：临时游客登录 MP → 「我的」→ 点击「升级为正式顾客」→ 确认权益说明弹窗 → 填写完整信息（姓名/身份证/生日/性别/地址/微信openid/支付宝user_id）→ 提交 → BE 校验身份证同租户唯一性 → 更新 `sys_user.status=ACTIVE` + `real_name_verified=1` + `temp_visitor_account.status=1` + 插入 `customer_membership`（level=BRONZE, points=0）→ 返回成功 → 页面刷新后升级入口消失。
12. **Boss 批量转正**：Boss PC「顾客管理」→ 筛选「临时游客」→ 勾选 3 个游客 → 点击「批量转正」→ 确认弹窗 → 提交 → BE 遍历校验身份证唯一性 → 批量更新 `sys_user.status=ACTIVE` + 插入会员记录 → 返回「成功 2 个，失败 1 个（身份证重复）」→ 列表自动刷新移除已转正游客。

## 七、开发规范遵循清单

按 memory「全局开发行为规则」强制遵循：

1. **SQL 落地规则**：本文档所有 SQL 脚本写入 `docs/最新整理好的需求/小微版/上线后新增的修改文档/全量sql/`，并登记 `00_执行顺序.sql`；SQL 文件统一 `SET NAMES utf8mb4;` 开头；ALTER 使用 `INFORMATION_SCHEMA` 守卫 + `SQL_SAFE_UPDATES` 包裹；菜单 / role_template 使用先删后插 + `JSON_CONTAINS` 守卫保证幂等。
2. **Java Spring Boot 开发规范**（`docs/最新整理好的需求/Java_Spring_Boot_开发规范.md`）：
   - **异常分层**：Controller 不捕获异常，Service 抛 `ServiceException`（业务）/ `RuntimeException`（系统），GlobalExceptionHandler 统一处理。
   - **结构化日志**：使用 `@Slf4j`，关键操作 `log.info("[SeatAssign] activityId={} seatId={} userId={} result={}", ...)`；异常 `log.error("[SeatAssign] failed", e)`。
   - **防空指针 fail-fast**：所有入参 `Objects.requireNonNull` / `Assert.notNull`；查询结果判空后抛业务异常，不返回 null。
   - **三层联动防线**：Controller 层 `@SaCheckPermission` + Service 层业务规则校验 + Mapper 层租户过滤（`@TenantIgnore` 显式声明例外）。
   - **Vo 类约定**：仅 `@Data` + `Serializable`，禁用 `@AutoMapper`（memory 已固化）。
3. **不执行 Maven**：Java 代码改动完成后不主动 `mvn compile`；用 `GetProblems` 做静态检查；编译验证由用户手工处理。
4. **多租户审计列**：新增表继承 `BaseEntity`（`create_by` / `create_time` / `update_by` / `update_time`）；`tenant_id` 列显式声明，`MetaObjectHandler` 自动填充；`IGNORE_TENANT_TABLES` 白名单不含本文档新增表。
5. **权限串规范**：`@SaCheckPermission` 权限串必须对应 `sys_menu` F 按钮菜单的 `perms`（memory 已固化）；本文档新增权限串全部在 M26_02 / M28_01 SQL 中登记为 F 菜单。
