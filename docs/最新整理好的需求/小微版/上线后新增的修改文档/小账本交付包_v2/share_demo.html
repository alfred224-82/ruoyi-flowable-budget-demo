为什么必须要有这个功能

选座页采用最小信息披露，已占座位只显示「已占」，不显示姓名和头像。 这是对的，但带来一个缺口：顾客无从知道谁坐在哪。

本功能就是这个缺口的唯一补偿——员工生成座位对照表发到活动群， 顾客在群里看这张图就知道自己和同伴坐哪。

两者必须配套：选座页隐藏信息， 分享功能以可控方式释放给群成员。缺了分享功能，隐藏姓名就成了残缺设计—— 顾客既看不到、也问不到。

为什么不用真截图

员工手动截图有两个问题：一是截的是自己手机屏幕，别人的手机型号、状态栏时间、电量都不同， 发出去不专业；二是可能截到别的顾客的完整信息。

用前端生成图，输出的是统一排版的干净长图，且手机号在生成时就已脱敏。

手机号处理：前三后四

页面上存脱敏值，生成图时也只写脱敏值：138****4521。

完整号码只在点击拨号时由前端临时拼进 tel: 链接，不出现在页面 DOM， 也不进入生成图。

两个库怎么选

库体积结论
html-to-image19.4 KB
gzip 6.4 KB		推荐
输出图片JPEG 81 KB
PNG 183 KB		用 JPEG
html2canvas194 KB
gzip 45 KB		兼容更稳

实测两者都能正确渲染圆角、阴影、渐变，以及本项目用的 CSS mask 图标（这是最容易翻车的点，已验证两个库都没问题）。

差 10 倍体积，优先用 html-to-image。代码里已做自动降级： 失败时自动切到 html2canvas，用户无感知。

注意：本地 file:// 打开时 html-to-image 会因读不到 外部 CSS 规则而失败并触发降级；线上同源部署不会出现。

分享的三条路

环境方式
普通浏览器navigator.share 直接调系统分享
微信内分享接口被屏蔽 → 长按图片保存到相册，再发群
都不行复制链接 / 下载图片兜底

微信里没法一键分享，这是微信的限制，不是实现问题。 所以主路径设计成「生成图 → 长按保存 → 自己发群」，比原来员工手动截图还是少一步。

合规要点

· 图上必须写明用途与脱敏说明，就像上面那张图的页脚

· 页面只存脱敏值，完整号码不进 DOM、不进图

· 报名页加告知：「组织者将获取联系方式用于活动通知」

· 生成动作记日志：谁、什么时候、导出了哪个活动
