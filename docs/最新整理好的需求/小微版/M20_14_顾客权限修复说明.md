# M20_14 顾客小程序权限 403 修复说明

## 问题描述

**错误日志**：
```
2026-10-03 19:42:34 [XNIO-1 task-1] ERROR c.r.f.w.e.GlobalExceptionHandler
 - 请求地址'/micro/customer/shop',权限码校验失败'无此权限：micro:customer:shop'
```

**影响范围**：所有通过小程序手机号一键登录的顾客用户，访问 `/micro/customer/shop`、`/micro/customer/submitBook`、`/micro/customer/myBook` 等顾客端接口时均报 403 权限错误。

## 根因分析

### 权限链路断裂（双层缺失）

RuoYi-Plus 权限校验依赖完整链路：
```
sys_user_role → sys_role_menu → sys_menu
   (用户角色)    (角色菜单授权)    (菜单权限定义)
```

**断裂点 1：顾客角色无菜单授权**
- `sys_role` 表中顾客角色 (role_id=9207, role_key='customer', tenant_id=NULL) 存在
- 但 `sys_role_menu` 表中该角色无任何记录 → 角色无菜单权限
- 原因：M15_07 创建了顾客角色，但未执行 `sys_role_menu` 授权脚本

**断裂点 2：顾客用户无角色关联**
- `registerByPhone()` 自动注册顾客用户时，仅创建 `sys_user` 记录
- 未分配 `sys_user_role` 记录 → 用户无任何角色
- 原因：T15.8 设计时假设顾客为"轻量档案"，无需显式角色，但忽略了权限链依赖

### 权限加载机制

```java
// SaPermissionImpl.getPermissionList()
return new ArrayList<>(loginUser.getMenuPermission());

// SysPermissionService.getMenuPermission()
Set<String> perms = menuService.selectMenuPermsByUserId(user.getUserId());

// SysMenuMapper.xml - selectMenuPermsByUserId
select distinct m.perms
from sys_menu m
    left join sys_role_menu rm on m.menu_id = rm.menu_id
    left join sys_user_role sur on rm.role_id = sur.role_id
    left join sys_role r on r.role_id = sur.role_id
where m.status = '0' and r.status = '0' and sur.user_id = #{userId}
```

**关键约束**：
- `selectMenuPermsByUserId` 不过滤 `menu_type`（M/C/F 类型均加载）
- 但要求 `sys_user_role` 和 `sys_role_menu` 完整链接
- 任一环节缺失 → 返回空权限集 → `@SaCheckPermission` 校验失败

## 修复方案

### 1. SQL 修复（M20_14_customer_role_permission_fix.sql）

#### 1.1 顾客角色补录 sys_role_menu
```sql
-- 从 role_template (micro_pro customer) 取 menu_keys → sys_menu.menu_id
INSERT IGNORE INTO `sys_role_menu` (`role_id`, `menu_id`)
SELECT 9207, m.`menu_id`
FROM `role_template` rt
CROSS JOIN JSON_TABLE(rt.`menu_keys`, '$[*]' COLUMNS (`perm` VARCHAR(64) PATH '$')) AS j
JOIN `sys_menu` m ON m.`perms` = j.`perm`
WHERE rt.`version_type` = 'micro_pro' AND rt.`role_code` = 'customer' AND rt.`status` = '0'
  AND m.`status` = '0';

-- 补全 M 类型祖先目录（7400 小程序·顾客）
INSERT IGNORE INTO `sys_role_menu` (`role_id`, `menu_id`)
VALUES (9207, 7400);

-- 补充 micro:activity:browse（lite 档顾客也需要）
INSERT IGNORE INTO `sys_role_menu` (`role_id`, `menu_id`)
SELECT 9207, m.`menu_id`
FROM `sys_menu` m
WHERE m.`perms` = 'micro:activity:browse' AND m.`status` = '0';
```

**授权菜单清单**（micro_pro customer 权限集）：
- micro:customer:shop（浏览店铺）
- micro:customer:book（预约服务）
- micro:customer:selectService（选择服务项目）
- micro:customer:selectTime（选择时间）
- micro:customer:submitBook（提交预约）
- micro:customer:myBook（我的预约）
- micro:customer:cancelBook（取消预约）
- micro:customer:payInfo（查看收款方式）
- micro:activity:browse（活动浏览页）
- M 目录 7400（小程序·顾客）

#### 1.2 存量顾客用户补录 sys_user_role
```sql
-- 为所有小微版租户下无 sys_user_role 的顾客用户补录角色关联
INSERT IGNORE INTO `sys_user_role` (`user_id`, `role_id`)
SELECT u.`user_id`, 9207
FROM `sys_user` u
JOIN `sys_tenant` t ON u.`tenant_id` = t.`id` AND t.`tenant_type` = 'micro'
WHERE u.`status` = '0' AND u.`del_flag` = '0'
  AND NOT EXISTS (
    SELECT 1 FROM `sys_user_role` sur WHERE sur.`user_id` = u.`user_id`
  );
```

### 2. Java 修复（SysLoginService.java）

**修改文件**：`ruoyi-system/src/main/java/com/ruoyi/system/service/SysLoginService.java`

**核心变更**：
```java
/** 顾客全局共享角色 ID（M15_07 创建，tenant_id=NULL） */
private static final long CUSTOMER_ROLE_ID = 9207L;

private final SysRoleMapper roleMapper;
private final SysUserRoleMapper userRoleMapper;

private SysUser registerByPhone(String phonenumber, Long tenantId) {
    // ... 原有用户创建逻辑 ...
    userMapper.insert(user);
    
    // ★v1.71 修复：tenantId 非空时自动分配 customer 角色
    if (ObjectUtil.isNotNull(tenantId)) {
        try {
            Long existCount = userRoleMapper.selectCount(
                Wrappers.<SysUserRole>lambdaQuery()
                    .eq(SysUserRole::getUserId, user.getUserId()));
            if (existCount == null || existCount == 0) {
                SysUserRole userRole = new SysUserRole();
                userRole.setUserId(user.getUserId());
                userRole.setRoleId(CUSTOMER_ROLE_ID);
                userRoleMapper.insert(userRole);
                log.info("[MicroLogin] 自动分配 customer 角色：userId={}, roleId={}",
                    user.getUserId(), CUSTOMER_ROLE_ID);
            }
        } catch (Exception e) {
            log.warn("[MicroLogin] 自动分配 customer 角色失败 userId={}: {}",
                user.getUserId(), e.getMessage());
        }
    }
    return user;
}
```

**设计要点**：
- 仅在 `tenantId` 非空时分配角色（平台级轻量档案无需角色）
- 幂等检查：已存在 `sys_user_role` 记录时跳过
- 异常容错：分配失败不阻断注册主流程

## 技术要点

### 1. 全局共享角色 vs 租户克隆角色
- **全局共享角色** (9206/9207)：`tenant_id=NULL`，所有租户可见，不通过 `clonePresetRoles` 克隆
- **租户克隆角色** (9201~9205)：`tenant_id=租户ID`，开通租户时自动克隆
- **设计决策**：顾客/业务员采用全局共享角色，简化跨租户场景

### 2. IGNORE_TENANT_TABLES 配置
以下表已加入 `MybatisPlusConfig.IGNORE_TENANT_TABLES`，不做租户隔离：
- `sys_user`、`sys_role`、`sys_menu`、`sys_user_role`、`sys_role_menu`
- 隔离靠 `role_id` 雪花唯一性，非 `tenant_id` 过滤

### 3. Sa-Token 权限快照机制
- 登录时一次性加载 `selectMenuPermsByUserId` 到会话缓存（Redis）
- 运行时修改 `sys_role_menu` 不会自动刷新
- **必须重新登录**才能获取新权限

### 4. 菜单类型与权限加载
- `selectMenuPermsByUserId` 不过滤 `menu_type`（M/C/F 均加载）
- `selectMenuTreeByUserId` 仅渲染 M/C 类型（侧边栏菜单树）
- F 类型按钮不渲染但权限生效（用于 `@SaCheckPermission`）
