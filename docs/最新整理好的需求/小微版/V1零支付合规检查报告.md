# V1 零支付合规检查报告

> 版本：v1.0  日期：2026-09-12  
> 依据：《资金管控系统开发任务文档（小微版）》v1.30 T15.23  
> 适用范围：小微版 V1 全部代码（ruoyi-admin / ruoyi-system / ruoyi-app）

---

## 一、合规要求

V1 版本（小微版首版交付）禁止集成任何在线支付 SDK，具体约束：

| 编号 | 约束 | 说明 |
|------|------|------|
| R1 | 禁止引入微信支付 SDK | 不得出现 `com.github.binarywang:wx-java-pay` 等依赖 |
| R2 | 禁止引入支付宝 SDK | 不得出现 `com.alipay.sdk` 等依赖 |
| R3 | 禁止任何在线支付接口 | 后端不得有 `/pay/*`、`/refund/*` 等在线支付 Controller 端点 |
| R4 | 小程序前端不得调用 `wx.requestPayment` | ruoyi-app 不得出现微信支付 JSAPI 调用 |
| R5 | 收款方式仅为「到店付」 | 收款流程为线下现金/扫码，系统仅做记账标记 |
| R6 | 计费套餐标记「已线下发放」 | 奖励发放（现金/提成）采用老板手动标记已线下发放模式 |

## 二、代码实证检查

### 2.1 后端依赖扫描（R1/R2）

**检查方法**：扫描全部 `pom.xml` 文件，搜索支付 SDK 关键字。

```bash
# 扫描命令（可复现）
grep -r "wx-java-pay\|alipay.sdk\|unionpay\|swiftpass" --include="pom.xml" ruoyi-*/
```

**检查结果**：✅ **零命中**。全部 13 个 Maven 模块 pom.xml 均无支付 SDK 依赖。

### 2.2 后端 Controller 扫描（R3）

**检查方法**：扫描全部 Controller 文件，搜索支付相关 URL 映射。

```bash
# 扫描命令（可复现）
grep -rn "@RequestMapping.*pay\|@PostMapping.*pay\|@GetMapping.*pay\|@RequestMapping.*refund" \
  --include="*.java" ruoyi-admin/src/main/java/
```

**检查结果**：✅ **零命中**。无任何 `/pay`、`/refund`、`/settle`（在线结算）端点。

**补充说明**：
- `/micro/booking/receive/{id}`（标记已收款）仅为 `pay_status=RECEIVED` 状态标记 + 写 cash_flow 收入流水，不调用任何支付接口。
- `/micro/promo/reward/markPaid/{id}`（标记现金奖励已线下发放）仅为 `issue_status=PAID_OFFLINE` 状态标记，不调用任何支付/转账接口。

### 2.3 小程序前端扫描（R4）

**检查方法**：扫描 ruoyi-app 全部 `.vue` / `.js` 文件，搜索微信支付 API 调用。

```bash
# 扫描命令（可复现）
grep -rn "requestPayment\|wx\.requestPayment\|wx\.openBusinessView\|payment" \
  --include="*.vue" --include="*.js" ruoyi-app/
```

**检查结果**：✅ **零命中**。小程序前端无任何微信支付 JSAPI 调用。

**补充说明**：
- 小程序预约提交页 `customerBook/submit.vue` 明确展示提示：「★ 本店支持到店付款，本小程序不提供在线支付」。
- 小程序顾客端 `customer/payInfo` 接口返回纯文案提示：「本店支持到店付款：服务完成后请向前台/老板付款，或扫描老板收款码支付。本小程序不提供在线支付。」

### 2.4 收款流程验证（R5）

**当前收款链路**（全部线下）：

```
顾客预约 → 老板确认 → 员工到店服务 → 完成服务 → 老板「标记已收款」→ cash_flow 收入流水
```

- `BookingOrderController.markReceived(id)` → `bookingOrderService.markReceived(id)` → `pay_status=RECEIVED, pay_time=now` → 自动写 cash_flow 收入流水。
- 全程无支付回调、无商户号对接、无资金流转。

### 2.5 奖励发放验证（R6）

**当前奖励发放链路**（全部线下标记）：

```
推广归因 → 触发奖励规则 → 生成奖励记录(issue_status=PENDING) → 老板「标记已线下发放」→ issue_status=PAID_OFFLINE
```

- `MicroPromotionRewardController` 无转账/支付端点。
- `distribution.js` 中 `markPaidOffline(id)` 仅调用 PUT `/micro/promo/reward/markPaid/{id}`，状态标记操作。
- 业务员推广（现金奖励）和顾客推广（优惠券）均采用此模式。
