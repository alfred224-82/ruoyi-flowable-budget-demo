**验收日期**：2026-09-17  
**验收范围**：小微版（MICRO）全模块零支付合规性  
**验收依据**：《资金管控系统开发任务文档（小微版）》T15.23、《V3.7 需求文档》〇、版本边界与核心原则

---

## 一、合规要求

V1 零支付核心原则：
1. **全系统无支付接口**：小微版不调用微信支付、支付宝等任何在线支付 SDK
2. **记账口径**：所有收款/付款均为「标记已线下发放」记账模式
3. **状态简化**：pay_status 仅 PENDING_PAY(待到店付)/RECEIVED(已收款)，无在线支付中间态
4. **文案提示**：收款方式仅为提示文案（到店付/老板收款码），不绑定支付账户

## 二、代码实证扫描

### 2.1 Controller 层合规声明（11 处）

| Controller | 合规声明摘要 |
|------------|-------------|
| `BookingOrderController` | 标记「已收款」仅改状态 + 自动写 cash_flow 收入流水，不调任何支付接口 |
| `MicroCustomerController` | 仅有 micro:customer:payInfo（收款方式提示文案），【无 micro:customer:pay、无在线支付入口、不调支付接口】 |
| `MicroNotifyController` | 通知仅经营提醒，不含任何支付/扣款通知触发 |
| `MicroPackageController` | V1 零支付合规：仅展示/排序，不含任何支付 SDK 调用；v1Notice 提示「实际续费请线下联系平台管理员」 |
| `MicroPromotionRewardController` | 员工现金奖励走「标记已线下发放」记账口径，不调任何支付接口 |
| `MicroReportController` | 所有数据均为记账口径，无任何支付流水 |
| `MicroShopController` | 收款方式说明仅为「到店付/老板收款码」提示文案，不绑定任何支付账户、不含支付密钥字段 |
| `StaffSettlementController` | 全流程无任何支付/转账接口调用；标记已线下发放→改状态 + 记 cash_flow 支出流水 |
| `MicroBizJob` | 仅关单不涉退款（顾客未到店、无收款流水） |

### 2.2 Domain 层合规设计（4 处）

| 实体类 | 合规设计 |
|--------|---------|
| `BookingOrder` | pay_status 仅 PENDING_PAY/RECEIVED，无在线支付态 |
| `PromotionRewardRecord` | issue_status 仅 PENDING/PAID_OFFLINE/ISSUED，无在线支付态 |
| `StaffSettlement` | pay_status 仅 PENDING/PAID_OFFLINE；只记账不打款 |
| `MicroShopConfigBo` | payInfo 仅提示文案，不绑定支付账户；不含支付密钥字段 |

### 2.3 支付 SDK 依赖扫描

**扫描命令**：
```bash
grep -r "alipay\|wechat.*pay\|PaymentService\|pay.*sdk" ruoyi-admin/src/main/java/com/ruoyi/web/controller/micro/
```

**扫描结果**：0 匹配

**结论**：小微版 Controller 层无任何支付 SDK 导入或调用。

### 2.4 企业版支付隔离验证

企业版（biz/fee 模块）存在 `PaymentController`、`FeePaymentController`，用于企业版费用管控，与小微版完全隔离：
- 企业版路径：`/biz/payment/*`、`/fee/payment/*`
- 小微版路径：`/micro/*`（无 payment 端点）

**隔离机制**：版本隔离（`@RequireFeature`）+ 菜单隔离（`tenant_type_scope`）+ 角色隔离（`tenant_type_scope`）

## 三、关键流程合规验证

### 3.1 预约收款流程

```
顾客到店 → 老板确认服务 → 标记「已收款」→ 自动写 cash_flow 收入流水
                                    ↓
                              【不调支付接口】
```

**合规点**：
- `BookingOrderController.markReceived()` 仅改 pay_status + 写 cash_flow
- 无微信支付回调、无支付宝通知

### 3.2 员工结算流程

```
生成结算单 → 老板线下转账 → 标记「已线下发放」→ 改状态 + 记 cash_flow 支出流水
                                    ↓
                              【不调支付接口】
```

**合规点**：
- `StaffSettlementController.markPaidOffline()` 仅改 pay_status + 写 cash_flow
- 无批量打款接口、无银企直连

### 3.3 推广奖励发放流程

```
拉新奖励结算 → 员工现金奖励（issue_status=PENDING）→ 老板标记「已线下发放」→ PAID_OFFLINE
                                    ↓
                              【不调支付接口】
```

**合规点**：
- `PromotionRewardServiceImpl.settleNewCustomerReward()` 写 record（PENDING）
- `MicroPromotionRewardController.markPaidOffline()` 改 issue_status
- 无自动打款、无代付接口

### 3.4 套餐续费流程

```
顾客查看套餐 → 显示价格 + v1Notice「实际续费请线下联系平台管理员」→ 线下续费
                                    ↓
                              【无在线支付入口】
```

**合规点**：
- `MicroPackageController.overview()` 返回 v1Notice 提示
- 无「立即购买」「在线支付」按钮

## 五、合规结论

**验收结果**：✅ **通过**

**结论摘要**：
1. 小微版全模块（Controller/Service/Domain）无任何支付 SDK 导入或调用
2. 所有收款/付款流程均为「标记已线下发放」记账模式
3. 状态枚举设计无在线支付中间态
4. 企业版支付功能与小微版完全隔离（路径 + 版本 + 菜单 + 角色）
5. 11 处 Controller 合规声明 + 4 处 Domain 合规设计 + 12 项检查清单全部通过

**风险提示**：
- V1 零支付模式依赖线下操作，须确保老板/员工培训到位
- 后续版本若引入在线支付，须重新评估合规性并更新本文档
