# 资金管控系统 · 基础版操作手册

**版本**：v2.0（对齐 v1.12「折中下移」口径）
**日期**：2026-09-05
**适用对象**：基础版租户（老板 boss、报销人 employee）
**文档定位**：指导基础版租户从零配置系统、跑通「轻量记账 + 项目资金流 + 全量业态能力」业务流程、使用共用微信小程序

> **v1.12 重大变更提示**：依据《多业态SaaS平台需求规格说明书》4.1「基础版资金管控 = 轻量记账」与 5.4「资金管控为高级版核心能力」，原属基础版的 **11 类资金管控重能力已下移至高级版**（预算编制闭环、费用大类三层科目、财务科目导入、报销大类硬拦截与三级预警、规则引擎、发票验真、烂账、项目关联规则、无发票后补、隐形成本、老板看板、凭证导出）。基础版收敛为「轻量记账 + 项目资金流 + 全量业态能力」，仅 **2 个角色**（boss / employee），审批统一为「极简确认」单级老板审批。相关表结构与历史数据全部保留，基础版仅关闭入口（接口 `@RequireFeature` 拦截 + 授权模板回收），升级高级版后自动解锁，数据零迁移。

### 0.2 基础版不含能力（已下移高级版，入口关闭 + 接口拦截）

| 下移能力 | 开关编码 | 基础版表现 |
|---------|---------|-----------|
| 预算编制闭环 / 预算调整 | `FEAT_BUDGET_PREPARE` | 无「预算编制」菜单，接口返回"当前版本不支持，请升级" |
| 费用大类三层科目 / 财务科目导入 | `FEAT_SUBJECT_3LAYER` | 无「费用大类/预算科目/财务科目」菜单 |
| 报销大类硬拦截 + 三级预警 | `FEAT_EXPENSE_CONTROL` | 报销提交不触发额度校验（短路跳过） |
| 规则引擎（内置） | `FEAT_RULE_ENGINE_BASE` | 报销提交不做科目自动匹配 |
| 发票验真（OCR/查验/金额比对） | `FEAT_INVOICE_VERIFY` | 报销提交不做发票查重与验真 |
| 烂账标记 + 坏账计提 | `FEAT_BAD_DEBT` | 无「烂账管理」菜单（3208） |
| 项目关联规则 | `FEAT_LINK_RULE` | 报销不强制关联项目（3216） |
| 无发票后补通道 | `FEAT_INVOICE_SUPPLEMENT` | 报销无「发票后补」勾选项 |
| 隐形成本（薪资/折旧/利息/分成） | `FEAT_HIDDEN_COST` | 无薪资社保/资产折旧/贷款利率菜单（3204/3205/3211~3214） |
| 老板看板（大类下钻） | `FEAT_BOSS_DASHBOARD` | 首页替换为轻量收支概览（3215 关闭） |
| 凭证导出（7 套模板） | `FEAT_VOUCHER_EXPORT` | 无「凭证导出」菜单（3209） |

### 0.3 角色与审批

- **角色数**：基础版 `max_roles=2`，仅 `boss`（老板）与 `employee`（报销人）两个内置角色。
- **职责合并**：项目资金流中的「财务登记/核验」「项目经理收入确认」等操作，在基础版由 **boss 统一承担**（不开放 finance/manager 独立角色，升级高级版后可拆分 4-6 角色）。
- **审批模式**：全部单据走「极简确认」——报销单/付款单/项目立项/合同变更均由 boss 单级审批，不走 Flowable 多级流程。

## 一、系统初始化（租户首次登录）

### 1.1 前提条件

**管理员已完成**：
- 数据库初始化：执行《基础版/sql/00_执行顺序.sql》全部 29 个脚本（阶段一~八），详见该索引文件
- 后端服务启动（ruoyi-admin、ruoyi-job）
- 前端服务启动（ruoyi-ui）
- 租户已创建并分配版本为基础版（`edition=BASIC`），业态包 `biz_code`（默认 `fund_control`）、访问通道 `access_channel=wechat`
- 租户管理员账号已创建（如 zhangsan/123456）

### 1.2 租户管理员登录

**操作步骤**：
1. 访问 `http://localhost:80`（或生产环境域名 / 共用小程序引导态入口）
2. 输入租户管理员账号密码（如 zhangsan/123456）
3. 登录成功进入后台管理界面

**验收检查**：
- 左侧菜单看到"费用管控"目录，展开后仅见：项目管理、收入确认、合同变更、付款单管理、收款单管理、报销管理（精简）
- 首页为「轻量收支概览」三卡片（本月收入/支出/结余）
- **不应看到**：预算编制、费用大类、财务科目、烂账管理、老板看板、凭证导出、薪资社保、资产折旧等（均已下移高级版）

### 1.3 创建业务用户（2 角色）

**操作路径**：系统管理 → 用户管理 → 新增用户

**创建示例用户**：

| 用户名 | 姓名 | 角色 | 说明 |
|--------|------|------|------|
| boss01 | 王老板 | 老板（boss） | 建项目、审批、收付款登记、收入核验、看轻量概览 |
| employee01 | 孙员工 | 报销人（employee） | 填报销单（仅金额/事由/附件/项目） |

**操作步骤**：
1. 点击"新增用户"按钮
2. 填写用户信息（用户名、姓名、密码、部门）
3. 选择角色（基础版仅可选：老板 / 报销人）
4. 点击"确定"创建

**验收检查**：
```sql
-- 查看用户与角色绑定
SELECT u.user_id, u.user_name, r.role_name, r.role_key
 FROM sys_user u
 JOIN sys_user_role ur ON u.user_id = ur.user_id
 JOIN sys_role r ON ur.role_id = r.role_id
 WHERE u.tenant_id = <租户ID>;
-- 预期：2 个用户分别绑定 boss / employee 角色

-- 基础版角色数上限
SELECT id, company_name, edition, max_roles FROM sys_tenant WHERE id = <租户ID>;
-- 预期：edition='BASIC'，max_roles=2
```

### 1.4 初始化基础数据（轻量）

基础版**无需**创建系统级费用大类、三层预算科目、财务科目（均已下移）。仅需在项目立项时按项目维护「项目级自定义科目」。

#### 1.4.1 项目级自定义科目（fee_project_subject）

**功能说明**：基础版项目预算走**项目级自定义科目**，挂在项目管理页（3201）内，随项目立项一并录入，不依赖系统级 `fee_expense_category` 三层科目，也不需要预算编制向导。

**操作路径**：费用管控 → 项目管理 → 新增项目 → 项目预算分配

**验收检查**：
```sql
-- 查看项目级自定义科目
SELECT project_id, subject_name, budget_amount
 FROM fee_project_subject
 WHERE tenant_id = <租户ID>;
-- 预期：随立项生成，可正常分配与扣减
```

## 二、核心业务流程测试（项目资金流 + 轻量记账）

### 2.1 项目管理流程

**流程**：老板建项目 → 审批通过 → 生成项目级自定义科目 → 项目预算可分配扣减

#### 步骤1：老板创建项目

**操作角色**：老板（boss01 登录）
**操作路径**：费用管控 → 项目管理 → 新增项目

**操作步骤**：
1. 输入项目名称（如"某某客户ERP项目"）
2. 输入客户名称（如"某某科技有限公司"）
3. 输入合同额（如 500000）
4. 输入项目预算（如 300000）
5. 按项目自定义科目分配预算（如 差旅 50000、材料 150000、人工 100000）
6. 添加项目成员（可选）
7. 点击"提交审批"

**验收检查**：
```sql
SELECT id, project_name, client_name, contract_amount, status
 FROM fee_project
 WHERE tenant_id = <租户ID> ORDER BY create_time DESC LIMIT 1;
-- 预期：status='PENDING_APPROVAL'
```

#### 步骤2：老板审批项目

**操作路径**：费用管控 → 项目管理 → 待审批 → 选择项目 → 审批通过

**验收检查**：
```sql
-- 查看项目状态
SELECT status, current_contract_amount FROM fee_project WHERE id = <项目ID>;
-- 预期：status='ACTIVE'，current_contract_amount=500000

-- 查看项目级自定义科目（自动生成）
SELECT subject_name, budget_amount FROM fee_project_subject WHERE project_id = <项目ID>;
-- 预期：按分配生成科目记录

-- 查看项目成员
SELECT user_name, role FROM fee_project_member WHERE project_id = <项目ID>;
```

### 2.2 收入确认三态流程

**流程**：老板创建 → 待核验 → 核验通过/驳回 → 计入项目已核验收入

#### 步骤1：创建收入确认

**操作角色**：老板（boss01 登录）
**操作路径**：费用管控 → 收入确认 → 新增

**操作步骤**：
1. 选择项目
2. 输入确认金额（如 100000）
3. 选择依据类型（合同/发票/其他）
4. 上传依据附件
5. 点击"提交"

**验收检查**：
```sql
SELECT id, project_id, confirmed_amount, verify_status
 FROM fee_income_confirmation
 WHERE tenant_id = <租户ID> ORDER BY create_time DESC LIMIT 1;
-- 预期：verify_status='PENDING'
```

#### 步骤2：核验

**操作路径**：费用管控 → 收入核验 → 选择收入确认 → 核验通过/驳回

**验收检查**：
```sql
SELECT verify_status, verify_by, verify_at, reject_reason
 FROM fee_income_confirmation WHERE id = <收入确认ID>;
-- 预期：verify_status='VERIFIED'

SELECT verified_income FROM fee_project WHERE id = <项目ID>;
-- 预期：verified_income 增加 100000
```

### 2.3 付款单流程

**流程**：老板登记付款单 → 审批 → 扣项目预算 + 记总支出

**操作路径**：费用管控 → 付款单管理 → 新增付款

**操作步骤**：
1. 选择关联项目（必选）
2. 输入收款方（如"某某供应商"）
3. 输入付款金额（如 50000）
4. 选择付款类型（工程/材料/服务/租金/其他）
5. 上传发票/合同附件
6. 点击"提交审批" → 老板审批通过

**验收检查**：
```sql
SELECT status, approved_by FROM fee_payment WHERE id = <付款单ID>;
-- 预期：status='APPROVED'

SELECT total_expense FROM fee_project WHERE id = <项目ID>;
-- 预期：total_expense 增加 50000
```

### 2.4 收款单流程

**流程**：老板创建收款单 → 审核通过 → 联动生成已核验收入确认

**操作路径**：费用管控 → 收款单管理 → 新增收款

**操作步骤**：
1. 选择关联项目（必选）
2. 输入付款方、收款金额（如 200000）、收款类型（项目款/退款/其他）
3. 上传回单附件 → 提交审核 → 审核通过

**验收检查**：
```sql
SELECT status, approved_by FROM fee_receipt WHERE id = <收款单ID>;
-- 预期：status='APPROVED'

-- 联动生成的收入确认（创建即核验）
SELECT project_id, confirmed_amount, verify_status, basis_type, basis_no
 FROM fee_income_confirmation WHERE basis_no = <收款单号>;
-- 预期：verify_status='VERIFIED'，basis_type='RECEIPT'
```

### 2.5 合同变更流程

**流程**：发起变更单 → 老板审批 → 合同额/预算增量叠加（不回溯）→ 待收款确认 → 财务闭环；30/60/90 天逾期升级预警

**操作路径**：费用管控 → 合同变更 → 发起变更

**操作步骤**：
1. 选择项目、变更类型（合同额增加/预算增加/综合）
2. 输入变更原因、合同额变更量（如 +100000）
3. 上传依据附件 → 提交 → 老板审批通过

**验收检查**：
```sql
SELECT change_status, approved_by FROM fee_project_change WHERE id = <变更单ID>;
-- 预期：change_status='CONFIRMED'

SELECT current_contract_amount, change_count FROM fee_project WHERE id = <项目ID>;
-- 预期：current_contract_amount 增加 100000，change_count + 1
```

### 2.6 轻量记账（报销）流程 ★基础版边界

**流程**：报销人填报销单（仅金额/事由/附件/项目）→ 老板极简确认单级审批 → 计入支出

> **关键边界（T5.19）**：基础版报销单**不做**科目匹配、额度拦截、发票验真——相关字段与校验在基础版租户下**短路跳过**。表单不含「费用大类」「发票后补」等下移字段，提交不触发任何预算/发票校验。

#### 步骤1：报销人提交报销单

**操作角色**：报销人（employee01 登录）
**操作路径**：费用管控 → 报销管理 → 新增报销

**操作步骤**：
1. 输入报销金额（如 3000）
2. 输入事由描述（如"北京出差交通费"）
3. 上传附件（发票/凭证图片，仅存档，不验真）
4. 选择关联项目（可选，不做强制关联规则）
5. 点击"提交"

**验收检查**：
```sql
SELECT id, bill_no, amount, status, project_id
 FROM fee_expense_bill
 WHERE tenant_id = <租户ID> ORDER BY create_time DESC LIMIT 1;
-- 预期：status='PENDING'，无 category_name / 无额度预占（不触发大类校验）
```

#### 步骤2：老板极简确认审批

**操作角色**：老板（boss01 登录）
**操作路径**：费用管控 → 报销管理 → 待审批 → 选择报销单 → 通过/驳回

**验收检查**：
```sql
SELECT status, approved_by, approved_at FROM fee_expense_bill WHERE id = <报销单ID>;
-- 预期：status='APPROVED'，approved_by=boss01 的 user_id（单级审批，无财务审核环节）
```

### 2.7 轻量收支概览（首页）

**操作角色**：老板（boss01 登录）
**操作路径**：登录后首页 / 费用管控 → 首页

**概览内容**（替换高级版「老板看板」）：
- **本月收入**：当月已核验收入合计
- **本月支出**：当月已审批报销 + 付款单合计
- **本月结余**：收入 − 支出

**验收检查**：
- 三卡片数据准确，与项目资金流单据一致
- **不含**大类下钻、项目利润拆解、风险预警区、固定成本卡片（这些属高级版老板看板 `FEAT_BOSS_DASHBOARD`）

## 三、全量业态能力（v1.12 基础版标配）

> 依据需求文档 5.1 活动管理、5.2 海报主题、5.3 直播公告与 6「项目即容器」，业态能力为**基础版标配（全版本可用）**，由 M11/M12 交付。

### 3.1 项目容器工作台（M11）

**功能说明**：企业任务与活动报名共用 `project` 容器，业态差异进 `extra_config`。登录后按 `biz_bundle.menus` 渲染工作台分组（资金管控 / 活动运营 / 门店管理）。

**操作路径**：工作台（按业态分组）

**验收检查**：
- `fund_control` 租户只见资金分组；`boardgame` 租户只见活动分组
- `project.type` 三类：activity（活动）/ team_buy（团购）/ general（通用）
- 与 `fee_project` 通过 `project_id` 关联（不合并、不迁移存量）

### 3.2 活动管理（M12 · T12.1）

**操作路径**：活动运营 → 活动管理 → 新增活动

**全流程**：创建 → 发布 → 报名 → 签到 → 结束；活动详情页按 Schema 引擎渲染；报名数据写入 `project_signup`。

**验收检查**：
```sql
SELECT id, tenant_id, type, status FROM project WHERE tenant_id = <租户ID> AND type = 'activity';
SELECT project_id, user_id, status FROM project_signup WHERE project_id = <活动ID>;
-- 预期：活动结束后不可报名；组队/组团按 engine_strategy 分发（桌游拼桌满员成团 / 生鲜团购达量成团）
```

### 3.3 主题与视觉管线（M12 · T12.2~T12.5）

- **4 套主题 Design Token**：暗夜桌游 / 暖光聚会 / 清新日系 / 霓虹赛博，`tenant_theme.preset_key` 选定，切换后全站配色即时变化
- **Logo 管线**：必须透明底 PNG，自动加衬底（圆形/圆角+毛玻璃），输出 80×80px
- **海报管线**：输出 750×400（列表卡）与 750×1000（详情），尺寸容差 ±5%，文件 ≤200KB，上传后调微信 `imgSecCheck` 内容安全审核

**操作路径**：门店管理 → 主题设置 / Logo 上传 / 海报上传

### 3.4 直播公告状态机（M12 · T12.6~T12.8）

**五种状态**：`living`（排第一）/ `pending ≤30分钟`（临近提醒）/ `pending >30分钟`（隐藏）/ `offline ≤10分钟`（可进回放）/ `offline >10分钟`（隐藏）；无直播时接口返回 `has_announcement=false`。视频号用 `navigateToChannelsLive` 跳转，抖音仅引流不跳转。

**验收检查**：公告接口缓存 TTL 5min，P99 < 100ms（命中缓存）。

## 四、共用微信小程序（引导态 + 门店选择）

### 4.1 小程序形态

基础版使用**共用小程序**（平台 AppID），公众号菜单跳转携带 `?tenant=xxx`；高级版起支持客户自有 AppID 的独立小程序（`FEAT_OWN_MINIAPP`）。

### 4.2 引导态门店识别（T8.8，双阶段租户识别）

**三种识别方式**（严格按双阶段实现）：
1. URL 参数 `?tenant=xxx`（公众号菜单跳转携带）
2. 公众号 AppID 反查（`sys_tenant.mp_app_id` → `tenant_id`）
3. 登录后绑定（JWT `tenant_id`，鉴权态唯一权限来源）

> **安全边界**：前两种仅用于「引导态」加载门店公开展示数据，走 `/portal/**` 白名单接口 + 限流，**绝不写入 `TenantContext`**；篡改 `?tenant=` 只能看到别家公开首页，登录后数据仍限本租户。

### 4.3 门店选择/搜索首页（T8.10）

共用小程序首页**不可空白**——提供门店列表（定位就近排序）+ 关键字搜索 + 扫码进入三种入口；未选定门店时展示平台介绍页；定位授权拒绝时降级为城市选择。

### 4.4 多绑定选择门店（T8.9）

同一微信 openid 可能绑定多个租户（员工在多家门店兼职）；登录时若查到多条 `user_tenant_bind` 记录，**必须弹出「选择门店」页由用户显式选定**，再签发携带该 `tenant_id` 的 JWT；**禁止按 openid 自动猜测或默认取第一条**。

### 4.5 老板端 / 报销人端测试

**Tab 分流**（基础版仅 2 角色）：
- **老板端（boss01）**：轻量概览 / 项目 / 审批 / 我的（首页为三卡片收支概览，非大类看板）
- **报销人端（employee01）**：首页待办 / 发起报销 / 我的报销 / 我的（发起报销无「后补通道/项目强制关联」，属高级版按开关渲染）

**验收检查**：
- 老板端「轻量概览」三卡片与 PC 端一致
- 报销人端提交报销不触发科目/额度/发票校验
- 到期/停用租户展示友好提示页而非白屏（T8.7）

## 五、工作流配置（极简确认）

### 5.1 基础版固定审批流程（状态机，不走 Flowable）

- **报销单**：报销人提交 → 老板极简确认（单级）→ 通过
- **付款单**：老板登记 → 老板审批 → 通过
- **收款单**：老板创建 → 审核通过 → 联动收入确认
- **项目立项**：老板提交 → 老板审批 → 通过
- **合同变更**：老板/成员发起 → 老板审批 → 通过

> 基础版审批统一为「极简确认」单级老板审批（T5.19③），不走 Flowable 多级流程。多级审批（`FEAT_FLOW_MULTI_LEVEL`）为高级版+ 能力。

### 5.2 审批人配置

```sql
-- 查看 boss 角色对应的用户（基础版单级审批人）
SELECT u.user_id, u.user_name, r.role_key
 FROM sys_user u
 JOIN sys_user_role ur ON u.user_id = ur.user_id
 JOIN sys_role r ON ur.role_id = r.role_id
 WHERE r.role_key = 'boss' AND u.tenant_id = <租户ID>;
```

## 六、常见问题与排查

### 6.1 看不到预算编制/老板看板/凭证导出等菜单

**现象**：基础版租户登录后找不到预算编制、费用大类、老板看板、凭证导出等菜单。

**说明**：这是 **v1.12 预期行为**，非缺陷。上述 11 类能力已下移高级版，基础版仅关闭入口，表结构与历史数据全部保留。

**解决方案**：如需使用，联系管理员在租户管理执行「版本分配 → ADVANCED」升级，升级后菜单与接口自动解锁，数据零迁移。

### 6.2 报销提交没有科目/额度/发票校验

**现象**：基础版报销单提交时不做科目匹配、不拦截超预算、不验真发票。

**说明**：这是基础版轻量记账边界（T5.19①）的预期行为——相关校验在基础版租户下短路跳过。升级高级版后恢复完整报销管控（`FEAT_EXPENSE_CONTROL` / `FEAT_RULE_ENGINE_BASE` / `FEAT_INVOICE_VERIFY`）。

### 6.3 无法创建 finance / manager 角色

**现象**：基础版用户管理只能选 boss / employee 两个角色。

**说明**：基础版 `max_roles=2`，财务/项目经理职责由 boss 合并承担。升级高级版后 `max_roles=6`，可拆分 4-6 角色并自建角色。

### 6.4 共用小程序首页空白或串租户

**排查步骤**：
1. 检查是否走引导态 `/portal/**` 白名单接口（未登录仅返回公开字段）
2. 检查 `?tenant=` 或 AppID 反查是否被误写入 `TenantContext`（引导态绝不写入）
3. 多绑定 openid 是否弹出「选择门店」页

**解决方案**：
```javascript
// 小程序开发者工具控制台
console.log(wx.getStorageSync('app_user_roles')); // 预期：['boss'] 或 ['employee']
// 检查登录后 JWT tenant_id 是否为选定门店
```
