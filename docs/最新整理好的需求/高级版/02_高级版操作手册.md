# 资金管控系统 · 高级版操作手册

**版本**：v2.0（对齐 v1.12「折中下移」口径）
**日期**：2026-09-05
**适用对象**：高级版租户（老板 / 财务 / 项目经理 / 报销人，4-6 角色）
**文档定位**：指导高级版租户在基础版基础上，测试「承接下移的 11 类资金管控重能力 + 高级版原生增量 + 企业微信访问通道」

> **v1.12 重大变更提示**：高级版 = 基础版全部能力 + **承接下移的 11 类资金管控重能力**（预算编制闭环、费用大类三层科目、财务科目导入、报销大类硬拦截与三级预警、规则引擎、发票验真、烂账、项目关联规则、无发票后补、隐形成本、老板看板、凭证导出）+ 高级版原生增量（部门预算/弹性额度/打卡/信用/规则自定义/利润报表/自定义模板/证据链/关联规则自定义）+ **企业微信访问通道**（`access_channel=wecom`）。角色数 `max_roles=6`，支持拆分 4-6 角色并自建角色。

## 〇、高级版能力全景（v1.12）

### 0.1 能力构成

| 层级 | 内容 | 开关 |
|------|------|------|
| 基础版全部 | 项目资金流 + 轻量记账 + 全量业态能力 + 共用小程序 + 计费合规 | 标配（不设开关） |
| 承接下移（组 A，11 项） | 预算编制/预算调整/费用大类三层科目/财务科目导入/报销管控三级预警/规则引擎/发票验真/无发票后补/项目关联规则/烂账/隐形成本/老板看板/凭证导出 | 组 A 开关 |
| 原生增量（组 B，9 项） | 部门预算/弹性额度/打卡定位/信用体系/规则引擎自定义/项目利润报表/自定义凭证模板/证据链分级/关联规则自定义 | 组 B 开关 |
| 访问通道（组 C） | 企业微信自建应用 + OAuth 免登 + 通讯录同步 | `FEAT_WECOM` |

### 0.2 三维能力模型（v1.12 核心）

**有效功能 = `feature_flag(edition 默认集)` ∩ `biz_bundle(biz_code).feature_flags` ∩ `License.features` ∪/− `sys_tenant.features`**

- **版本维度（edition）**：`FeatureService` 按 `edition=ADVANCED` 读默认开启集（组 A 11 + 组 B 9 + FEAT_WECOM）
- **业态包维度（biz_code）**：`biz_bundle` 按业态过滤（如 `fund_control` 含资金管控，`boardgame` 侧重活动运营）
- **License 维度**：签发 License 时可按 `features` 精细增减
- 接口 `GET /system/edition/features` 返回 `{ edition, bizCode, accessChannel, features, copy }`

> 三维取交集：构造「License 有 + 业态包无」或「业态包有 + 版本无」，功能均不可用（防串第⑥层）。

### 0.3 角色与审批（max_roles=6）

| 角色 | role_key | 职责 |
|------|---------|------|
| 老板 | boss | 定大类预算/确认锁定/审批/看板/烂账标记/定分成比例 |
| 财务 | finance | 编制微调/审核报销/收入核验/收付款/凭证导出/隐形成本配置 |
| 项目经理 | manager | 收入确认/发起变更/盯本人项目利润/本人项目烂账上报 |
| 报销人 | employee | 填报销（选大类+自动匹配+财务兜底）/补票 |

- `platform_admin` 可自建角色（含角色管理菜单 101），总数受 `max_roles=6` 约束
- 审批支持多级流程（`FEAT_FLOW_MULTI_LEVEL`），报销单走「财务审核 → 老板审批」两级

**操作路径**：系统管理 → 租户管理 → 选择租户 → 版本分配

**操作步骤**：
1. 选择"高级版（ADVANCED）"
2. 点击"确定"

   - 更新 `sys_tenant.edition = 'ADVANCED'`（经 `normalizeEdition()` 归一化）

## 二、承接下移的资金管控重能力（组 A 开关）★v1.12 新增

> 以下 11 类能力在 v1.11 及以前属基础版，v1.12 起下移高级版。表结构与历史数据全部保留，接口补 `@RequireFeature`，菜单由 `M2_10`/`M6_03` 从 `*_BASIC` 模板迁至 `*_ADVANCED`/`*_PROFESSIONAL` 模板。基础版租户调用任一接口返回"当前版本不支持此功能，请升级 License"。

### 2.1 费用大类主数据与三层科目（FEAT_SUBJECT_3LAYER）

**三层角色分工**：
1. `admin` 超管维护费用大类主数据（`fee_expense_category`，约 6 个，系统级共享，不按 `tenant_id` 隔离）
2. `platform_admin` 从主数据勾选租户启用大类（租户级 `fee_tenant_category`，绑定 `tenant_id`）
3. `boss` 为已启用大类录入预算金额（**按年月 + 部门维度**；高级版起支持多部门/分公司分别编制）

**预算金额调整下限控制**：某大类已使用比例达 X% 时，调整后新预算不得低于原预算的 X%（防止降额变相绕过已发生超支）。

**操作路径**：费用管控 → 费用大类 / 预算科目 / 拆分比例配置（3310~3315）

**验收检查**：
```sql
SELECT id, category_name, category_code FROM fee_expense_category;  -- 系统级约 6 条
SELECT category_id FROM fee_tenant_category WHERE tenant_id = <租户ID>;  -- 租户勾选
```

### 2.2 财务科目导入（FEAT_SUBJECT_3LAYER）

**功能说明**：将客户自有财务系统（金蝶/用友/畅捷通/速达/管家婆/柠檬云/通用，7 套模板）会计科目导入，自动匹配预算科目建立映射 A（租户级）。

**操作角色**：财务（finance01 登录）
**操作路径**：费用管控 → 财务科目（导入）

**操作步骤**：
1. 点击"导入"，选择来源系统 → "下载模板"填写（科目编码、名称必填）
2. 上传 Excel，系统按名称关键字自动匹配：完全一致→AUTO；互含→映射到重叠最长科目；未匹配→UNMAPPED
3. 对"未映射"科目点击"映射"选择目标预算科目（仅叶子）；不需要的点"忽略"
4. 重复导入同编码自动覆盖（幂等）

**验收检查**：
```sql
SELECT status, match_type, COUNT(*) FROM fee_finance_subject
 WHERE tenant_id = <租户ID> GROUP BY status, match_type;
SELECT subject_code, subject_name, mapped_subject_code FROM fee_finance_subject
 WHERE tenant_id = <租户ID> AND status = 'MAPPED';
```

### 2.3 预算编制闭环（FEAT_BUDGET_PREPARE）

**流程**：老板定大类预算 → 系统按比例拆科目 → 财务微调 → 老板确认 → 锁定快照

#### 步骤1：老板设定大类预算
**操作路径**：费用管控 → 预算编制 → 新增编制（2001/2002）
1. 选择预算期间（如 2026-09）与部门（高级版支持多部门）
2. 输入各大类预算额度 → 保存

#### 步骤2：生成拆分初稿（三级兜底）
**操作路径**：预算编制 → 草稿单 → "科目拆分" → "生成拆分初稿"
1. **历史实绩比例**：近 3 个月已批报销实绩占比（口径：已审批+已提交+超预算待审）
2. **财务预设比例**：无历史时按"拆分比例配置"预设
3. **均分兜底**：按叶子科目数均分，尾差修正到首行
- 仅草稿/已驳回状态可生成；确认后覆盖旧明细

#### 步骤3：财务微调科目
- **硬校验**：明细之和不得突破大类限额；如需调整须回步骤1改大类额度重新拆分

#### 步骤4：老板确认并锁定
- 生成版本快照，状态 LOCKED，不可编辑（调整走新版本）

**验收检查**：
```sql
SELECT period, status, lock_time FROM budget_preparation WHERE id = <编制ID>;
-- 预期：status='LOCKED'，lock_time 不为空
SELECT d.category_name, d.budget_amount, SUM(s.budget_amount)
 FROM budget_detail d JOIN budget_preparation_detail s ON d.id = s.detail_id
 WHERE d.preparation_id = <编制ID> GROUP BY d.category_name, d.budget_amount;
-- 预期：每行大类额度 = 科目明细之和
```

### 2.4 预算调整申请（FEAT_BUDGET_PREPARE）

财务提交调整申请 → 老板审批；老板本人加钱亦走同一流程（自动通过但留记录）；调整不改写已锁定快照，生成新编制版本（ADR-001）。

### 2.5 报销管控与三级预警（FEAT_EXPENSE_CONTROL）

**流程**：报销人填报销单 → 系统校验大类额度 → 财务审核 → 老板审批 → 计入实际

**报销提交瞬间同步校验**：
- **发票验真**（见 2.6）
- **大类额度硬拦截**：剩余不足直接拦截"超出大类预算限额"；已用口径含已审批+已提交+超预算待审（防拆单绕过）
- **三级预警**：已用比例 85%🟡 / 95%🟠 / 100%🔴，触发时消息通知老板与财务
- **科目软提示**：科目超支仅黄色提示不拦截
- **项目预算双扣**：关联项目时同步扣项目预算
- **报销追溯时间线**：提交→审核→审批→扣减→补票各环节留痕（ADR-003/015）

**验收检查**：
```sql
SELECT id, bill_no, category_name, amount, status, project_id FROM fee_expense_bill
 WHERE tenant_id = <租户ID> ORDER BY create_time DESC LIMIT 1;
SELECT category_name, budget_amount, used_amount FROM budget_detail
 WHERE preparation_id = <编制ID> AND category_name = '差旅招待';
```

### 2.6 规则引擎与发票验真（FEAT_RULE_ENGINE_BASE + FEAT_INVOICE_VERIFY）

**科目自动匹配链**（提交期）：发票号精确 → 关键字精确 → 模糊 → 金额区间 → 财务人工兜底；记录匹配依据，财务确认/纠偏反哺规则库（越用越准）。

**发票验真**：发票 OCR 识别 → 查验接口验真 → 发票金额与报销金额比对，不一致拦截标记；同发票号/代码重复报销直接拦截；未接入查验接口时自动降级放行（ADR-006/014）。

**验收检查**：
```sql
SELECT match_trace FROM fee_expense_bill WHERE id = <报销单ID>;
-- 示例：{"match_type":"KEYWORD","keyword":"出租车","rule_id":123,"manual_override":false}
```

### 2.7 无发票后补通道（FEAT_INVOICE_SUPPLEMENT）

勾选后补 + 预计补票日期（默认 7 天）→ 财务审核必填理由 → 老板必批 → 额度预占 → 补票转实扣 → 超时释放 + 异常标记。预占/实扣看板区分展示。

**验收检查**：
```sql
SELECT bill_id, estimated_date, status FROM fee_invoice_supplement WHERE bill_id = <报销单ID>;
-- 预期：estimated_date=提交日+7 天，status='PENDING'
```

### 2.8 项目关联规则（FEAT_LINK_RULE）

内置三层：角色级硬规则（项目经理必填项目）+ 大类级软提示 + 财务兜底补关联；未选项目默认公司级（`project_id=0`）。项目经理报销未关联项目被 400 拦截（菜单 3216）。

### 2.9 烂账标记（FEAT_BAD_DEBT）

**流程**：老板标记烂账 → 项目状态 LOST → 看板风险预警区联动（菜单 3208）
1. 选择项目、烂账类型（失联/质量争议/价格问题/其他）
2. 输入原因、处理方案（坏账/跟进/法律）、计提坏账金额

**验收检查**：
```sql
SELECT id, project_id, type, provision_amount, status FROM fee_bad_debt
 WHERE tenant_id = <租户ID> ORDER BY create_time DESC LIMIT 1;
SELECT status, bad_debt_provision FROM fee_project WHERE id = <项目ID>;
-- 预期：status='LOST'
```

### 2.10 隐形成本（FEAT_HIDDEN_COST）

薪资社保计提（公司级方案 A）+ 资产折旧（含项目分摊）+ 项目分成（老板定比例）+ 利息计提（菜单 3204/3205/3211~3214）。

- **薪资社保**：员工月薪基数 × 社保/公积金比例
- **资产折旧**：月折旧额 =（原值 − 残值）/ 使用年限；残值 = 原值 × 残值率
- **定时计提**（每月 1 号）：`salaryAccrualJob` / `assetDepreciationJob` / `loanInterestJob`

**验收检查**：
```sql
SELECT accrual_month, user_name, total_amount FROM fee_salary_record
 WHERE tenant_id = <租户ID> AND accrual_month = '2026-09';
SELECT accrual_month, asset_id, amount FROM fee_asset_depreciation
 WHERE tenant_id = <租户ID> AND accrual_month = '2026-09';
```

### 2.11 老板看板（FEAT_BOSS_DASHBOARD）

**操作路径**：费用管控 → 老板看板（3215，替换基础版轻量收支概览）

**看板内容**：总览区（实扣/预占/剩余）+ 大类卡片🟢🟡🔴 + 四层下钻 + 项目卡片（合同额/已收/已付/预估利润）+ 风险预警区（烂账/逾期变更）+ 固定成本卡片（薪资/折旧/利息）+ 未归类池。

**验收标准**：老板 3 秒看懂"哪个项目赚钱、哪个在亏、有没有烂账"；大类卡片颜色正确（<85% 绿 / 85~95% 黄 / >95% 红）。

### 2.12 凭证导出（FEAT_VOUCHER_EXPORT）

**操作路径**：费用管控 → 凭证导出（3209）
1. 选月份 → 选模板（内置 7 套：通用/金蝶/用友/畅捷通/速达/管家婆/柠檬云）→ 选范围
2. 每条单据生成 2 行（借+贷），借贷自动平衡：
   - 报销单：借=费用科目，贷=银行存款
   - 付款单：借=成本费用科目，贷=银行存款
   - 收款单：借=银行存款，贷=主营业务收入

**验收检查**：7 套模板均可导出，格式正确，借贷金额平衡。

## 三、高级版原生增量功能（组 B 开关）

### 3.1 打卡定位（FEAT_TIME_CLOCK）

**功能定位**：防假账辅助（威慑非定罪），报销提交时按规则触发定位+拍照（菜单 3219/3220）。

**内置默认规则**（tenant_id=0 模板）：

| 规则编码 | 触发条件 |
|---------|---------|
| TRAVEL_CATEGORY | 大类=差旅/招待 |
| AMOUNT_THRESHOLD | 金额≥500 |
| HISTORY_ABNORMAL | 历史异常≥2 次 |

**测试用例**：
- 差旅招待大类 300 元 → 触发定位+拍照，`trigger_rule='TRAVEL_CATEGORY'`，`evidence_level='medium'`
- 办公费用 600 元 → 金额阈值触发 `AMOUNT_THRESHOLD`
- 办公费用 300 元 → 不触发，直接提交
- 定位精度 >50 米 → `is_suspicious=1`（存疑仅标记不拦截）

**验收检查**：
```sql
SELECT bill_id, trigger_rule, longitude, latitude, accuracy, is_suspicious, evidence_level
 FROM fee_clock_record WHERE tenant_id = <租户ID> ORDER BY create_time DESC LIMIT 1;
```

### 3.2 信用体系（FEAT_CREDIT_SCORE）

**功能定位**：后补通道差异化审批（信用分越高权限越大，菜单 3221/3222）。

**内置规则**：ON_TIME +2（按时补票）/ OVERDUE −5（逾期）/ CONSECUTIVE_BONUS +10（连续 3 次按时）。

**信用等级差异化权限**：
- ≥80 EXCELLENT（优秀）→ 免老板审批，补票期限 14 天
- 50~79 NORMAL（正常）→ 标准流程，7 天期限
- <50 RESTRICTED（受限）→ 禁止无发票报销（前后端双拦截）

**定时计算**：`creditScoreCalcJob` 每周一 02:00 重算（基础版租户跳过）。

**验收检查**：
```sql
SELECT user_id, credit_score, credit_level, on_time_count, overdue_count
 FROM fee_employee_credit WHERE tenant_id = <租户ID>;
```

### 3.3 部门级预算与弹性额度（FEAT_DEPT_BUDGET + FEAT_ELASTIC_QUOTA）

**功能定位**：大类额度支持公司级/部门级双粒度（`department_id`），弹性阈值内超支放行（菜单 3217）。

- **部门级编制**：选部门 + 大类额度，按提交人部门扣额度；支持年月维度分别编制与跨月汇总
- **弹性额度**：如差旅招待 +10%，超支但在阈值内自动标记预警放行；超阈值硬拦截

**验收检查**：
```sql
SELECT department_id, category_name, budget_amount, used_amount FROM budget_detail
 WHERE preparation_id = <编制ID> AND department_id = <部门ID>;
SELECT department_id, dept_budget_deducted FROM fee_expense_bill WHERE id = <报销单ID>;
-- 弹性配置
SELECT category_id, threshold_pct, is_enabled FROM fee_elastic_quota_config WHERE tenant_id = <租户ID>;
```

### 3.4 规则引擎租户级自定义（FEAT_RULE_ENGINE_CUSTOM）

财务维护本租户关键字匹配规则，草稿 → 发布流程 + 影响分析（3003 菜单增强，按钮 3296/3297）。

**操作**：新增规则（名称/大类/关键字/金额区间/预算科目）→ 保存草稿 → 影响分析（写 `fee_mapping_audit_log`）→ 发布（PUBLISHED）。

**验收检查**：
```sql
SELECT rule_name, category_name, keywords, publish_status FROM fee_mapping_rule
 WHERE tenant_id = <租户ID> ORDER BY create_time DESC LIMIT 1;
SELECT action, draft_content, publish_content FROM fee_mapping_audit_log
 WHERE rule_id = <规则ID> ORDER BY create_time DESC;
```

### 3.5 项目利润报表（FEAT_PROFIT_REPORT）

纸面利润 vs 实际利润分离，利润拆解，收支时间线，进度条，按项目/月导出（菜单 3218）。

- **纸面利润** = 合同额 −（已核验+待核验收入）− 支出
- **实际利润** = 已核验收入 − 支出
- **利润拆解** = 已核验收入 − 报销/付款 − 折旧分摊 − 项目分成
- 项目经理数据限本人项目（按 `fee_project_member` 过滤）

### 3.6 自定义凭证模板（FEAT_EXPORT_TEMPLATE_CUSTOM）

在内置 7 套基础上新增/修改模板（列头/分隔符/借贷方向，菜单 3223）。

**验收检查**：
```sql
SELECT template_name, target_system, column_config, delimiter FROM fee_export_template
 WHERE tenant_id = <租户ID> AND is_builtin = 0;
```

### 3.7 证据链分级与批量审核（FEAT_EVIDENCE_CHAIN）

每条报销单存证据等级 `evidence_level`（strong 人脸+发票验真 / medium 打卡+发票 / weak 仅发票），财务批量通过/打回（3004 增强）。

### 3.8 项目关联规则自定义（FEAT_LINK_RULE_CUSTOM）

3216 解锁"大类强制关联"/"项目严格模式"；如差旅招待大类强制关联项目，否则 400 拦截。

**验收检查**：
```sql
SELECT scope, target, rule, is_enabled FROM fee_project_link_rule WHERE tenant_id = <租户ID>;
```

## 四、企业微信访问通道（M13，FEAT_WECOM）★v1.12 新增

> 依据需求文档 4.1「访问通道与版本绑定」：基础版=微信小程序+公众号，高级版=企业微信，专业版=企业微信+开放平台。

### 4.1 企微自建应用配置（T13.2）

**操作角色**：platform_admin / 老板
**操作路径**：系统管理 → 租户管理 → 访问通道配置

**验收检查**：

### 4.2 OAuth 免登

企微工作台点击应用 → `code` → 企微 `userid` → 绑定系统用户 → 免登进入。基础版租户企微入口不可用并提示升级。

### 4.3 通讯录同步

同步企微部门与成员到系统组织架构，幂等、失败可重试（通讯录同步 Job）。

### 4.4 消息 Provider 三通道分发（T13.3）

`IMessageProvider` 抽象，实现微信模板消息 / 公众号客服消息 / 企微应用消息三通道，按 `access_channel` 自动分发。T5.12 三层通知、T3.4 到期提醒、T5.17 三级预警统一改走 Provider；切换通道业务代码零改动，Provider 失败降级不阻塞主流程。

### 4.5 端适配（T13.4）

企微通道隐藏微信专属入口（模板消息、门店选择）；`FEAT_FLOW_MULTI_LEVEL` 多级审批的审批人来源按通道解析（企微通讯录 / 系统组织架构）。

## 七、常见问题与排查

### 7.1 升级后仍看不到下移菜单（预算编制/老板看板等）

**排查**：
1. 确认 `sys_tenant.edition='ADVANCED'`（经 normalizeEdition 归一化）
2. 确认已执行 `M2_10_downshift_menu_templates.sql` 与 `M6_03_downshift_menu_migration.sql`（菜单迁入 *_ADVANCED 模板）
3. 确认版本分配已触发授权模板刷新（`sys_role_menu` 含下移菜单）

```sql
SELECT COUNT(*) FROM sys_role_menu
 WHERE role_id IN (SELECT role_id FROM sys_role WHERE tenant_id = <租户ID>)
   AND menu_id IN (2001,3208,3215,3209);
-- 预期：> 0
```

### 7.2 打卡定位失败

引导用户授权小程序定位权限 + 开启 GPS；仍失败可跳过打卡（不阻断主流程，标记 `evidence_level=weak`）。

### 7.3 信用分未更新

```sql
SELECT edition FROM sys_tenant WHERE id = <租户ID>;  -- 预期 ADVANCED/PROFESSIONAL
SELECT * FROM fee_employee_credit WHERE tenant_id = <租户ID>;  -- 无记录则自动创建初始 100 分
```

### 7.4 部门预算编制后报销未扣部门额度

检查报销人部门归属、部门预算是否锁定、`dept_budget_deducted` 字段：
```sql
SELECT u.dept_id, d.dept_name FROM sys_user u LEFT JOIN sys_dept d ON u.dept_id = d.dept_id
 WHERE u.user_id = <报销人user_id>;
SELECT dept_budget_deducted FROM fee_expense_bill WHERE id = <报销单ID>;  -- 预期 1
```

### 7.5 企微通道无法免登

检查 `access_channel='wecom'`、企微凭据配置正确（密钥解密成功）、`FEAT_WECOM` 开关开启、企微 userid 已绑定系统用户。
