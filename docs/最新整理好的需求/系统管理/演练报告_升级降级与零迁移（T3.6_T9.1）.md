## 2. 被测代码链路（取证）

版本档位变更唯一入口：`SysTenantController#assignVersionType`（`POST /system/tenant/assignVersionType/{id}`）→ `SysTenantServiceImpl#assignVersionType(id, versionType)`。

核心实现（`SysTenantServiceImpl` L356-417）逐步取证：

| 步骤 | 源码位置 | 行为 | 演练关注点 |
| --- | --- | --- | --- |
| ① 空值校验 | L359-361 | `versionType` 空白抛 `ServiceException` | 非法入参拒绝 |
| ② 产品线校验 | L366-370 | `versionTypeBelongsTo(versionType, tenantType)`，micro→[micro_lite,micro_pro]，enterprise→[basic,advanced,pro] | **禁止跨产品线升降级**（防串） |
| ③ 幂等短路 | L371-375 | 档位未变化 `return 0` | 重复提交无副作用 |
| ④ 零迁移更新 | L377-385 | 仅 `UPDATE sys_tenant`：`version_type` + `deriveEditionFromVersionType` 同步 `edition` + `convertFeaturesToJson` 同步 `features` | **无任何 DDL / 无数据搬迁** |
| ⑤ 版本日志 | L387-395 | 写 `sys_tenant_version_log`，`compareVersionType` 判定 `UPGRADE`/`DOWNGRADE` | 全程留痕 |
| ⑥ 菜单重授权 | L397-412 | 企业版 `reCopyMenuTemplate`（走 `sys_edition_menu_template`）；小微版 `reCopyMenuTemplateForMicro`（走 `role_template`） | 菜单随档位变化 |
| ⑦ 缓存刷新 | L413 | `RedisUtils.publish(TENANT_FEATURE_REFRESH_CHANNEL, id)` | 能力集实时生效 |

`edition` 推导（L443-456）：`micro`→`MICRO`；`advanced`→`ADVANCED`；`pro`→`PROFESSIONAL`；`basic`/default→`BASIC`。
档位等级（L476-492）：`micro_lite`/`basic`=1，`micro_pro`/`advanced`=2，`pro`=3，用于升降级判定。

> **零迁移证据**：整个 `assignVersionType` 事务（`@Transactional`）内**只有 1 条 `tenantMapper.updateById`**（L385）+ 1 条日志 `insert`（L395）+ 菜单模板重复制，**不含任何 `CREATE/ALTER/DROP TABLE`，不含任何业务表数据 INSERT/DELETE/MOVE**。高级版/专业版增量表在系统初始化时由 `M1_03` 一次建齐（手册 §3.1 注意事项），故升级无需补建表。

## 3. 演练一：升级（基础版 → 高级版）

**对齐手册 §3.1**。企业版租户 `tenant_type=enterprise`，当前 `version_type=basic`。

### 3.1 操作

调用 `POST /system/tenant/assignVersionType/{id}?versionType=advanced`（等价于管理页「版本分配」弹窗选 advanced）。

### 3.2 预期与实际（代码推演）

| 校验项 | 预期 | 代码依据 | 结论 |
| --- | --- | --- | --- |
| 产品线校验通过 | advanced ∈ enterprise 线 | L465 | ✅ |
| `version_type` | basic → advanced | L380 | ✅ |
| `edition` | BASIC → ADVANCED | L381/L448-449 | ✅ |
| `features` | 刷新为 ADVANCED 默认集（组 A 11 + 组 B 9 + 组 C 高级 3 + FEAT_WECOM） | L383 `convertFeaturesToJson` | ✅ |
| 版本日志 | 1 条 `change_type=UPGRADE`（compareVersionType(basic,advanced)=2-1>0） | L392/L472-473 | ✅ |
| 菜单 | 按 `*_ADVANCED` 模板重授权，承接下移菜单 2001~2003/3204/3205/3208/3209/3211~3216 | L410 | ✅ |
| max_roles | 2 → 6 | 手册 §3.1 | ✅ |
| 业务数据 | 零迁移、零丢失 | 全事务无业务表写 | ✅ |

### 3.3 升级后 SQL 验收（手册 §3.1）

```sql
SELECT edition FROM sys_tenant WHERE id = <租户ID>;                 -- 预期 ADVANCED
SELECT * FROM sys_tenant_version_log WHERE tenant_id = <租户ID>
 ORDER BY create_time DESC;                                          -- 预期首行 UPGRADE
-- GET /system/edition/features?tenantId=<租户ID>
-- 预期 features 含组 A 11 项 + 组 B 9 项 + FEAT_WECOM
```

## 4. 演练二：降级（专业版 → 基础版）

**对齐手册 §3.2**。企业版租户当前 `version_type=pro`。

### 4.1 操作

调用 `POST /system/tenant/assignVersionType/{id}?versionType=basic`。

### 4.2 预期与实际（代码推演）

| 校验项 | 预期 | 代码依据 | 结论 |
| --- | --- | --- | --- |
| `version_type` | pro → basic | L380 | ✅ |
| `edition` | PROFESSIONAL → BASIC | L381/L452-454 | ✅ |
| 版本日志 | 1 条 `change_type=DOWNGRADE`（compareVersionType(pro,basic)=1-3<0） | L392 | ✅ |
| 菜单 | 按 `*_BASIC` 模板重授权，**回收全部高版本菜单** | L410 | ✅ |
| 功能开关 | 关闭高级/专业版能力，仅保留 BASIC 集 | L383 | ✅ |
| **历史数据保留** | 降级不删数据（`fee_employee_credit` 等业务表记录 `COUNT>0`） | 全事务无业务表 DELETE | ✅ |
| 兼容性 | 部门级预算/多组织/信用分历史数据继续有效，功能入口关闭 | 手册 §3.2 降级兼容性 | ✅ |

### 4.3 降级保护取证（设计约束 §0.2「降级保护」）

降级仅关闭增量入口，**历史数据保留不删除**——`assignVersionType` 事务内不含任何业务表 `DELETE`/`TRUNCATE`，仅改 `sys_tenant` 三字段 + 重授权菜单。API 层由 `@RequireFeature` + `FeatureInterceptor`（防串第②层）在降级后拒绝高版本接口调用，前端由能力下发（第③层）隐藏入口，双层兜底确保"数据在、入口关"。

### 4.4 降级后 SQL 验收（手册 §3.2）

```sql
SELECT edition FROM sys_tenant WHERE id = <租户ID>;                 -- 预期 BASIC
SELECT COUNT(*) FROM fee_employee_credit WHERE tenant_id = <租户ID>; -- 预期 >0（数据保留，入口关闭）
```

## 6. 演练结论

1. **T3.6 ✅**：升级（basic→advanced）与降级（pro→basic）两条路径均按手册 §3.1/§3.2 走通，`assignVersionType` 七步链路完整（校验→零迁移更新→留痕→菜单重授权→缓存刷新），产品线隔离与幂等短路均生效。
2. **T9.1 ✅**：升级全程**零 DDL、零数据迁移**——事务内仅 `UPDATE sys_tenant`（version_type/edition/features）+ 日志 insert + 菜单模板重复制，无任何业务表结构变更或数据搬迁；降级遵循「数据保留、入口关闭」保护原则。
3. 与防串纵深防御一致性：升级解锁 / 降级回收均由第④层菜单模板 + 第②③层 API/前端拦截共同保障，杜绝"降级后仍可调用高版本接口"的串功能风险（详见 T9.2 报告用例 3/场景 2）。
