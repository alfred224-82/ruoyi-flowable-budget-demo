## 〇、版本管控硬约束（版本由管理员控制，不可以串）

> "不可以串"含义：① 低版本租户**不能使用**高版本功能（API/前端/菜单三层拦截）；② 版本**只能由管理员（平台管理员 `platform_admin`）分配和调整**，租户侧任何角色无自助变更入口；③ 租户之间数据不串（`tenant_id` 行级隔离）；④ 版本变更全程留痕；⑤ 租户实际可用功能由 **License 授权** 决定（`platform_admin` 导入 License 激活，未导入则降级为基础版）；⑥ **【v1.12 新增】业态之间不串**：`biz_code` 决定业态包，租户只能使用本业态包声明的能力与文案，**跨业态菜单/字段/引擎策略不得泄露**。

| 层 | 机制 | 现状 | 落地任务 |

### 0.2 补充约束

- **兜底原则**：菜单与版本解耦（菜单由角色控制），即使误给低版本租户分配了高版本菜单，② 层 API 拦截仍会拒绝——**②③ 层是防串底线，任何增量功能不得跳过**；
- **到期控制**：使用天数由管理员在租户管理中配置，到期后租户状态转 `EXPIRED`，登录与全部业务接口禁用；
- **留痕**：版本变更必须写入 `sys_tenant_version_log`（INIT/UPGRADE/DOWNGRADE），操作日志全覆盖；
- **降级保护**：降级（DOWNGRADE）时已产生的历史数据保留不删除，仅关闭增量入口；
- **admin 豪免**：`admin` 超管功能开关免检（既有策略），验收用例中不得以 admin 账号验证防串效果，必须用租户内普通角色验证。

### 0.3 三维能力模型（v1.12 新增）

租户最终可用能力由**三个维度取交集**得出，任一维未授权即不可见且不可用：

```
有效功能 = feature_flag(edition 默认开启集)
           ∩ biz_bundle(biz_code).feature_flags
           ∩ License.features
           ∪/− sys_tenant.features
```

| 维度 | 载体 | 新增字段/表 | 落地任务 |
|------|------|------------|----------|
| 业态包 | `sys_tenant.biz_code` → `biz_bundle` | `biz_bundle`（menus/copy/schema_blocks/engine_strategy/feature_flags JSON） | T1.7、T10.2 |
| 版本开关 | `sys_tenant.edition` → `feature_flag` | `feature_flag`（code/biz_code/basic_enabled/advanced_enabled/pro_enabled） | T1.7、T10.3 |
| 访问通道 | `sys_tenant.access_channel` | `access_channel` + `wecom_corp_id`/`wecom_agent_id`/`wecom_secret` | T1.8、T13.2 |
| 单店覆盖 | `tenant_biz_config.module_overrides` | `tenant_biz_config` | T1.7、T10.4 |

### 0.4 双阶段租户识别（v1.12 新增）

| 阶段 | 识别方式 | 可访问数据 | 硬约束 |
|------|---------|-----------|--------|
| **引导态**（登录前） | URL `?tenant=xxx` / 公众号 AppID 反查 / 首页门店选择 | 仅**公开展示态**字段 | 走独立白名单 Controller（`/portal/**`）+ 限流；**绝不**写入 `TenantContext` |
| **鉴权态**（登录后） | JWT payload `tenant_id` → TenantContext → 拦截器拼 SQL | 全部业务数据 | **唯一权限来源** |

## 四、开发与落地规范

1. **建表规范**：所有表必须含 `tenant_id` + 租户索引；高级/专业版表一次建齐；脚本遵循"先删后建/先删后插"幂等规范。
2. **接口规范**：高级/专业版增量接口**必须**标注 `@RequireFeature("FEAT_XXX")`，同时保留 `@SaCheckPermission`。
3. **菜单落库**：`menu_id` 冲突时顺延但 `perms` 不变；三版本授权模板是唯一授权依据。
4. **版本编码**：统一 `BASIC` / `ADVANCED` / `PROFESSIONAL`。存量 `ENTERPRISE` 与 `pro` 通过 `normalizeEdition()` 归一化，**不写迁移脚本、不改存量数据**。
5. **定时任务**：租户级任务执行前校验租户开关；新增任务登记 JobHandler 名与 cron。
6. **留痕**：版本分配/天数变更/租户启停全部写操作日志 + 版本变更日志。
7. **任务状态同步**：需求变更时必须同步更新任务状态标记。
8. **业态包规范**：新增业态 = 插数据 + 补文案 + 加策略子类。**禁止**引擎源码硬编码 `if (bizCode == "...")`。
9. **双阶段租户识别**：引导态走 `/portal/**` 白名单，**绝不写入 `TenantContext`**；鉴权态 `tenant_id` 唯一来源为 JWT。
9.5. **PC 端登录租户ID输入（v2.2 新增）**：PC 登录页新增「租户ID」输入框。`admin` 超管可留空登录（全局唯一用户名，无需租户隔离）；其他所有用户**必须填写 tenant_id** 以区分租户。tenant_id 由平台管理员在创建租户时分配，租户自身不可自行生成或修改。前端 `login.vue` 已加 `tenantId` 字段，Vuex `Login` action 与 `api/login.js` 已支持透传；后端 `LoginBody.tenantId` 已有字段，`SysLoginService.login()` 已有租户归属校验。勾选「记住账号」时 tenant_id 一并记住（Cookie 30 天有效）。
10. **文案与主题**：文案走 `t('key')` 映射；主题走 CSS 变量。
11. **图片与内容安全**：Logo 80×80px；海报 750×400 / 750×1000；UGC 过 `imgSecCheck`/`msgSecCheck`。
12. **小微版身份与角色**：手机号为唯一身份锚点；标准角色集全版本共用；**禁止新增角色 code**。**★admin 与租户管理员(platform_admin)菜单权限完全隔离**：admin 拥有「资金平台管理菜单」(1300)下的租户管理/行业模板/角色模板/版本档位/License 管理；小微版 platform_admin 仅拥有「[租户名称]管理菜单」下的三件套：版本升级（上传 License）+ 角色映射 + 人员管理，两套菜单互不可见。
13. **V1 零支付**：全系统禁止支付 SDK；「标记已线下发放」只改状态不调接口。
14. **模块化页面**：单一页面壳 + 区块配置；**禁止**多套首页；`/page/config` = 配置 ∩ perms。
15. **分档与角色硬隔离**：差异只在菜单范围；`tenant_type_scope` 数据源层过滤。
16. **防爽约与黑名单**：仅 `micro_pro` 生效；主动取消不计分；满 3 次原子拉黑；老板手动移出唯一出口。
17. **任务状态标注规范**：四态（✅/🟡/🔄/🆕）+ 四赛道取证；桩实现不计 ✅；第二章为唯一权威。
18. **推广分销与激励规范**：仅小微版启用；推广码永久一人一码；归因只认最后扫码；奖励仅一次；员工现金走线下发放记账。
19. **通用评价与点赞规范**（v1.24 新增）：评价针对 User 而非角色；一套表管全部场景（通过 `scene` 字段区分）；禁止自己评价自己；图片走 `imgSecCheck`；综合评分可聚合所有场景；数据按 `tenant_id` 隔离；老板可屏蔽但后台保留原始数据；`FEAT_RATING` 仅小微版付费版启用。
