**版本**：v2.0  
**日期**：2026-07-15  
**项目**：基于 RuoYi-Flowable-Plus 框架的预算管控与费用管理系统  
**对应需求文档**：预算编制和费用管控需求.md V1.3

---

## 一、技术架构总览

### 1.1 技术栈选型

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 前端 | Vue 2.x + Element UI + ECharts | SPA 单页应用 |
| 网关 | Nginx 反向代理 | 静态资源 + API 转发 |
| 后端 | Spring Boot 2.5 + MyBatis Plus | RESTful API |
| 工作流 | Flowable 6.x | 预留预算调整审批流程（可选） |
| 权限 | Sa-Token | 认证 + 授权 |
| 数据库 | MySQL 8.0+ | 主数据存储 |
| 缓存 | Redis | 预留预算余额/科目余额热点缓存 |
| 消息 | 系统站内消息（sys_message） | 审批通知 + 预警通知 |

### 1.2 系统架构图

```
前端层（Vue.js SPA + Element UI）
    ↓
网关层（Nginx 反向代理）
    ↓
应用层（Spring Boot + Sa-Token）
    ↓
服务层（MappingRule / CostCenter / PurposeTag / ExpenseBill / ExpenseApproval /
       OverBudgetApproval / ReservedBudget / BudgetAdjustment / BudgetCheck /
       OperationLog / ReportAnalysis）
    ↓
数据层（MySQL + Redis）
```

### 3.2 关键前端交互

| 页面 | 核心功能 |
|------|----------|
| 报销单填写页 | 物资小类树形选择 → 用途标签单选 → 系统自动预览预算归属 → 预算不足时弹出调整申请入口 |
| 报销单审批页 | 部门经理查看报销详情 + 预算校验结果 → 通过/驳回（驳回必填原因） |
| 报销单详情页 | 全字段只读展示 + 底部操作时间线（完整审批轨迹） |
| 超预算审批详情 | 超预算详情 + 三个操作：通过/驳回/调整科目预算 |
| 预算调整申请页 | 显示缺口金额 → 填写调整原因 → 提交至部门领导 |
| 预算调整审批详情 | 申请详情 + 本级预留预算余额 → 同意分摊/驳回/向上级转审 |
| 预留预算总览页 | 总额度/已分摊/剩余额度 + 分摊记录明细列表 |
| 操作日志页 | 按单据号/操作人/操作类型/时间范围组合查询 + 导出 |

### 4.3 超预算审批单表设计 (fee_over_budget_approval)

```sql
CREATE TABLE `fee_over_budget_approval` (
  `id` BIGINT(20) NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `bill_id` BIGINT(20) NOT NULL COMMENT '关联报销单ID',
  `bill_no` VARCHAR(50) DEFAULT NULL COMMENT '关联报销单号',
  `cost_center_code` VARCHAR(50) DEFAULT NULL COMMENT '预算责任中心编码',
  `budget_subject` VARCHAR(50) NOT NULL COMMENT '超预算的预算科目编码',
  `budget_subject_name` VARCHAR(100) DEFAULT NULL COMMENT '预算科目名称',
  `original_budget` DECIMAL(15,2) NOT NULL COMMENT '该科目原预算金额',
  `used_amount` DECIMAL(15,2) NOT NULL COMMENT '该科目已使用金额',
  `request_amount` DECIMAL(15,2) NOT NULL COMMENT '本次申请金额',
  `shortage_amount` DECIMAL(15,2) NOT NULL COMMENT '缺口金额',
  `approval_action` VARCHAR(20) DEFAULT NULL COMMENT '审批动作：APPROVE/REJECT/ADJUST',
  `adjust_from_subject` VARCHAR(50) DEFAULT NULL COMMENT '调出科目编码',
  `adjust_from_subject_name` VARCHAR(100) DEFAULT NULL COMMENT '调出科目名称',
  `adjust_amount` DECIMAL(15,2) DEFAULT NULL COMMENT '调剂金额',
  `approver_id` BIGINT(20) DEFAULT NULL COMMENT '审批人ID',
  `approver_name` VARCHAR(50) DEFAULT NULL COMMENT '审批人姓名',
  `approval_opinion` TEXT COMMENT '审批意见',
  `approval_time` DATETIME DEFAULT NULL COMMENT '审批时间',
  `status` VARCHAR(20) NOT NULL DEFAULT 'PENDING' COMMENT '状态：PENDING/APPROVED/REJECTED',
  `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP,
  `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_bill_id` (`bill_id`),
  KEY `idx_status` (`status`),
  KEY `idx_approver` (`approver_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='超预算审批单表';
```

### 4.6 预留预算表设计 (fee_reserved_budget)

```sql
CREATE TABLE `fee_reserved_budget` (
  `id` BIGINT(20) NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `budget_period` VARCHAR(20) NOT NULL COMMENT '预算期间（如 2026-Q3 / 2026-07）',
  `level_type` VARCHAR(20) NOT NULL COMMENT '层级类型：DEPT/BRANCH/HQ',
  `dept_id` BIGINT(20) DEFAULT NULL COMMENT '部门ID（HQ级别为空）',
  `dept_name` VARCHAR(100) DEFAULT NULL COMMENT '部门名称',
  `total_amount` DECIMAL(15,2) NOT NULL DEFAULT 0.00 COMMENT '预留预算总额度',
  `allocated_amount` DECIMAL(15,2) NOT NULL DEFAULT 0.00 COMMENT '已分摊金额',
  `available_amount` DECIMAL(15,2) GENERATED ALWAYS AS (`total_amount` - `allocated_amount`) STORED COMMENT '剩余可用额度（生成列）',
  `warning_threshold` DECIMAL(5,2) DEFAULT 80.00 COMMENT '预警阈值百分比',
  `creator_id` BIGINT(20) DEFAULT NULL COMMENT '编制人ID',
  `status` VARCHAR(20) NOT NULL DEFAULT 'ACTIVE' COMMENT '状态：ACTIVE/FROZEN/EXPIRED',
  `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP,
  `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  `create_by` VARCHAR(64) DEFAULT '',
  `update_by` VARCHAR(64) DEFAULT '',
  `remark` VARCHAR(500) DEFAULT NULL,
  PRIMARY KEY (`id`),
  KEY `idx_period_level` (`budget_period`, `level_type`),
  KEY `idx_dept_id` (`dept_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='预留预算表';
```

## 五、核心业务逻辑

### 5.1 报销单审批流程（部门经理单级审批）

```
报销人创建报销单（status=DRAFT）
    ↓
报销人提交（status=SUBMITTED / OVER_BUDGET_PENDING）
    ↓
部门经理审批
    ├─ 通过 → status=APPROVED → 预算扣减（若充足）→ 通知报销人 → 写操作日志
    └─ 驳回 → status=REJECTED → 通知报销人（含驳回原因）→ 写操作日志
        ↓
    报销人修改后重新提交 → status=SUBMITTED → 通知部门经理 → 写操作日志
```

**权限规则**：
- 唯一审批人：报销人所属部门的部门经理（dept_leader 角色）
- admin 角色可审批所有部门的报销单
- 其他角色仅可查看，不可执行审批操作

**只读规则**：
- DRAFT / REJECTED 状态：报销人可编辑
- SUBMITTED / APPROVED / OVER_BUDGET_PENDING 状态：全部只读

### 5.2 超预算审批流程

```
报销单提交 → 预算校验不足 → 自动创建超预算审批单
    ↓
上级审批人审批
    ├─ 通过 → 追加科目预算 → 完成扣减 → 通知报销人 → 写操作日志
    ├─ 驳回 → 退回报销人 → 通知报销人 → 写操作日志
    └─ 调整科目预算 → 指定调出科目+金额 → 完成调剂 → 通知报销人 → 写操作日志
```

**科目调剂约束**：
- 仅允许同一预算责任中心内科目间调剂
- 调出科目调剂后剩余 ≥ 原预算 10%（可配置安全比例）
- 单笔调剂金额上限可配置（如不超过该科目预算的 30%）

### 5.3 预留预算逐级审批流程

```
报销人发起申请（status=PENDING, current_level=1）
    ↓
部门领导审批（DEPT_APPROVING）
    ├─ 同意分摊 → 从部门预留预算分摊 → status=APPROVED
    ├─ 驳回 → status=REJECTED
    └─ 向上级转审 → current_level=2, status=BRANCH_APPROVING
        ↓
分公司领导审批（BRANCH_APPROVING）
    ├─ 同意分摊 → 从分公司预留预算分摊 → status=APPROVED
    ├─ 驳回 → status=REJECTED
    └─ 向上级转审 → current_level=3, status=HQ_APPROVING
        ↓
总公司领导审批（HQ_APPROVING）
    ├─ 同意分摊 → 从总公司预留预算分摊 → status=APPROVED
    └─ 驳回 → status=REJECTED（各级预留均不足）
```

### 5.4 分摊操作（事务保证）

```java
@Transactional(rollbackFor = Exception.class)
public void doAllocate(Long applicationId, Long reservedId, BigDecimal amount) {
    // 1. 锁定预留预算行（SELECT FOR UPDATE）
    ReservedBudget reserved = reservedBudgetMapper.selectForUpdate(reservedId);
    
    // 2. 校验预留预算剩余额度
    if (reserved.getAvailableAmount().compareTo(amount) < 0) {
        throw new ServiceException("预留预算剩余额度不足");
    }
    
    // 3. 更新预留预算已分摊金额
    reserved.setAllocatedAmount(reserved.getAllocatedAmount().add(amount));
    reservedBudgetMapper.updateById(reserved);
    
    // 4. 增加目标科目可用余额（更新 budget_preparation_detail）
    budgetDetailMapper.addBudgetBySubject(targetSubject, costCenterCode, amount);
    
    // 5. 写入分摊记录
    ReservedAllocationLog log = buildAllocationLog(reserved, application, amount);
    allocationLogMapper.insert(log);
    
    // 6. 更新申请单状态
    application.setStatus("APPROVED");
    application.setAllocateAmount(amount);
    application.setAllocateFromReservedId(reservedId);
    application.setCompleteTime(new Date());
    applicationMapper.updateById(application);
    
    // 7. 写操作日志
    feeOperationLogService.log(...);
    
    // 8. 发送站内消息通知
    sysMessageService.sendMessage(...);
    
    // 9. 预留预算预警检查（使用比例 > 80%）
    checkReservedWarning(reserved);
}
```

### 5.5 操作日志与消息通知集成

**执行顺序**：业务操作 → 写入操作日志 → 发送系统消息，三步在同一事务中完成。

**操作日志写入规范**：
```java
// 每次业务操作完成后调用
feeOperationLogService.log(
    module,           // EXPENSE / OVER_BUDGET / BUDGET_ADJUST
    operationType,    // SUBMIT / APPROVE / REJECT / RESUBMIT / DELETE / ...
    billId, billNo,
    relatedAppId,
    beforeStatus, afterStatus,
    operationDetail   // JSON: {rejectReason, amount, budgetSubject, ...}
);
```

**消息通知规范**：
- 复用已有 `ISysMessageService` 服务，通过 `sys_message` 表存储站内消息
- 前端导航栏铃铛图标显示未读角标
- 消息类型：APPROVAL_PENDING（待审批）/ APPROVAL_RESULT（审批结果）/ REJECTION（驳回）/ SYSTEM_WARNING（系统预警）

## 八、技术特性

| 特性 | 方案 |
|------|------|
| 事务控制 | 分摊/审批操作使用 @Transactional，预留预算行 SELECT FOR UPDATE 悲观锁 |
| 防重复提交 | @RepeatSubmit 注解 |
| 参数校验 | BO 使用 JSR-303 注解 + AddGroup/EditGroup 分组校验 |
| 日志记录 | @Log 注解记录系统操作日志 + fee_operation_log 记录业务操作日志 |
| 缓存 | 预留预算余额/科目余额 Redis 缓存，分摊/审批后主动失效 |
| 通知 | 复用 ISysMessageService 发送站内通知，与业务操作同事务 |
| 操作日志 | fee_operation_log 仅 INSERT + SELECT，不可 UPDATE/DELETE |
