## 一、验收总览

### 1.1 验收范围

| 模块 | 验收内容 | 优先级 |
|------|---------|--------|
| 映射规则引擎 | 物资小类+用途标签+责任中心→预算科目映射 | P0 |
| 报销单管理 | 填写/提交/预算校验/超预算触发 | P0 |
| 报销单审批 | 部门经理单级审批（通过/驳回）/ 驳回后重新提交 / 只读规则 | P0 |
| 超预算审批 | 通过/驳回/科目调剂 | P0 |
| 操作日志 | 全链路操作日志记录 / 不可篡改 / 时间线展示 | P0 |
| 系统消息通知 | 全节点站内消息通知 / 消息类型 / 及时性 | P0 |
| 预留预算管理 | 三级预留预算 CRUD + 总览 + 预警 | P0 |
| 预算调整申请 | 报销人申请 + 逐级审批 + 分摊 | P0 |
| 责任中心管理 | 部门-责任中心对应关系 | P1 |
| 用途标签管理 | 标签 CRUD + 项目交付特殊逻辑 | P1 |
| 报表分析 | 盈利分析表 + 异常监控表 | P2 |

### 1.2 验收标准总则

- P0 功能：通过率必须 100%
- P1 功能：通过率 ≥ 95%
- P2 功能：通过率 ≥ 90%
- 性能指标：全部达标
- 安全指标：零漏洞

## 七、回归测试清单

### 7.1 核心流程（必测）

- [ ] 报销人填写报销单 → 系统自动匹配预算科目
- [ ] 预算充足 → 正常提交 → 部门经理审批通过 → 预算扣减
- [ ] 部门经理驳回 → 报销人修改 → 重新提交 → 审批通过
- [ ] 预算不足 → 触发超预算审批 → 审批通过 → 追加预算
- [ ] 超预算审批驳回 → 退回报销人
- [ ] 超预算科目调剂 → 调出科目余额减少，调入科目余额增加
- [ ] 预算不足 → 发起预算调整申请
- [ ] 部门领导同意分摊 → 科目余额增加 → 报销人重新提交成功
- [ ] 部门预留不足 → 向分公司转审 → 分公司同意分摊 → 科目余额增加
- [ ] 分公司预留不足 → 向总公司转审 → 总公司同意分摊 → 科目余额增加
- [ ] 三级预留均不足 → 驳回申请

### 7.2 通知与日志（必测）

- [ ] 每个业务节点均发送站内消息通知
- [ ] 每个业务节点均写入操作日志
- [ ] 报销单详情页操作时间线完整展示所有节点
- [ ] 操作日志按单据号/操作人/时间范围查询正确
- [ ] fee_operation_log 表无 UPDATE/DELETE 操作入口

### 7.3 数据一致性（必测）

- [ ] 审批通过后预算余额 = 原余额 - 报销金额
- [ ] 分摊后预留预算 allocated_amount + available_amount = total_amount
- [ ] 分摊后科目可用余额 = 原余额 + 分摊金额
- [ ] 调剂后调出科目余额 = 原余额 - 调剂金额
- [ ] 调剂后调入科目余额 = 原余额 + 调剂金额
- [ ] 分摊记录流水完整可追溯
- [ ] 申请单状态与审批操作一一对应

## 八、Bug 分级标准

| 等级 | 定义 | 修复时限 | 示例 |
|------|------|---------|------|
| P0-致命 | 系统崩溃/数据丢失 | 4小时 | 分摊后余额不一致、预留预算扣减错误、操作日志丢失 |

- P1 Bug：0 个
- P2 Bug：≤ 3 个（有修复计划）
- P3 Bug：≤ 10 个
