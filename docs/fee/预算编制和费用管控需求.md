## 2. 业务术语与核心逻辑

### 2.1 核心概念
*   **物资小类**：对报销物品的标准化分类（如：电子设备、办公耗材、差旅服务）。员工必须选择。
*   **用途标签**：描述花钱的业务目的（如：日常运营、研发投入）。员工必须勾选。
*   **会计6大科目**：资产类、负债类、共同类、所有者权益类、损益类、成本类。

### 2.2 映射逻辑（核心算法）
系统不再通过“部门+摘要”判断，而是通过以下公式自动计算预算科目：

> **预算科目 = 物资小类 + 用途标签 + 部门**

**示例：**
员工（研发部-中台组）报销笔记本电脑。
1.  **物资小类**：电子设备
2.  **用途标签**：🔬 研发投入
3.  **部门**：研发部
4.  **系统命中规则**：电子设备 + 研发投入 + 研发部 $\rightarrow$ **研发费用-设备购置**

## 3. 系统功能需求

### 3.1 基础档案配置模块

#### 3.1.1 用途标签管理
*   **功能描述**：定义业务用途，作为映射的核心维度。
*   **预设标签**：
    *   `日常运营`（对应管理费用/销售费用）
    *   `研发投入`（对应研发费用）
    *   `项目交付`（需关联项目编号）
    *   `生产制造`（对应制造费用）
    *   `市场活动`（对应销售费用）
*   **特殊逻辑**：若选择“项目交付”，则强制校验“项目编号”字段必填。

#### 3.1.2 映射规则引擎（核心表）
*   **功能描述**：维护“物资小类+用途标签 $\rightarrow$ 预算科目 $\rightarrow$ 会计大类”的转换规则。
*   **字段设计**：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| 规则ID | 文本 | 唯一标识 |
| 物资小类 | 下拉 | 如：电子设备 |
| 用途标签 | 下拉 | 如：研发投入 |
| 目标预算科目 | 下拉 | 如：研发费用-设备购置 |
| 归属会计大类 | 下拉 | **损益类**（自动带出，用于顶层报表） |
| 是否固定资产 | 布尔 | 是（影响后续折旧逻辑） |
| 状态 | 枚举 | 启用/停用 |

### 3.2 报销业务模块（前端交互）

#### 3.2.1 报销单填写优化
*   **改造点1**：移除“自由文本摘要”作为判断依据的功能，改为结构化录入。
*   **改造点2**：新增必填项**【用途标签】**（单选按钮组，样式清晰）。
*   **改造点3**：**物资小类**改为树形下拉选择（层级：大类 $\rightarrow$ 小类）。
*   **改造点4**：新增必填项**【报销年月】**（月份选择器，格式 YYYY-MM），对应预算编制期间。系统根据报销年月查询对应月份的预算可用余额。
*   **交互逻辑**：
    1.  员工选择物资小类（如：电子设备）。
    2.  员工选择用途标签（如：日常运营）。
    3.  员工选择报销年月（默认当前月，如：2026-07）。
    4.  系统自动显示预览：“预计归属预算：管理费用-办公设备购置”，可用余额按所选报销年月查询。
    5.  若选择“项目交付”，弹出“项目编号”搜索框（数据源来自立项系统）。

#### 3.2.2 预算实时校验与超预算审批
*   **校验逻辑**：保存单据时，系统根据上述映射规则算出具体的预算科目，调用预算系统接口，校验该员工所属**部门**下的该科目余额。**预算校验使用报销人填写的“报销年月”作为预算期间**，而非系统当前日期。
*   **可用余额计算公式**：

> **可用余额 = 预算编制金额（`budget_preparation_detail.budget_amount`） − 已审批通过的报销金额（`fee_expense_bill WHERE status='APPROVED'`）**

*   **余额扣减时机**：报销单仅在经理审批通过（`status='APPROVED'`）时才扣减余额。提交（`SUBMITTED`）、超预算待审（`OVER_BUDGET_PENDING`）、驳回（`REJECTED`）状态均不扣减余额。
*   **预算调整影响**：预算调整审批通过后，直接调用 `setBudgetAmount` 更新 `budget_preparation_detail.budget_amount` 为目标金额，后续所有余额查询均以该字段为权威数据源，不再关联调整表。
*   **校验结果处理**：

| 场景 | 系统行为 | 说明 |
|------|----------|------|
| 预算充足 | 正常提交，自动扣减预算 | 无需额外审批 |
| 预算不足（超预算） | 触发**超预算审批流程** | 单据提交至上级审批人 |
| 预算科目无预算 | 阻断提交，提示错误 | 该科目尚未编制预算，需先联系财务编制 |

*   **超预算提示**："研发费用-设备购置预算不足，当前预算余额 ¥5,000.00，本次申请 ¥8,000.00，缺口 ¥3,000.00。单据将提交至上级审批人进行审批。"

### 3.3 报销单审批流程模块

#### 3.3.1 审批流程概述

报销单提交后进入审批流程，采用**单级审批**模式，仅由**报销人所属部门的部门经理**进行审批。部门经理可以选择**通过**或**驳回**，审批完成后报销单状态相应更新。

```
报销人填写并提交报销单
        │
        ▼
┌─────────────────────┐
│  部门经理审批         │
│  操作：通过 / 驳回    │
└──────┬──────────────┘
       │
   ┌───┴───┐
   │ 通过   │ 驳回
   ▼       ▼
 状态→    状态→
 APPROVED  REJECTED
           │
           ▼
     报销人修改后
     重新提交
```

#### 3.3.2 报销单状态机

| 状态 | 编码 | 说明 | 允许的操作 |
|------|------|------|------------|
| **草稿** | DRAFT | 报销人已创建但尚未提交 | 编辑、提交、删除 |
| **已提交** | SUBMITTED | 报销人已提交，等待部门经理审批 | 查看、删除 |
| **已通过** | APPROVED | 部门经理审批通过 | 查看（只读） |
| **已驳回** | REJECTED | 部门经理驳回 | 编辑、重新提交、删除 |
| **超预算待审批** | OVER_BUDGET_PENDING | 预算不足，进入超预算审批流程 | 查看、删除 |

> **❗ 删除规则**：未审核通过的报销单（DRAFT、SUBMITTED、REJECTED、OVER_BUDGET_PENDING）均可删除，仅已审核通过（APPROVED）的报销单不可删除。

#### 3.3.3 审批权限规则

*   **唯一审批人**：只有报销人**所属部门的部门经理**（`deptManager` 角色）可以执行审批操作（通过/驳回）。
*   **其他角色限制**：非部门经理角色（包括分公司本部 `branch`、总公司本部 `headquarters`、财务人员等）**不可**对该报销单执行通过或驳回操作，仅可查看。
*   **管理员例外**：`admin` 角色可审批所有部门的报销单。

> **⚠️ 角色标识规范**：系统角色标识严格使用 `deptManager`（部门经理）、`branch`（分公司本部）、`headquarters`（总公司本部）、`admin`（管理员），禁止使用 `dept_leader`、`branch_leader`、`hq_leader` 等过时别名。

#### 3.3.4 部门经理审批操作

| 操作 | 说明 | 后续处理 |
|------|------|----------|
| **通过** | 部门经理同意该报销单 | 报销单状态变为 APPROVED，预算自动扣减（若预算充足），发送系统消息通知报销人，写入操作日志 |
| **驳回** | 部门经理拒绝该报销单 | 报销单状态变为 REJECTED，**必须填写驳回原因**，发送系统消息通知报销人修改后重新提交，写入操作日志 |

*   **审批人操作界面**：
    1.  展示报销单详情：报销人、部门、物资小类、用途标签、金额、预算科目、预算余额。
    2.  展示预算校验结果：是否超预算、缺口金额。
    3.  操作按钮：【通过】【驳回】。
    4.  驳回时弹出原因输入框（**必填**，5-500字符）。
    5.  审批意见（选填）。

#### 3.3.5 驳回后重新提交

*   报销人收到驳回通知后，可进入报销单编辑页面进行修改。
*   可修改的内容包括：报销金额、物资小类、用途标签、项目编号等。
*   修改完成后重新提交，报销单状态从 REJECTED 回到 SUBMITTED，重新进入部门经理审批队列。
*   驳回原因在报销单详情页展示，供报销人参考修改。
*   **通知要求**：重新提交时，系统自动发送消息通知部门经理"报销单已重新提交，请审批"，并记录操作日志。

#### 3.3.6 报销单查看模式

*   **查看入口**：报销单详情页面支持通过 URL 参数 `view=1` 进入查看模式，所有表单字段（物资小类、用途标签、金额、备注等）均为只读，仅显示【取消】按钮返回。
*   **权限**：后端 `getInfo` 接口已移除权限校验，所有已登录用户均可查看任意报销单详情。
*   **标题**：查看模式下标题动态显示为"查看报销单"。
*   **预算归属预览**：查看模式下仍展示预算归属预览信息（预算科目、可用余额）。

#### 3.3.7 报销单只读规则

*   **查看模式**：除 DRAFT 和 REJECTED 状态外，所有其他状态（SUBMITTED、APPROVED、OVER_BUDGET_PENDING）的报销单均为**全部只读**。
*   **只读范围**：所有字段不可编辑，包括物资小类、用途标签、金额、项目编号、备注等。
*   **操作按钮控制**：

| 状态 | 报销人可见操作 | 部门经理可见操作 | 其他角色可见操作 |
|------|--------------|----------------|----------------|
| DRAFT | 编辑、提交、删除 | 查看、删除 | 查看、删除 |
| SUBMITTED | 查看、删除 | 通过、驳回、删除 | 查看、删除 |
| APPROVED | 查看（只读） | 查看（只读） | 查看（只读） |
| REJECTED | 编辑、重新提交、删除 | 查看、删除 | 查看、删除 |
| OVER_BUDGET_PENDING | 查看、删除 | 查看、删除 | 查看、删除 |

### 3.4 超预算审批模块

#### 3.4.1 超预算审批流程
*   **触发条件**：报销单据经预算实时校验后，对应预算科目的可用余额不足以覆盖本次报销金额。
*   **审批人确定规则**：
    *   默认审批人为**报销人所属部门的上级部门负责人**。
    *   若报销金额超过部门级审批权限（阈值可配置），自动升级至**财务总监**审批。
    *   支持配置多级审批链（如：部门经理 → 财务总监 → 总经理），按超预算比例或金额阶梯触发。
*   **审批动作**：

| 审批动作 | 说明 | 后续处理 |
|----------|------|----------|
| **通过** | 审批人同意该笔超预算支出 | 系统自动调整该科目预算额度（追加预算），完成扣减，发送消息通知报销人，写入操作日志 |
| **驳回** | 审批人拒绝该笔超预算支出 | 单据退回至报销人，附驳回原因，发送消息通知报销人，写入操作日志 |
| **调整科目预算** | 审批人认为合理，但需要从其他科目调剂预算 | 审批人指定**调出科目**和**调出金额**，系统自动完成科目间预算调剂后通过，发送消息通知报销人，写入操作日志 |

*   **审批人操作界面**：
    1.  展示超预算详情：部门、预算科目、原预算金额、已使用金额、本次申请金额、缺口金额。
    2.  展示报销单明细及附件。
    3.  操作按钮：【通过】【驳回】【调整科目预算】。
    4.  选择"调整科目预算"时，弹出科目调剂面板：
        *   下拉选择**调出科目**（仅显示该部门下有可用余额的科目）。
        *   输入**调出金额**（不得超出调出科目的可用余额）。
        *   系统实时校验：调出金额 ≥ 缺口金额，且不超过调出科目余额。
    5.  审批意见（必填）。

#### 3.4.2 预算科目调剂规则
*   **同部门调剂**：仅允许在同一部门内的科目之间进行调剂。
*   **调剂记录**：每次调剂系统自动记录调剂流水，包含：调出科目、调入科目、调剂金额、操作人、操作时间、关联单据号。
*   **调剂约束**：
    *   调出科目调剂后的剩余金额不得低于该科目当月预算的 **10%**（可配置安全比例），防止连锁超预算。
    *   单笔调剂金额上限可配置（如不超过该科目预算的 30%），超过则需更高级别审批。

#### 3.4.3 超预算审批记录与追溯
*   **审批记录**：所有超预算审批单据独立存档，支持按部门、预算科目、期间、审批状态查询。
*   **审计追溯**：审批流程中的每一步操作（提交、通过、驳回、调剂）均记录操作日志，不可篡改。
*   **统计看板**：
    *   超预算审批通过率 / 驳回率。
    *   各部门超预算频次排名。
    *   科目调剂频次与金额汇总。

### 3.5 报表分析模块

#### 3.5.1 组织机构盈利分析表
*   **维度**：组织机构（树形展开）、期间。
*   **指标**：
    *   预算金额（按预算科目汇总）
    *   实际金额（按会计凭证汇总）
    *   执行差异
*   **展示特色**：支持按**“会计6大科目”**进行聚合切换。
    *   视图A：展示明细预算科目（如差旅费、办公费）。
    *   视图B：展示宏观分类（如损益类合计、资产类合计）。

#### 3.5.2 预算归属异常监控表
*   **目的**：监控边界不清的业务。
*   **逻辑**：列出所有被归入“待分摊池”或触发“人工二次确认”的单据。
*   **功能**：支持财务在此处批量调整预算归属，并生成调整凭证。

## 4. 特殊业务场景处理（边界定义）

### 4.1 场景一：边界模糊部门（如中台部、共享中心）
*   **策略**：设立虚拟的**【待分摊部门】**。
*   **流程**：
    1.  中台部发生的费用，默认进入"待分摊部门"的"共用-办公费"等科目。
    2.  月末，财务根据预设规则（如按各部门人数比例、工时占比），运行"自动分摊任务"。
    3.  系统自动生成会计凭证：借（各部门费用），贷（待分摊部门费用）。

### 4.2 场景二：报销单部门经理审批
*   **背景**：销售部李四提交了一笔 ¥3,500 的差旅报销单，预算充足。
*   **流程**：
    1.  李四填写报销单，选择物资小类"差旅服务"、用途标签"市场活动"，系统自动匹配预算科目"销售费用-差旅费"。
    2.  系统校验预算余额充足，李四点击提交，报销单状态变为 SUBMITTED。
    3.  销售部部门经理收到待审批通知，查看报销单详情。
    4.  部门经理判断：
        *   认为合理 → 点击【通过】，报销单状态变为 APPROVED，预算自动扣减 ¥3,500。
        *   认为不合理 → 点击【驳回】，填写原因"差旅费用超标，请降低住宿标准"，报销单状态变为 REJECTED。
    5.  李四收到驳回通知，进入报销单编辑页面修改金额后重新提交。
*   **只读规则**：报销单状态为 SUBMITTED/APPROVED 时，李四查看报销单所有字段均为只读，不可修改。只有 DRAFT 和 REJECTED 状态才可以编辑。

### 4.3 场景三：超预算紧急采购
*   **背景**：业务部门因紧急需求（如设备故障替换、突发项目）发生超预算支出。
*   **流程**：
    1.  员工提交报销单，系统检测到超预算，自动触发超预算审批流程。
    2.  审批人（部门经理）收到审批通知，查看超预算详情。
    3.  审批人判断：
        *   若认为合理，选择【通过】，系统自动追加该科目预算并完成扣减。
        *   若认为应从其他科目调剂，选择【调整科目预算】，将"办公费-日常耗材"科目的 ¥3,000 调剂至"设备购置"科目。
        *   若认为不合理，选择【驳回】，填写原因"请降低采购规格或延后至下月"。
    4.  报销人收到审批结果通知。

### 4.4 场景四：通过资金池调整解决超预算
*   **背景**：研发部张三需报销 ¥8,000 的笔记本电脑，但"研发费用-设备购置"科目余额仅剩 ¥3,000，缺口 ¥5,000。
*   **流程**：
    1.  张三提交报销单，系统提示预算不足，显示缺口 ¥5,000。
    2.  张三选择【申请预算调整】，填写原因"紧急采购开发用笔记本"，提交至部门领导。
    3.  **部门领导**收到申请，查看本部门资金池剩余 ¥18,000，足够覆盖：
        *   选择【同意分摊】，系统从部门资金池中拨出 ¥5,000 至"研发费用-设备购置"。
        *   该科目可用余额从 ¥3,000 增至 ¥8,000，部门资金池剩余 ¥13,000。
    4.  张三收到通知"预算调整已通过"，重新进入报销单，科目余额充足，正常提交。

*   **资金池不足的场景**：
    1.  若部门资金池仅剩 ¥3,000，不足以覆盖 ¥5,000 缺口。
    2.  部门领导可选择：
        *   先分摊 ¥3,000（本级全部资金池），剩余 ¥2,000 【向上级转审】至分公司领导。
        *   或直接【向上级转审】，将全部 ¥5,000 转至分公司领导处理。
    3.  分公司领导查看分公司资金池，若充足则直接分摊；若不足则继续向总公司转审。
    4.  总公司资金池若仍不足，则驳回申请，提示"各级资金池均已不足，请等待下预算周期或联系财务调整预算"。

### 4.5 场景五：资本性支出 vs 收益性支出
*   **策略**：利用映射表中的**【是否固定资产】**字段。
*   **逻辑**：
    *   若标记为“是”（如买电脑），预算扣减“资本性支出预算”，会计入账“资产类”。
    *   若标记为“否”（如修电脑），预算扣减“收益性支出预算”，会计入账“损益类”。

## 5. 非功能性需求

*   **性能**：预算校验接口响应时间 < 500ms。
*   **数据一致性**：报销系统与预算系统的科目编码、部门编码必须一致（通过主数据管理同步）。
*   **权限**：映射规则的维护权限开放给财务主管。
*   **通知及时性**：系统消息通知必须在业务操作完成后 **3秒内** 发送，确保审批人能及时收到待办提醒。
*   **日志完整性**：所有业务操作必须写入 `fee_operation_log` 表，日志记录不可删除、不可修改，确保全链路可追溯。
*   **通知可靠性**：消息通知与业务操作在同一事务中完成，保证业务操作成功则通知必定发送。

## 6. 资金池与预算调整申请模块

### 6.1 功能概述

当报销人员的报销金额超出对应预算科目的可用余额时，除了现有的超预算审批流程外，系统新增**资金池调整**机制。各级管理层（部门领导、分公司领导、总公司领导）在预算编制阶段会预留一定额度的**资金池**，用于应对执行过程中的超预算情况。资金池为一个**总金额**，不绑定特定科目，管理层可根据实际需要将其**分摊**到不同的预算科目上，从而增加科目的可用余额，使报销人员能够继续填写和提交报销单。

### 6.2 核心概念

*   **资金池（Fund Pool）**：各级管理层在年度/季度预算编制时，单独预留的一笔总额度，不归属于任何具体预算科目。用于在执行期间灵活调配至超预算的科目。系统设置三级资金池，默认初始额度为：
    *   部门级资金池：**10万元**
    *   分公司级资金池：**50万元**
    *   总公司级资金池：**100万元**
    *   资金池不存在时系统自动创建默认记录，额度由上级分摊设定，后续支持继续申请调整。
*   **预算调整申请**：当报销金额超出科目可用余额时，报销人可发起预算调整申请，请求上级管理层从资金池中向该科目追加额度。
*   **分摊（Allocation）**：管理层将资金池金额分配到指定预算科目的操作。分摊成功后，目标科目的可用余额相应增加。

### 6.3 资金池层级体系

系统设置三级资金池，逐级向上申请：

| 层级 | 资金池持有人 | 资金池来源 | 审批范围 |
|------|--------------|-------------|----------|
| **第一级** | 部门领导 | 部门资金池（年度编制时设定，默认10万元） | 本部门内各预算科目的额度追加 |
| **第二级** | 分公司领导 | 分公司资金池（年度编制时设定，默认50万元） | 分公司下辖各部门的额度追加 |
| **第三级** | 总公司领导 | 总公司资金池（年度编制时设定，默认100万元） | 全公司范围的额度追加 |

### 6.4 预算调整申请流程

#### 6.4.1 触发条件
报销人员提交报销单时，系统检测到对应预算科目的可用余额不足以覆盖报销金额，且报销人选择发起**预算调整申请**（而非走超预算审批流程）。

#### 6.4.2 科目定位规则
预算调整申请与报销单使用相同的映射规则体系：

*   报销人选择**物资小类**和**用途标签**，系统调用 `mappingRuleService.matchRule()` 自动匹配目标预算科目。
*   申请单新增字段：`itemCategory`（物资小类编码）、`purposeTag`（用途标签编码）、`targetSubjectName`（科目中文名称）。
*   提交前展示预算归属预览：目标科目、当前可用余额。

#### 6.4.3 逐级申请流程

```
报销人发起预算调整申请
        │
        ▼
```

#### 6.4.4 各级审批动作

| 审批动作 | 说明 | 后续处理 |
|----------|------|----------|
| **同意分摊** | 资金池充足，审批人同意从资金池中拨出额度至目标科目 | 系统自动完成分摊操作，目标科目可用余额增加，发送消息通知报销人可重新提交，写入操作日志 |
| **驳回** | 审批人认为申请不合理或资金池不足 | 申请退回至报销人，附驳回原因，发送消息通知报销人，写入操作日志 |
| **向上级转审** | 本级资金池不足，审批人同意将申请转至上级 | 申请自动流转至上一级审批人，发送消息通知上级审批人，写入操作日志 |

### 6.5 资金池管理规则

#### 6.5.1 资金池编制
*   资金池在年度/季度预算编制阶段由各级管理层设定。
*   资金池为一个**总金额**，不绑定具体预算科目。
*   资金池额度建议控制在总预算的 **5%~15%**（可配置）。

#### 6.5.2 分摊规则

> **⚠️ 三级差异化分摊规则（核心）**

| 层级 | 分摊金额计算 | 资金来源 | 资金去向 | 是否操作科目预算 |
|------|------|------|------|------|
| **部门级（level=1）** | 差额分摊：`allocateAmount = requestAmount - currentBalance` | 部门资金池 | 目标科目预算余额（直接设为 `requestAmount`） | ✔ 是 |
| **分公司级（level=2）** | `allocateAmount = requestAmount`（或审批人指定） | 分公司资金池 | 申请部门的部门资金池 `totalAmount` | ✖ 否 |
| **总公司级（level=3）** | `allocateAmount = requestAmount`（或审批人指定） | 总公司资金池 | 申请部门所在分公司的分公司资金池 `totalAmount` | ✖ 否 |

**部门级分摊说明**：
*   分摊金额 = 申请金额 - 当前科目可用余额（仅补足差额，避免重复分配）。
*   分摊完成后直接调用 `setBudgetAmount` 将 `budget_preparation_detail.budget_amount` 更新为 `requestAmount`，此后所有余额查询均以该字段为权威数据源。

**分公司/总公司级分摊说明**：
*   不直接操作科目预算，仅做资金池层级间流转。
*   分公司审批通过后，资金注入申请部门的部门资金池，部门经理后续自行分配科目预算。
*   总公司审批通过后，资金注入申请部门所在分公司的分公司资金池，通过 `findBranchDeptId()` 定位分公司部门ID。
*   资金池不存在时，系统自动创建默认记录并关联到申请单。
*   管理层将资金池金额分摊至指定科目时，需指定**目标预算科目**和**分摊金额**。
*   分摊金额不得超过当前资金池的剩余额度（部门级分摊除外，部门级仅扣减差额）。
*   分摊完成后：
    *   目标预算科目的**可用余额**增加相应金额。
    *   资金池的**已分摊金额**累加，**剩余可用额度**相应减少。
*   同一笔资金池可多次分摊到不同科目。

#### 6.5.3 资金池余额管控
*   各级资金池需实时展示：总额度、已分摊金额、剩余可用额度。
*   当资金池使用比例超过 **80%** 时，系统向管理层发送预警通知。
*   资金池在预算周期结束后**不结转**，下个周期重新编制。

### 6.6 报销人操作流程

1.  报销人填写报销单，选择物资小类、用途标签，系统自动计算归属预算科目。
2.  系统校验预算余额，提示预算不足，显示缺口金额。
3.  报销人选择**【申请预算调整】**，填写：
    *   物资小类（下拉选择）
    *   用途标签（单选按钮组）
    *   系统自动匹配目标预算科目并展示预览
    *   申请调整金额（默认等于缺口金额）
    *   调整原因说明（必填）
4.  系统自动提交至**部门领导**审批。
5. 审批通过后，系统自动将资金池分摊至目标科目，科目可用余额增加。
6.  报销人收到通知后，**重新进入报销单填写页面**，此时科目余额已更新，可正常提交报销单。

## 7. 系统消息通知与操作留痕

### 7.1 概述

报销单全生命周期中的**每一个业务节点**均需同时完成两项操作：

1.  **发送系统消息通知**：基于已有的 `sys_message` 站内消息模块，向相关人员发送实时通知，确保流程流转及时透明。
2.  **写入操作日志**：将每次操作记录保存至 `fee_operation_log` 操作日志表，实现全链路可追溯、不可篡改的审计留痕。

### 7.2 通知与留痕规则

*   **消息通知**：复用项目已有的 `ISysMessageService` 服务，通过 `sys_message` 表存储站内消息。前端导航栏铃铛图标显示未读角标，支持下拉面板查看消息列表。
*   **操作日志**：每次业务操作必须写入 `fee_operation_log` 表，记录操作人、操作时间、操作类型、操作详情、关联单据号、操作前/后状态等关键信息，日志记录**不可删除、不可修改**。
*   **执行顺序**：业务操作 → 写入操作日志 → 发送系统消息，三步在同一事务中完成，保证一致性。

### 7.6 查询与追溯

*   **操作日志查询**：支持按单据号、操作人、操作类型、时间范围组合查询。
*   **单据时间线**：报销单详情页展示完整的操作时间线，包含每个节点的操作人、操作时间、操作类型、操作详情。
*   **审计导出**：支持按时间范围导出操作日志，供审计人员核查。
*   **不可篡改**：操作日志表仅允许 INSERT 和 SELECT 操作，禁止 UPDATE 和 DELETE。
