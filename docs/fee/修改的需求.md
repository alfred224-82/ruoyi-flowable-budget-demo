## 核心统一规则（全版本通用底层逻辑）

1. 所有报销依靠「**行业 + 物资小类 + 用途标签 + 部门**」自动匹配预算科目，取消自由文本判定科目（行业作为前置筛选维度，无行业专属规则时自动回退通用规则）；
2. AI 仅负责收集消费信息、抽取文字实体，**无权判定、推荐、编造预算科目**，科目匹配全部由后台规则引擎执行；
3. 所有传给 AI 的敏感数据统一脱敏，支持后台配置脱敏规则；
4. 固定资产折旧、借款利息、租金摊销等无报销单支出，由系统按月自动计提预占预算；
5. 按支出类型分为三轨管控：**费用轨软预警、资本轨硬阻断、资金轨硬阻断**，解决折旧超标无法采购设备冲突；
6. 系统自动识别科目对利润的影响，全页面展示标准化盈利提示。

## 第一部分 通用基础能力（三版本全部包含）

### 一、基础档案管理

- 用途标签、物资小类树形分类维护，财务可新增、停用分类；
- 预算科目与物资、用途的映射规则配置；
- 基础角色权限配置：普通员工、部门经理、财务、管理员；
- 报销单基础字段配置：报销年月、金额、发票附件。

### 二、报销单基础流程

- 结构化填报：物资小类、用途标签、报销年月必填，无自由摘要；
- 发票上传：支持拍照/图片/PDF 上传发票或收据，系统智能识别票据类型并校验合规性；
- 单级部门经理审批流程，单据状态：草稿 / 已提交 / 驳回 / 已通过；
- 预算实时校验，自动计算科目可用余额；
- 单据只读控制：草稿、驳回可编辑，其余状态全部只读；
- 未审批通过单据可删除，已通过单据禁止删除；
- 站内消息通知所有审批、驳回、单据变更节点；
- 全操作留痕日志，记录操作人、时间、单据状态变更。

### 三、AI 对话报销基础能力

- 进入 AI 对话自动带入当前登录员工所属部门，无需手动填写；
- AI 引导式分步采集：消费大类、物品、金额、业务用途；
- 数据脱敏传输 AI，隐藏发票、供应商、手机号等敏感信息；
- AI 只展示系统预设提示文字，不自主分析利润、财务科目；
- 若规则引擎无匹配预算科目，仅提示联系财务配置规则，AI 不编造科目。

### 四、基础预算管控

- 可用余额统一计算规则：`预算总额 - 已审批报销金额`；
- 单部门内部小额科目调剂，解决小额超预算；
- 基础预算执行报表，查看各部门科目使用情况。

### 五、发票合规引擎（客户自定义合规规则）

- 报销单必填发票/收据附件，上传后系统智能识别票据类型（正规发票 / 收据 / 其他）；
- 合规引擎三级模式，由客户在后台自主定义：

| 合规级别 | 票据要求                   | 适用场景                       |
| -------- | -------------------------- | ------------------------------ |
| 简单     | 有收据即可通过             | 小额零星支出、内部费用         |
| 正常     | 收据或正规发票均可         | 日常经营费用（默认级别）       |
| 严格     | 正规发票 + 公司财务盖章确认 | 大额支出、资本性采购、高风险科目 |

- **按科目设置**：合规级别绑定预算科目，不同科目可配置不同合规要求（如「办公费」= 简单，「差旅费」= 正常，「固定资产采购」= 严格）；
- **批量设置**：支持勾选多个科目一键批量设定合规级别，也支持按科目大类统一设置；
- 智能识别不通过时自动拦截提交，提示具体不合规原因（票据类型不符 / 缺少财务盖章确认等）；
- 严格模式下，票据需财务岗线上确认盖章状态后方可流转审批；
- 合规校验结果在审批详情页可视化展示，审批人可查看票据合规状态。

### 六、盈利提示通用规则

- 系统自动区分三类盈利影响：**增加利润、扣减利润、不影响利润**；
- 报销填写页、AI 确认页、审批详情页统一展示盈利提示；
- 固定资产采购提示：当期不影响利润，后续折旧分期扣减盈利；
- 普通费用提示：直接扣减当期净利润。

### 七、系统初始化配置

系统首次部署或管理员进入「系统初始化」页面时，需完成以下基础配置方可正式使用：

#### 7.1 工作流配置（三大核心流程）

管理员可分别配置以下三条工作流，每条工作流支持按系统现有角色定制审批节点：

| 工作流名称     | 流程 Key              | 说明                                                         |
| -------------- | --------------------- | ------------------------------------------------------------ |
| 预算编制工作流 | `budget_preparation`  | 预算编制提交后的多级审批流程（如：编制人 → 部门经理 → 分公司 → 总公司） |
| 报销审核工作流 | `expense_approval`    | 报销单提交后的审批流程（如：报销人 → 部门经理 → 财务）       |
| 预算调整工作流 | `budget_adjustment`   | 预算调整/超预算申请的审批流程（如：申请人 → 部门 → 分公司 → 总公司） |

**配置规则：**

- 每条工作流的审批节点从系统现有角色列表中选择（如：部门经理、财务、分公司管理员、总公司管理员等）；
- 支持自定义审批层级数量（1~N 级），每级绑定一个或多个角色；
- 支持配置每个节点的审批方式：单人审批（任一角色成员通过即可）/ 会签（全部指定角色成员均需通过）；
- 配置完成后系统自动生成对应的 BPMN 流程定义并部署；
- 未配置的工作流使用系统内置默认流程（预算编制三级审批、报销单级审批、预算调整三级审批）。

#### 7.2 资金池初始额度配置（按角色分配）

管理员可按角色设定三级资金池的初始额度，系统在新预算期间自动按此额度创建资金池记录：

| 层级       | 关联角色（示例）       | 默认初始额度 | 说明                                   |
| ---------- | ---------------------- | ------------ | -------------------------------------- |
| 部门级     | 部门经理               | 100,000 元   | 每个部门独立一个资金池                 |
| 分公司级   | 分公司管理员           | 500,000 元   | 每个分公司独立一个资金池               |
| 总公司级   | 总公司管理员 / 管理员  | 1,000,000 元 | 全公司唯一资金池                       |

**配置规则：**

- 管理员可在初始化页面修改各层级的初始额度，修改后仅影响新创建的预算期间，不追溯历史数据；
- 每个层级可绑定一个或多个角色，绑定后该角色用户登录时自动关联对应层级资金池；
- 支持配置预警阈值百分比（默认 80%），资金池使用超过阈值时自动推送预警消息；
- 初始化配置保存后，系统在每月预算编制启动时自动按配置额度创建当期资金池。

## 第二部分 分版本功能清单

---

### 版本一：基础版（小微企业轻量化使用）

#### 一、AI 对话能力（轻量化）

- 仅支持人民币报销，无外币、汇率相关采集；
- 仅区分普通费用、固定资产两类场景；
- 固定资产仅询问折旧年限，无残值率、启用日期采集；
- AI 引导话术固定，后台不可自定义修改；
- 一笔单据仅能归集至单个预算科目，不支持多科目拆分；
- 脱敏规则固定内置，财务无法自定义敏感词、脱敏策略。

#### 二、报销与补贴

- 支持普通差旅、餐饮报销；
- 无后台补助标准配置，不支持自动计算餐补、出差补助；
- 不支持已审批单据补贴补填流程；
- 无员工福利专项报销入口。

#### 三、计提与无单据费用

- 仅支持固定资产折旧自动计提；
- 无合同待摊、租金预提、长短期借款利息计提功能；
- 无资产卡片后台管理页面，仅报销时简单录入折旧年限。

#### 四、预算分摊与资金池

- 仅支持同部门小额科目调剂；
- 无三级资金池（部门/分公司/总公司）、无跨部门分摊；
- 无超预算多级审批、预算调整申请流程。

#### 五、三轨管控

- 简易双轨区分：固定资产采购硬管控、普通费用仅提示；
- 无独立资金轨现金流管控。

#### 六、盈利提示

- 固定内置提示文案，后台不可编辑；
- 无大额支出预警、无强制弹窗提示；
- 不细分折旧、利息专属盈利提醒。

#### 七、报表与审计

- 仅基础预算执行、报销明细报表；
- AI 简易操作日志，无完整 AI 推理审计记录导出。

#### 八、不包含能力

> 外币报销、资金池、利息计提、跨部门分摊、福利补贴配置、私有化 AI、多级超预算审批、完整三轨管控、自定义引导话术、合规引擎自定义（固定「正常」级别不可调整）。

#### 📋 报销单填写示例（基础版）

**场景：员工报销日常办公用品采购**

| 字段       | 填写内容             | 说明                           |
| ---------- | -------------------- | ------------------------------ |
| 报销年月   | 2026-07              | 必填，选择费用归属月份         |
| 物资小类   | 办公用品 > 打印耗材  | 必填，从树形分类中选择         |
| 用途标签   | 日常办公             | 必填，从预设标签中选择         |
| 金额（元） | 356.00               | 必填，仅支持人民币             |
| 发票/收据  | 📎 收据照片.jpg      | 必填附件，系统智能识别票据类型 |

**系统自动处理：**

1. 规则引擎根据「打印耗材 + 日常办公 + 所属部门」自动匹配预算科目 → `管理费用-办公费`；
2. 发票合规校验：该科目合规级别为「正常」，收据满足要求 → ✅ 合规通过；
3. 页面展示盈利提示：⚠️ *该笔费用直接扣减当期净利润*；
4. 预算实时校验：该科目可用余额 = 预算总额 - 已审批报销金额，余额充足则正常提交；
5. 提交后单据状态变为「已提交」，站内消息通知部门经理审批。

### 版本二：高级版（中型企业标准化管控）

> 包含基础版全部功能，新增以下完整能力

#### 一、AI 对话增强功能

- 支持多币种外币报销，AI 自动询问币种、汇率取值方式（自动月度汇率 / 手动填写汇率）；
- 完整固定资产信息采集：折旧月数、残值率、资产启用日期，后台可配置字段是否必填；
- 普通费用场景可配置询问月度固定分摊费率、分摊周期；
- AI 引导话术、页面提示文案财务后台可视化自定义；
- 单笔单据支持规则引擎自动拆分至多个预算科目；
- 完整脱敏配置页面：自定义脱敏字段、敏感词黑名单、拦截动作；
- AI 置信度不足自动转人工复核并推送财务通知。

#### 二、员工福利与补助管理

- 后台可配置差旅补助、餐补、交通补贴标准；
- 报销单根据出差天数自动计算补助金额，自动归集职工福利费科目；
- 支持已审批单据追加补贴补填，重新核算预算并留痕；
- 福利专项报销入口：团建、体检、节日福利。

#### 三、发票合规引擎自定义

- 合规级别后台可视化配置：按预算科目独立设定简单 / 正常 / 严格三级合规要求；
- 批量设置：支持勾选多个科目一键批量设定合规级别，也支持按科目大类统一设置；
- 未单独配置的科目默认使用「正常」级别；
- 智能识别票据类型（正规发票 / 收据 / 其他），不满足当前科目合规级别时自动拦截提交；
- 严格模式：票据需财务岗线上确认盖章状态后方可流转审批；
- 合规校验结果在审批详情页可视化展示，审批人可查看票据合规状态。

#### 四、周期计提引擎（多类无单据费用管理）

- 资产卡片全生命周期管理：固定资产、无形资产，按月自动折旧摊销；
- 合同台账管理：租金、长期服务费自动按月预提摊销；
- 折旧、摊销生成凭证草稿，自动预占费用轨预算，财务复核后正式扣减；
- 计提任务失败自动重试并推送财务预警。

#### 五、预算分摊与超预算流程

- 超预算多级审批，支持科目间预算调剂；
- 单部门资金池，可从资金池分摊额度补足超预算科目；
- 分摊流水完整记录，支持按科目、时间查询分摊明细；
- 调剂保护规则：调出科目余额最低保留 10%，单笔调剂上限可配置。

#### 六、完整三轨预算管控

- **费用轨**（折旧、摊销、福利利息）：仅软提示，不阻断固定资产采购；
- **资本轨**（设备、在建工程）：硬管控，额度不足无法提交；
- **资金轨**（现金流付款）：硬管控，现金流不足禁止付款；
- 彻底解决折旧预算用尽、无法采购新设备的冲突问题。

#### 七、盈利提示增强

- 后台自定义盈利提示文案、文字颜色；
- 可配置大额支出阈值，超阈值高亮红色预警；
- 折旧、待摊费用专属盈利提示，清晰说明分期扣减利润规则；
- 大额支出支持弹窗强制阅读盈利提示，操作日志记录已读记录。

#### 八、报表与审计

- 组织机构盈利分析报表，按六大会计科目聚合查看收支；
- 资金池使用、超预算审批统计看板；
- AI 全链路推理审计日志，脱敏存储，支持审计导出；
- 资金池使用超过 80% 自动推送管理层预警消息。

#### 九、不包含能力

> 分公司/总公司两级上层资金池、长短期借款台账 + 利息自动计提、集团跨部门自动分摊、私有化 AI 部署。

#### 📋 报销单填写示例（高级版）

**场景一：员工出差报销（含自动补助核算）**

| 物资小类     | 差旅费 > 交通住宿   | 必填                                                       |

1. 规则引擎自动拆分为两个预算科目：`差旅费-交通住宿` 2,860元 + `职工福利费-出差补助` 600元；
2. 分别校验两个科目可用余额，任一不足即触发超预算流程；

2. 以折算后人民币金额 3,575.00 元校验预算余额并扣减。

### 版本三：企业专业版（集团大型企业全闭环）

> 包含高级版全部功能，新增集团级、投融资类完整能力

#### 一、AI 对话扩展：长短期借款场景采集

- AI 识别融资借款业务，自动引导录入完整借款信息：借款类型（短期/长期）、本金、年化利率、起止日期、利息计提周期；
- 借款信息自动生成借款台账，无需财务手工录入；
- 后台可自定义借款场景 AI 提问话术、盈利预警提示。

#### 二、完整周期计提体系（三大计提数据源）

- **资产卡片**：折旧、无形资产摊销；
- **合同台账**：租金、长期待摊、年终奖预提；
- **借款台账**：短期/长期借款利息按月自动计提；
- 系统区分两类成本逻辑：
  - 折旧：资产价值消耗，分期扣减利润；
  - 利息：融资财务成本，持续扣减各期利润；
- 利息仅占用费用轨预算，不影响设备资本采购额度。

#### 三、三级资金池逐级分摊机制

- 三层资金池独立额度：部门级、分公司级、总公司级；
- 部门资金池不足可向上级分公司、总公司逐级转审分摊；
- 差异化分摊规则：
  - **部门级**：直接补足目标科目缺口；
  - **分/总公司级**：向下流转资金池总额，下级自行分配科目；
- 完整资金池台账，记录每一笔分摊来源、去向、剩余额度。

#### 四、集团跨部门自动分摊

- 中台、共享中心设立待分摊虚拟部门；
- 月末系统按人数、工时比例自动分摊共用费用至各业务部门；
- 分摊自动生成调整凭证，同步更新各部门盈利扣减金额。

#### 五、投融资负债全流程管理

- 独立借款台账管理页面，支持 AI 录入、财务手工录入双渠道；
- 借款状态全生命周期：正常计息、已结清、逾期预警；
- 逾期借款自动推送财务管理员预警通知；
- 盈利报表单独拆分利息支出维度，直观展示融资成本对净利润影响。

#### 六、AI 企业级安全能力

- 支持 AI 模型私有化部署，业务数据不出内网；
- 完整敏感数据隔离，银行借款合同、供应商涉密信息不传入 AI 接口；
- 可配置 AI 全部 Prompt 约束，严格禁止 AI 输出财务、利润相关解读内容；
- 合规引擎与行业配置联动：行业配置包可预设科目级合规级别（如金融行业全部科目默认严格），批量导入即生效；
- 合规校验记录纳入全链路审计导出范围。

#### 七、集团级报表与审计

- 集团多层级盈利汇总报表，可按分公司、部门、科目钻取明细；
- 折旧、摊销、利息、费用分摊四类计提数据分开统计展示；
- 全链路审计日志导出，覆盖报销、AI 推理、计提、资金池分摊、借款利息所有操作节点；
- 支持年度审计底稿一键导出。

## 第四部分 统一管控注意事项（全版本通用约束）

### 1. AI 相关管控要求

- AI 仅采集信息，无任何预算科目、利润判定权限；
- 所有敏感数据必须脱敏后传输 AI，原始合同、发票、银行信息隔离；
- AI 不能自主解读盈利、税负、经营建议，仅展示系统预设提示；
- AI 无法生成系统不存在的预算科目，无匹配规则时只能引导人工配置。

### 2. 折旧与利息业务区分要求

- 固定资产采购属于资产类，不直接扣减当期利润；每月折旧为成本消耗，分期减少盈利；
- 借款本金属于负债，不影响利润；每月利息为融资成本，持续扣减各期净利润；
- 折旧、利息全部归入费用轨软预警，不会阻断新增固定资产采购。

### 3. 预算分摊冲突解决方案

- 三轨物理隔离：费用额度、资本采购额度、现金流额度相互独立，互不占用；
- 单部门科目小额调剂，设置最低余额保护阈值；
- 高级版支持本级资金池补足缺口；企业专业版支持三级资金池逐级兜底；
- 月末跨部门分摊仅调整各部门费用轨额度，不占用资本采购预算。

### 4. 盈利提示规范

- 🟢 收益类科目绿色提示：增加当期净利润；
- 🔴 费用、折旧、利息红色提示：扣减当期净利润；
- ⚪ 资产、借款本金灰色提示：不直接影响当期利润；
- 大额支出可配置弹窗强制确认，留痕审计记录。

### 5. 无报销单费用管理规范

- 折旧、摊销、利息、租金预提全部依靠台账自动生成计提凭证，无需每月提交报销；
- 计提金额提前预占对应费用预算，保证预算执行数据真实无失真；
- 所有计提记录可在财务后台统一复核、查看、作废。

### 6. 发票合规管理规范

- 合规引擎三级标准（简单/正常/严格）由客户后台自主定义，系统不硬编码合规策略；
- 合规级别按预算科目独立配置，支持批量设置，未单独配置的科目默认使用「正常」级别；
- 智能识别仅判定票据类型是否满足当前科目的合规级别，不判定票据真伪（真伪校验可对接税务接口扩展）；
- 合规校验不通过时阻断提交，不允许绕过；严格模式必须财务线上确认盖章后方可进入审批流；
- 所有合规校验记录纳入操作留痕日志，支持审计追溯。

### 7. 多行业适配通用约束

- AI 底层逻辑不变：仅采集信息，不判定科目，行业差异仅影响展示提问内容；
- 三轨管控、资金池、计提、报销审批底层计算逻辑统一，行业仅调整阈值、默认参数；
- 盈利提示底层逻辑不变，仅切换行业专属提示文案；
- 无新增业务流程、无新增状态机、无新增核心计算逻辑，最大化减少系统改动。

## 第五部分 多行业适配轻量化设计方案（地产 / 互联网 / 传统制造 / 金融）

> **核心设计思路**：不做多套系统、不大量新增代码/业务分支，采用「行业隔离配置层 + 通用底层内核」模式——底层报销、AI 对话、预算、计提、三轨管控、资金池逻辑完全共用；行业差异全部通过「后台行业参数配置」「行业专属标签/科目映射包」「行业开关控制」实现，切换行业仅导入配置包、修改开关，底层业务逻辑零改动。

### 一、顶层行业基础档案（仅新增配置模块，不修改原有业务主流程）

#### 1.1 行业档案主数据（仅新增数据表，原有报销、计提、资金池表不改动）

- 行业类型枚举固定 4 大类，可扩展：**互联网、房地产、传统制造、金融**；
- 每条行业配置独立一套隔离参数，所有差异化规则绑定行业编码，互不干扰。

每条行业配置包含：

| 配置项                               | 说明                                   |
| ------------------------------------ | -------------------------------------- |
| 行业基础开关组                       | 一键开启/关闭行业专属规则              |
| 行业专属物资小类、用途标签           | 仅本行业可见，其他行业隐藏             |
| 行业专属预算科目映射规则包           | 导入式配置，一键切换                   |
| 行业 AI 引导提问模板、盈利提示文案包 | 按行业自动加载                         |
| 行业计提规则参数                     | 折旧年限默认值、利息核算规则、待摊周期 |
| 行业预算管控阈值                     | 资金池比例、调剂保护比例、大额预警金额 |
| 行业特殊合规拦截规则                 | 金融敏感支出拦截、地产工程类支出强制字段 |

#### 1.2 组织绑定行业，自动隔离数据

- 分公司/部门档案新增「所属行业编码」字段（仅新增字段，原有组织逻辑不变）；
- 用户登录后，系统读取当前部门绑定的行业，自动加载对应行业全套配置：
  - AI 对话展示本行业专属提问、物资分类；
  - 报销单下拉仅展示本行业可用物资、用途标签；
  - 盈利提示、弹窗文案自动切换行业版本；
  - 折旧、利息、分摊默认参数自动匹配行业标准。
- **跨行业集团**（同时有地产 + 互联网子公司）：不同子公司绑定不同行业编码，前端、规则引擎自动隔离，互不影响。

### 二、四大行业差异化配置方案（全部通过配置实现，底层业务无改动）

> 统一底层不变能力（全行业共用）：AI 信息采集、脱敏机制、三轨预算管控、三级资金池、折旧/摊销/利息计提、报销审批流、盈利提示、操作审计日志、外币报销、费用分摊底层计算逻辑完全复用，不做分支改造。

#### 1）互联网行业

**差异化特征**：研发投入高、大量软件采购、人力福利、云服务年费、无大额固定资产、长期软件待摊。

**配置实现（无需改代码）：**

- 行业专属用途标签：研发投入、云服务采购、员工期权福利、技术外包；
- 物资小类新增：云资源、软件授权、知识产权；
- AI 引导配置：软件类自动询问待摊周期；
- 折旧默认参数：软件资产默认摊销 36 个月；
- 盈利提示模板适配研发费用加计扣除提示文案；
- 管控阈值：研发类科目资金池分配比例调高。

#### 2）房地产行业

**差异化特征**：工程项目、土地配套、建安成本、长期待摊、大额工程固定资产、预提工程款、大额资金管控。

**配置实现：**

- 行业专属标签：建安工程、土地配套、项目前期费用、工程维保；
- 物资小类新增：工程设备、建材、施工服务；
- 开关开启：工程类支出增加工程标段扩展字段；
- 计提配置：工程类资产默认折旧年限加长，工程款预提周期按季度；
- 资金轨管控强制开启，大额支出双重预警；
- 盈利提示区分开发成本、期间费用两套文案。

#### 3）传统制造企业

**差异化特征**：生产设备、车间耗材、生产线固定资产、制造费用分摊、原材料采购、废品损耗分摊。

**配置实现：**

- 专属标签：生产制造、车间运维、原材料采购；
- 物资小类：生产设备、原材料、车间耗材；
- AI 分摊配置：生产类支出自动询问车间分摊比例；
- 折旧默认：生产设备折旧年限统一预设；
- 月末自动分摊开关开启，按产线/车间分摊制造费用。

#### 4）金融行业（银行 / 证券 / 保险）

**差异化特征**：强合规、严禁回扣/招待超标、融资借款多、利息收支频繁、敏感支出拦截、监管审计要求高。

**配置实现：**

- 行业敏感词黑名单一键导入（回扣、礼品、大额招待等），AI 对话直接拦截；
- 招待费设置行业专属大额预警阈值，超阈值强制多级审批；
- 借款台账、利息计提规则默认开启，盈利提示重点突出利息收支；
- 审计日志增强开关：AI 推理、报销、计提操作日志全部自动开启导出权限；
- 隐藏不合规物资分类，限制高风险支出类目可选。

| 改动点                       | 改动内容                                                       | 影响范围                                             |
| ---------------------------- | -------------------------------------------------------------- | ---------------------------------------------------- |
| 新增顶层行业配置管理页面     | 仅新增配置模块，维护行业参数、标签包、映射规则包、AI 话术包    | 原有基础档案、报销、AI、计提页面复用，仅增加行业过滤条件 |
| 组织表新增 1 个字段          | 「所属行业编码」单字段新增，不修改原有组织权限、审批逻辑       | 用户登录自动携带行业参数作为全局过滤条件             |
| 规则/模板表增加行业绑定字段  | 映射规则、AI 引导配置、盈利提示表仅新增行业编码过滤字段        | 匹配时增加行业前置筛选，原有逻辑无重构               |

**科目匹配公式更新：**

```
预算科目 = 行业 + 物资小类 + 用途标签 + 部门
```

> 底层匹配逻辑无重构，仅多一层行业过滤，改动量极低。

### 四、跨行业快速落地实施方式（零代码切换，无需开发改动）

1. 新建行业档案，导入对应行业「标签 + 科目映射 + AI 话术 + 计提参数」配置包；
2. 给对应分公司/部门绑定行业编码；
3. 开启行业专属管控开关（金融敏感拦截、制造分摊等）；
4. 用户重新登录，自动加载本行业全套适配规则，系统功能无需二次开发。

### 五、分版本行业适配能力划分

| 能力                                                 | 基础版                   | 高级版                       | 企业专业版                       |
| ---------------------------------------------------- | ------------------------ | ---------------------------- | -------------------------------- |
| 行业配置后台                                         | ❌ 固定内置单行业，不可切换 | 单行业自定义（互联网/制造等） | ✅ 多行业档案并行维护            |
| 自定义行业标签、科目、阈值                           | ❌                       | ✅                           | ✅                               |
| 多行业组织同一系统并存                               | ❌                       | ❌                           | ✅ 分公司/部门独立绑定，自动隔离 |
| 行业配置包导入导出                                   | ❌                       | ❌                           | ✅ 新行业快速上线                |
| 行业专属合规开关（金融拦截、地产强制字段、制造分摊） | ❌                       | 部分                         | ✅ 全部开放                      |
| 集团报表按行业维度汇总                               | ❌                       | ❌                           | ✅ 盈利、预算执行按行业钻取      |

### 六、多行业冲突兜底方案（配置化解决，无需开发）

- 同一集团存在多行业时，规则匹配优先读取「行业 + 物资 + 用途 + 部门」精准规则；无行业专属规则时，自动回退匹配通用基础规则；
- 行业间物资、标签互相隔离，A 行业看不到 B 行业专属分类，避免选错；
- 计提、分摊、预算预警参数按行业独立存储，互不覆盖。

### 七、多客户与多行业部署模型设计

> 系统需同时覆盖两类典型场景：**不同行业的多个客户**各自独立使用，以及**一个客户内部跨多行业**。两类场景底层共用同一套内核，通过「部署模型 + License 行业授权 + 组织绑定」三层组合实现。

#### 7.1 两类场景对比

| 维度           | 场景 A：多客户不同行业                             | 场景 B：一个客户跨多行业                         |
| -------------- | -------------------------------------------- | -------------------------------------------- |
| 典型客户       | 客户甲=地产、客户乙=互联网、客户丙=金融       | 某集团：地产子公司 + 互联网子公司 + 制造子公司 |
| 部署方式       | 每个客户独立部署一套系统（或 SaaS 多租户）     | 一套系统，多个子公司共用                       |
| 行业数量       | 每套系统仅 1 个行业（或少数几个）             | 同一系统内 2~4 个行业并存                   |
| 数据隔离       | 物理隔离（独立数据库）或租户隔离（SaaS）     | 组织级逻辑隔离（部门/子公司绑定行业）       |
| 行业配置管理   | 客户仅看到自己行业的配置，其他行业不可见     | 集团管理员可见全部行业，各子公司仅见本行业   |
| 报表汇总       | 无跨客户汇总需求                             | 集团报表按行业维度钻取、汇总                 |
| 版本要求       | 基础版/高级版/企业版均可（按客户规模）       | 通常企业专业版（多行业并存仅企业版支持）   |
| License        | 每客户一份，绑定 1 个行业 + 1 台机器         | 一份 License 绑定多个行业 + 1 台机器       |

#### 7.2 场景 A：多客户不同行业（独立部署 / SaaS 多租户）

**私有化独立部署模式：**

- 每个客户独立部署一套系统，各自拥有独立数据库、独立 License；
- 部署时导入对应行业配置包（如客户甲导入 `realestate.zip`，客户乙导入 `internet.zip`）；
- License 中 `industries` 字段仅含该客户购买的行业，未授权行业配置包即使存在也无法导入；
- 客户后台仅展示本行业的物资分类、用途标签、科目映射、AI 话术，其他行业完全不可见；
- 各客户系统完全独立，无数据交叉、无配置干扰。

**SaaS 多租户模式（可选，适用于基础版/高级版小微客户）：**

- 一套系统服务多个租户客户，每个租户拥有独立数据空间（tenant_id 隔离）；
- 每个租户绑定 1 个行业编码，登录后自动加载对应行业配置；
- 租户间数据完全隔离：A 客户（地产）看不到 B 客户（互联网）的任何单据、科目、配置；
- 行业配置由平台统一维护，租户仅可在授权范围内自定义参数（阈值、文案等）；
- License 按租户签发，每个租户独立试用/正式授权、独立计费。

#### 7.3 场景 B：一个客户跨多行业（集团多业态）

> 此场景仅企业专业版支持（`FEE_INDUSTRY_MULTI` 开关）。

**组织绑定行业，自动隔离：**

```
某集团（企业专业版，一份 License）
├── 地产子公司（industry=REALESTATE）
│   ├── 工程部       → 看到：建材/施工服务/工程标段，匹配地产科目
│   └── 财务部       → 看到：地产行业报表、工程款预提
├── 互联网子公司（industry=INTERNET）
│   ├── 研发部       → 看到：云资源/软件授权，匹配研发科目
│   └── 运维部       → 看到：云服务年费、待摊配置
└── 制造子公司（industry=MANUFACTURING）
    ├── 一车间       → 看到：生产设备/车间耗材，分摊比例
    └── 采购部       → 看到：原材料、制造科目
```

**关键规则：**

- 用户登录后，系统根据其所属部门/子公司绑定的行业编码，自动加载对应行业全套配置；
- 地产员工看不到互联网的「云资源」分类，制造员工看不到地产的「工程标段」字段；
- 集团管理员可查看全部行业数据，报表支持按行业维度钻取、汇总、对比；
- 跨行业子公司之间的费用分摊，按各自行业规则独立计算，互不干扰；
- 资金池三级分摊在行业内部独立运作，不跨行业占用额度。

#### 7.4 License 行业授权设计

License 新增 `industries` 字段，控制客户可使用的行业配置包：

```json
{
  "licenseId": "LIC-2026-000789",
  "licenseType": "FORMAL",
  "customer": "某某集团",
  "edition": "ENTERPRISE",
  "trialDays": 0,
  "industries": ["REALESTATE", "INTERNET", "MANUFACTURING"],
  "maxTenants": 1,
  "features": ["...全部功能开关..."],
  "machineFingerprint": "b7e2d4...f93a",
  "issuedAt": "2026-07-01",
  "expiresAt": "2027-06-30",
  "signature": "MEUCIQA8...（RSA-SHA256 签名）"
}
```

**字段说明：**

| 字段           | 说明                                                                 |
| -------------- | -------------------------------------------------------------------- |
| `industries`   | 授权行业列表，仅列表内的行业配置包可导入使用；未授权行业无法导入、无法绑定组织 |
| `maxTenants`   | 最大租户数（私有化部署=1；SaaS 多租户按购买席位数签发）             |
| `edition`      | 版本等级，决定功能开关；行业数量不影响版本等级                       |

**行业授权校验规则：**

- 导入行业配置包时，校验 `industries` 列表是否包含目标行业编码，未授权则拒绝导入；
- 组织绑定行业时，校验目标行业是否在 License 授权范围内，未授权则禁止绑定；
- 客户追加购买新行业：厂商签发新 License（`industries` 增加新行业编码），替换后重启即可导入新行业包；
- 行业授权与版本授权独立：基础版/高级版客户也可购买单行业包（`FEE_INDUSTRY_SINGLE`），企业版可购买多行业。

#### 7.5 典型客户场景举例

| 客户类型                 | 版本       | 行业授权                     | 部署方式       | 说明                                       |
| ------------------------ | ---------- | ---------------------------- | -------------- | ------------------------------------------ |
| 小微互联网公司（10人）   | 基础版     | `["INTERNET"]`              | SaaS 云端      | 固定内置互联网行业，开箱即用               |
| 中型制造企业（200人）   | 高级版     | `["MANUFACTURING"]`         | 私有化单机     | 单行业自定义，可调整阈值/标签/科目       |
| 地产集团（多子公司）     | 企业专业版 | `["REALESTATE"]`            | 私有化集群     | 单行业，但多子公司共用一套系统             |
| 多元化集团（地产+互联网） | 企业专业版 | `["REALESTATE","INTERNET"]` | 私有化集群     | 多行业并存，子公司各自绑定行业，集团汇总报表 |
| 全行业集团（4大行业）   | 企业专业版 | `["REALESTATE","INTERNET","MANUFACTURING","FINANCE"]` | 私有化集群 | 全行业覆盖，集团级报表按行业钻取 |

#### 7.6 行业配置包与 License 的协作流程

```
厂商签发 License（含 industries 授权）
        │
        ▼
客户部署系统，导入 license.key
        │
        ▼
系统校验 License → 加载 industries 列表至内存
        │
        ▼
客户尝试导入行业配置包（如 finance.zip）
        │
        ├─ industries 包含 FINANCE → ✅ 导入成功，行业配置生效
        │
        └─ industries 不包含 FINANCE → ❌ 拒绝导入，提示「未授权该行业，请联系厂商购买」
        │
        ▼
组织绑定行业时同样校验 → 未授权行业不可绑定
```

> 行业配置包本身不加密（内容是标签/科目/参数，非核心机密），但「能否导入使用」由 License 签名控制，客户无法绕过。

## 第六部分 产品策略与版本发布方案

### 一、核心结论：不拆分产品，维持「一套系统 + 版本分级」模式

> **建议：不拆分为两个独立产品（轻量版 / 完整版），维持一套系统通过功能开关分级交付。**

#### 拆分两套产品的问题

| 维度       | 拆分后的代价                                                   |
| ---------- | ------------------------------------------------------------ |
| 研发成本   | 两套代码分支维护，底层报销/预算/计提逻辑重复开发，Bug 需修两遍 |
| 客户成长   | 小公司长大后要迁移系统、迁移数据，等于逼客户换产品，流失风险极高 |
| 交付复杂度 | 两套部署方案、两套运维文档、两套售后体系                     |
| 功能漂移   | 时间一长两个产品越走越远，通用能力逐渐不通用                 |
| 品牌认知   | 两个产品名 = 两倍市场教育成本                               |

#### 一套系统 + 版本分级的优势

| 维度         | 说明                                                       |
| ------------ | ---------------------------------------------------------- |
| 轻量交付     | 基础版关闭高级功能开关即可，部署包同一个，配置不同           |
| 无缝升级     | 基础版 → 高级版仅开启功能开关 + 导入配置包，数据零迁移     |
| 研发统一     | 一套内核、一套测试、一次发版全版本生效                     |
| 定价灵活     | 按版本 + 行业包组合定价，比两个独立产品更灵活               |
| 多行业复用   | 「行业隔离配置层」天然依赖统一底层，拆分后无法复用           |

> 本质：**小公司用的是“看起来轻”的产品，大公司用的是“打开全部开关”的同一套系统**。用户感知的是轻量产品，底层是同一套系统的不同配置。

#### 2.3 开关配置管理机制（License 授权驱动）

- 功能开关不由本地配置文件或数据库决定，而是由厂商签发的 **License 授权文件**（数字签名 + 机器指纹绑定）驱动，客户无法自行修改解锁；
- 系统启动时验签并加载 features 列表至内存，管理员后台不可见、不可改；
- 升级版本 = 厂商签发新 License + 执行增量初始化 SQL，无需重新部署、无需数据迁移；
- 前端菜单、页面按钮、后台配置入口均根据 features 动态渲染，未授权功能完全不可见；
- 接口层统一校验 features，未授权功能即使绕过前端调用接口也会被拒绝（403）。

#### 3.2 版本授权与防篡改机制（License 保护）

> **核心原则：版本能力由厂商签发的 License 授权文件决定，客户无法通过修改任何本地配置解锁高级功能。**

**为什么不用明文配置文件：**

- 明文 YAML/properties 客户可直接编辑，基础版改一下就变高级版，版本分级形同虚设；
- 数据库配置表同样可被 DBA 直接篡改，不可作为唯一信任源；
- 必须引入密码学手段，让「篡改可检测、伪造不可能」。

**License 授权文件设计：**

| 设计要点       | 方案说明                                                                 |
| -------------- | ------------------------------------------------------------------------ |
| 文件格式       | JSON 内容 + RSA/国密 SM2 数字签名，生成 `license.key` 文件               |
| 签发方         | 厂商 License 签发工具（私钥仅厂商持有，永不随产品发布）                   |
| 校验方         | 系统内核内置公钥，启动时验签；签名不合法 = 文件被篡改 → 拒绝启动或降级为基础版 |
| 绑定维度       | 版本编码 + 客户标识 + 机器指纹（MAC/主板序列号哈希）+ 有效期             |
| 防复制         | 机器指纹绑定，license.key 拷贝到其他服务器无法通过校验                   |
| 有效期控制     | 支持永久授权与按年订阅两种模式；到期后高级功能自动冻结（数据保留、只读） |
| 离线可用       | 验签为纯本地计算，无需联网；私有化部署环境无外网也能正常运行             |

**license.key 内容结构（明文部分）：**

```json
{
  "licenseId": "LIC-2026-000123",
  "licenseType": "FORMAL",
  "customer": "某某科技有限公司",
  "edition": "ADVANCED",
  "trialDays": 0,
  "industries": ["INTERNET"],
  "maxTenants": 1,
  "features": [
    "FEE_MULTI_CURRENCY", "FEE_SUBSIDY_CONFIG", "FEE_AI_CUSTOM_PROMPT",
    "FEE_AI_MULTI_SUBJECT", "FEE_COMPLIANCE_CUSTOM", "FEE_ASSET_CARD",
    "FEE_CONTRACT_AMORTIZE", "FEE_FUND_POOL_DEPT", "FEE_OVER_BUDGET_MULTI",
    "FEE_TRACK_CASHFLOW", "FEE_PROFIT_CUSTOM_TIP", "FEE_LARGE_AMOUNT_ALERT",
    "FEE_REPORT_PROFIT", "FEE_AUDIT_AI_LOG", "FEE_INDUSTRY_SINGLE"
  ],
  "machineFingerprint": "a3f8c9...e71d",
  "issuedAt": "2026-07-01",
  "expiresAt": "2027-06-30",
  "signature": "MEUCIQDx...（RSA-SHA256 签名）"
}
```

> `licenseType` 取值：`TRIAL`（试用授权）/ `FORMAL`（正式授权）；`trialDays` 仅试用授权有效（如 3）；`industries` 控制可导入的行业配置包；`maxTenants` 控制最大租户数（私有化=1）。

**系统校验流程：**

1. **启动时校验**：读取 `license.key` → 公钥验签 → 校验机器指纹 → 校验有效期 → 加载 features 列表写入内存；
2. **试用授权额外校验**：licenseType=TRIAL 时，读取加密激活记录 → 首次启动则写入激活时间戳 → 计算剩余试用时长；时钟回拨/记录损坏 → 直接降级；
3. **校验失败处理**：签名不合法或指纹不匹配 → 系统降级为基础版功能运行，管理后台展示「授权异常」告警；
4. **运行时校验**：定时任务每小时复核试用剩余时长与正式授权有效期；试用到期即时降级，正式授权到期前 30 天站内消息 + 邮件提醒续期；
5. **接口层强制**：所有高级功能接口在执行前校验内存中的 features 列表，未授权功能一律返回 403；
6. **防降级回滚**：License 只能升级不能降级，新签发的 license 版本号必须 ≥ 当前版本，防止用旧文件回滚绕过到期限制。

**试用授权机制（3 天全功能体验，到期自动降级）：**

客户可在未签约前获得 **3 天全功能试用**，到期后自动降级为基础版，全程无需人工干预，且客户无法通过任何手段延长试用期。

| 设计要点         | 方案说明                                                                 |
| ---------------- | ------------------------------------------------------------------------ |
| 试用授权签发     | 厂商签发 `licenseType=TRIAL, trialDays=3` 的签名授权，features 含目标版本全部功能 |
| 起算时机         | 系统**首次启动**时记录激活时间戳，试用期从首次启动时刻起算 3×24 小时     |
| 激活记录存储     | 激活时间写入加密本地文件（AES 加密 + HMAC 校验），与 license.key 分离存储 |
| 到期自动降级     | 试用期满后，系统自动按 edition=BASIC 加载 features，高级功能即时冻结（数据保留、只读） |
| 降级后提示       | 管理后台展示「试用已到期，已降级为基础版」+ 联系厂商购买入口，站内消息通知管理员 |
| 转正无缝衔接     | 签约后厂商签发正式 license.key（同机器指纹），替换后重启即恢复全部功能，试用期间数据完整保留 |

**试用期防篡改保护（客户无法延长试用）：**

| 攻击手段                 | 防御措施                                                                 |
| ------------------------ | ------------------------------------------------------------------------ |
| 修改 license.key 的 trialDays | 签名校验失败 → 直接降级基础版并告警                                 |
| 删除/重置激活记录文件     | 文件缺失或 HMAC 校验失败 → 视为试用已到期，直接降级（宁可误判不可放行） |
| 回拨系统时间             | 每次启动记录「最后校验时间戳」，当前时间 < 最后校验时间 → 判定为时钟回拨，试用立即到期 |
| 重装系统重新试用         | 机器指纹绑定硬件（主板序列号 + MAC），重装系统指纹不变，激活记录写入固件级存储区（如 EFI 变量/隐藏分区），重装后仍可检测已试用 |
| 拷贝 license 到其他机器 | 机器指纹不匹配 → 拒绝加载，试用授权每台机器仅一次机会               |
| 用旧试用 license 替换新的 | 防降级回滚机制：license 版本号必须 ≥ 当前已加载版本，旧文件无法生效   |

**试用授权 license.key 示例：**

```json
{
  "licenseId": "LIC-TRIAL-2026-000456",
  "licenseType": "TRIAL",
  "customer": "试用客户",
  "edition": "ENTERPRISE",
  "trialDays": 3,
  "features": ["...目标版本全部功能开关..."],
  "machineFingerprint": "a3f8c9...e71d",
  "issuedAt": "2026-07-20",
  "expiresAt": "2026-08-20",
  "signature": "MEQCIFx9...（RSA-SHA256 签名）"
}
```

> 说明：`expiresAt` 为授权文件本身的最后激活期限（超过此日期未激活则文件作废），实际试用到期时间 = 首次启动时间 + 3 天。

**离线/断网环境授权保障方案：**

> 核心设计原则：License 校验全链路纯本地计算（公钥验签 + 本地时钟 + 本地指纹比对），**不依赖任何网络请求**，完全断网环境下与联网环境行为一致。

| 场景                 | 离线解决方案                                                                 |
| -------------------- | ------------------------------------------------------------------------ |
| 日常运行校验         | 公钥已内置在 jar 包中，验签、指纹比对、有效期判断均为本地计算，无需联网     |
| 试用期激活与到期     | 激活时间戳写入本地加密文件，每次启动本地比对系统时钟，无需服务器确认       |
| 正式授权续期/升级 | 客户导出「机器指纹文件」→ 通过任意渠道（邮件/U盘/电话）发给厂商 → 厂商签发新 license.key → 客户拷贝回服务器替换 → 重启生效 |
| 硬件更换/服务器迁移 | 客户联系厂商说明情况，提供新机器指纹，厂商重新签发绑定新指纹的 license.key |
| 时钟回拨防护       | 本地「最后校验时间戳」机制，无需 NTP 服务器，纯本地前后对比即可检测回拨   |

**离线续期操作流程（无需联网，5 分钟完成）：**

```
客户服务器（断网）                    厂商（任意网络）
────────────────────                    ────────────────────
1. 系统后台点击「导出机器指纹」
   → 生成 fingerprint.json
   （含 MAC、主板序列号、当前版本）

2. 通过 U盘/邮件/微信 发送 ──────→  3. 厂商工具读取指纹
                                         → 签发新 license.key
                                         （绑定该指纹 + 新有效期）

4. 收到新 license.key  ←──────────

5. 替换服务器上旧文件
6. 重启服务 → 验签通过 → 续期成功
```

> 全程客户服务器无需联网，指纹文件与 license.key 通过任意离线渠道传递即可。

**可选增强方案（适用于高安全要求客户）：**

| 方案               | 说明                                                                 | 适用场景               |
| ------------------ | -------------------------------------------------------------------- | ---------------------- |
| USB 硬件加密狗     | License 存储在加密狗硬件芯片内，系统启动时读取狗内授权，拔狗即降级 | 金融/军工等极高安全要求 |
| 内网 License 服务器 | 集团内网部署一台 License 管理服务，各业务系统向内网服务器校验（非外网） | 集团多系统统一授权管理 |
| 永久授权模式       | 一次性签发无 expiresAt 的 license，后续无需续期，仅升级时需新文件   | 买断制客户、长期断网环境 |

> 默认方案（文件 License + 离线续期）已能覆盖绝大多数私有化部署场景，硬件加密狗和内网 License 服务器为可选增强，按客户安全等级选配。

**各版本发布包内 license 差异：**

| 版本       | license.key 内容                        | 签发方式                     |
| ---------- | ------------------------------------- | ---------------------------- |
| 基础版     | edition=BASIC，features 仅含基础功能     | 随包附带（永久授权）           |
| 高级版     | TRIAL：3 天全功能试用；FORMAL：正式授权 | 试用随包附带，正式授权商务签约后签发 |
| 企业专业版 | TRIAL：3 天全功能试用；FORMAL：正式授权 | 试用申请签发，正式授权项目交付时签发 |

#### 3.3 三个发布包差异对比

| 对比项           | 基础版                     | 高级版                     | 企业专业版                   |
| ---------------- | ------------------------ | ------------------------ | -------------------------- |
| 内核代码           | 相同（同一构建产物）       | 相同                       | 相同                         |
| 授权文件           | 永久 License（基础功能）   | 3 天试用 + 正式 License    | 3 天试用 + 正式 License      |
| 防篡改             | ✅ 签名校验 + 机器绑定    | ✅ 签名校验 + 机器绑定    | ✅ 签名校验 + 机器绑定      |
| 初始化数据         | 默认科目/标签/固定提示文案 | + 补助标准模板/计提模板    | + 借款台账模板/分摊模板       |
| 行业包             | 不附带（固定内置单行业）   | 不附带（后台可配置单行业） | 附带 4 大行业配置包           |
| 部署形态           | SaaS 云端 / 单机部署       | SaaS 云端 / 私有化         | 私有化部署为主               |
| 实施周期           | 1 天（开箱即用）           | 3~5 天（配置补助/计提参数） | 项目制交付（2~4 周）          |
| 升级路径           | —                        | 厂商签发新 License 即可升级 | 新 License + 导入行业包     |

#### 3.4 版本升级流程（零迁移、零代码、厂商授权）

**试用转正：**

1. 客户试用满意后签约，厂商签发正式 `license.key`（licenseType=FORMAL，同机器指纹）；
2. 替换服务器上的 `license.key` 文件，重启服务；
3. 全部功能即时恢复，试用期间产生的业务数据完整保留，无需任何迁移。

**版本升级（基础版 → 高级版 → 企业专业版）：**

1. 客户向厂商申请升级，厂商签发新版本 `license.key`（edition + features 升级，绑定原机器指纹）；
2. 替换服务器上的 `license.key` 文件；
3. 执行目标版本增量初始化 SQL（仅新增默认数据，不修改已有业务数据）；
4. 重启服务，内核验签通过后按新 features 加载功能，前端菜单、后台配置项自动渲染；
5. 客户历史单据、预算数据、审批记录完整保留，无任何数据迁移。

> ❗ 客户自行修改 license.key 内容 → 签名校验失败 → 系统自动降级为基础版并告警，**篡改无法获得任何高级功能，也无法延长试用期**。
