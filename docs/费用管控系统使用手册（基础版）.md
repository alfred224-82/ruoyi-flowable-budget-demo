## 1. 系统概述与版本能力

### 1.1 基础版定位

基础版面向小型企业或部门级应用场景，提供**预算编制→审核→锁定**的最小管理闭环。系统开箱即用，无需复杂配置，帮助用户快速建立预算管控意识。

### 1.2 基础版核心特征

| 特征 | 说明 |
|------|------|
| 审批模式 | 固定单级审批（状态机控制，无需配置工作流） |
| 资金池 | 无 |
| 费用确认方式 | 仅直接费用化（DIRECT） |
| 风控规则 | 固定5条ERROR级规则，不可自定义 |
| 通知方式 | 仅审批结果邮件通知 |
| AI能力 | 不支持 |
| 数据范围 | 单部门 |
| 报表分析 | 不支持 |
| 跨部门分摊 | 不支持 |

### 1.3 与其他版本对比

| 能力维度 | 基础版 | 高级版 | 企业专业版 |
|---------|--------|--------|-----------|
| 审批层级 | 固定单级 | 1~N级可配 | 三级审批 |
| 资金池 | 无 | 部门级单层 | 三级资金池 |
| 费用确认方式 | 仅直接费用化 | 折旧+摊销 | 完整四轨 |
| 映射规则 | 不支持 | 支持 | 支持 |
| 用途标签 | 不支持 | 支持 | 支持 |
| 成本中心 | 不支持 | 支持 | 支持 |
| AI对话填报 | 不支持 | 支持 | 支持 |
| 报表分析 | 不支持 | 不支持 | 支持 |
| 跨部门分摊 | 不支持 | 不支持 | 支持 |

### 1.4 角色体系

基础版采用两级角色：

| 角色标识 | 角色名称 | 职责 |
|---------|---------|------|
| `deptPlan` | 部门预算编制人员 | 编制预算、提交报销、申请预算调整 |
| `deptManager` | 部门经理 | 单级审批（预算审核、报销审核、调整审核） |

### 1.5 核心业务主线

```
预算编制 → 单级审核 → 费用报销 → 预算调整（简易）
```

## 2. 租户与多租户管理

### 2.1 多租户模式说明

本系统采用 **SaaS 多租户架构**，支持多家企业（租户）共享同一套系统部署，各租户之间数据完全隔离。

**核心机制：**
- 每个企业作为一个独立「租户」接入系统
- 所有业务数据（预算、报销、科目等）通过 `tenant_id` 字段实现行级隔离
- 租户A的用户无法看到或操作租户B的任何数据
- 超级管理员（admin）不受租户隔离限制，可跨租户管理

### 2.2 租户信息

每个租户包含以下基本信息：

| 字段 | 说明 | 示例 |
|------|------|------|
| 租户编码 | 唯一标识（不可修改） | T0001 |
| 企业名称 | 公司全称 | XX科技有限公司 |
| 联系人 | 业务对接人 | 张三 |
| 联系电话 | — | 138xxxx0001 |
| 行业 | 所属行业 | 制造业 |
| 规模 | SMALL/MEDIUM/LARGE | SMALL |
| 分配版本 | BASIC/ADVANCED/ENTERPRISE | BASIC |
| 授权类型 | TRIAL（试用）/FORMAL（正式） | TRIAL |
| 授权到期日 | 试用到期时间 | 2026-12-31 |
| 最大用户数 | 允许创建的用户上限 | 10 |
| 状态 | PENDING/NORMAL/DISABLED/EXPIRED | NORMAL |

### 2.3 租户生命周期

```
PENDING（待激活）→ NORMAL（正常使用）→ DISABLED（已停用）
                                      → EXPIRED（已过期）
```

| 状态 | 说明 |
|------|------|
| PENDING | 租户已创建，尚未激活使用 |
| NORMAL | 正常使用中 |
| DISABLED | 平台管理员手动停用，所有用户无法登录 |
| EXPIRED | 授权到期，系统自动标记 |

### 2.4 租户管理员操作（平台管理员）

租户管理功能仅对拥有 `platform_admin` 角色的平台管理员可见。

**操作路径：** 系统管理 → 租户管理 → 租户列表

#### 2.4.1 创建租户

1. 进入「租户管理 → 租户列表」
2. 点击「新增」
3. 填写租户信息：
   - 租户编码（唯一，如：T0002）
   - 企业名称
   - 联系人、联系电话
   - 选择行业、规模
   - 选择分配版本（基础版/高级版/企业版）
   - 设置授权类型（试用/正式）
   - 设置授权到期日
   - 设置最大用户数
4. 点击「确定」
5. 系统自动：
   - 创建租户管理员账号
   - 初始化默认角色
   - 记录版本分配日志

#### 2.4.2 启用/停用租户

1. 在租户列表找到目标租户
2. 点击「状态」开关
3. 停用后，该租户所有用户将无法登录系统
4. 重新启用后恢复正常

#### 2.4.3 版本分配与升级

1. 在租户列表点击「分配版本」
2. 选择目标版本（BASIC → ADVANCED → ENTERPRISE）
3. 确认后系统：
   - 更新租户版本字段
   - 记录版本变更日志（含变更类型：INIT/UPGRADE/DOWNGRADE）
   - 刷新功能开关缓存
4. 租户用户下次登录即生效新版本功能

**版本变更日志：**

| 字段 | 说明 |
|------|------|
| 变更前版本 | 原版本 |
| 变更后版本 | 新版本 |
| 变更类型 | INIT（初始化）/UPGRADE（升级）/DOWNGRADE（降级） |
| 操作人 | 执行操作的管理员 |
| 时间 | 变更时间 |

#### 2.4.4 用量统计

平台管理员可查看每个租户的用量信息：
- 当前用户数 / 最大用户数
- 版本变更次数
- 配置项数量
- 当前版本与状态

### 2.5 租户数据隔离范围

以下业务数据均按租户隔离，各租户互不可见：

| 数据类型 | 隔离表 |
|---------|--------|
| 预算编制 | budget_preparation / budget_preparation_detail |
| 报销单 | fee_expense_bill |
| 预算科目 | budget_subject |
| 预算调整 | fee_budget_adjustment_app |
| 资金池 | fee_reserved_budget |
| 映射规则 | fee_mapping_rule |
| 用途标签 | fee_purpose_tag |
| 成本中心 | fee_cost_center |
| 操作日志 | fee_operation_log |
| 福利政策 | fee_welfare_config |

### 2.6 租户级功能配置

平台管理员可为每个租户单独配置功能参数：

| 配置键 | 说明 | 示例值 |
|--------|------|--------|
| approval_flow | 审批流程配置 | JSON |
| welfare_policy | 福利政策配置 | JSON |
| subject_system | 科目体系配置 | JSON |

**操作路径：** 租户详情 → 功能配置

### 2.7 基础版租户注意事项

- 基础版租户最大用户数默认为 **10人**
- 试用授权到期后状态自动变为 EXPIRED，需联系平台管理员续期
- 基础版不支持的功能（如映射规则、AI填报等）在界面上自动隐藏
- 如需更多功能，联系平台管理员升级版本即可，数据零迁移

## 3. 系统初始化

### 3.1 初始化概述

基础版**无需手动初始化工作流和资金池**。系统采用固定单级审批模式，开箱即可使用。

上线前仅需完成以下基础数据配置：

| 序号 | 配置项 | 操作路径 | 必要性 |
|------|--------|---------|--------|
| 1 | 配置预算科目 | 费用管理 → 预算科目 | 必须 |
| 2 | 配置补助标准 | 费用管理 → 补助标准 | 按需 |

> **说明：** 基础版不支持映射规则、用途标签、成本中心等高级配置项。报销时由用户手动选择预算科目。

### 2.2 预算科目配置

预算科目是预算编制和费用管控的基础数据。

**配置路径：** 费用管理 → 预算科目

**操作步骤：**
1. 进入「预算科目」页面
2. 点击「新增科目」
3. 填写科目编码（如：BX-001）
4. 填写科目名称（如：差旅费）
5. 选择所属会计大类（费用类/资产类）
6. 设置科目类型
7. 保存

**推荐科目设置（小型企业）：**

| 科目编码 | 科目名称 | 会计大类 |
|---------|---------|---------|
| BX-001 | 差旅费 | 费用类 |
| BX-002 | 办公费 | 费用类 |
| BX-003 | 招待费 | 费用类 |
| BX-004 | 交通费 | 费用类 |
| BX-005 | 通讯费 | 费用类 |
| ZC-001 | 办公设备 | 资产类 |

### 2.3 固定审批模式说明

基础版采用**固定单级审批**，无需配置：
- 预算编制完成后 → 部门经理审核 → 通过/驳回
- 报销单提交后 → 部门经理审核 → 通过/驳回
- 预算调整申请后 → 部门经理审核 → 通过/驳回

审批通过状态机控制，不依赖Flowable工作流引擎。

### 2.4 固定风控规则

基础版内置5条ERROR级风控规则，自动生效，不可修改：

| 序号 | 规则说明 |
|------|---------|
| 1 | 报销金额不得为负数或零 |
| 2 | 报销金额不得超过单笔限额 |
| 3 | 预算科目必须已启用 |
| 4 | 预算编制月份不得早于当前月 |
| 5 | 同一科目同月不得重复编制 |

## 3. 预算编制

### 3.1 编制流程概述

基础版预算编制采用向导式三步流程：

```
第一步：基础信息 → 第二步：科目预算编制 → 第三步：预览提交
```

**流程规则：**
- 新增编制：从第一步开始
- 修改编制（被驳回后）：从第二步开始，不可返回第一步
- 查看模式：直接进入第三步

### 3.2 场景一：月度预算编制

#### 第一步：填写基础信息

1. 进入「费用管理 → 预算编制」
2. 点击「新增编制」
3. 填写基础信息：
   - 编制年度（如：2026）
   - 编制月份（如：8）
   - 所属部门（自动填充当前用户部门）
   - 编制说明（可选）

#### 第二步：科目预算编制

1. 系统自动加载所有启用的预算科目
2. 逐科目填写本月预算金额
3. 点击「下一步」，系统保存所有科目金额

> **注意：** 基础版不支持上月实绩数据自动加载，所有金额需手动填写。

#### 第三步：预览与提交

1. 预览所有科目预算汇总表
2. 确认无误后点击「完成编制」
3. 预算单状态变为 `Completed`
4. 点击「提交审核」，进入部门经理审批

### 3.3 场景二：部门经理审核

1. 部门经理登录系统
2. 进入「费用管理 → 预算审核」
3. 查看待审批预算单列表
4. 点击预算单进入详情
5. 审核各科目预算金额合理性
6. 操作选择：
   - **通过：** 预算状态变为 `Approved`，预算锁定生效
   - **驳回：** 必须填写驳回原因，回退至编制人员

### 3.4 场景三：被驳回后修改

1. 编制人员收到驳回邮件通知
2. 进入预算编制列表，找到被驳回的预算单
3. 点击「修改」，系统从第二步进入
4. 根据驳回原因调整预算金额
5. 点击「完成编制」→「提交审核」
6. 重新进入部门经理审批

### 3.5 预算编制状态流转

```
Draft（草稿）→ Completed（完成编制）→ Pending_Dept_Review（审核中）→ Approved（已通过）

审核中 → Rejected（已驳回）→ 修改后重新提交
```

> **说明：** 基础版仅有单级审批，无分公司/总公司审核环节。审核通过后预算即锁定，不可再修改。

## 4. 费用管控（报销管理）

### 4.1 报销流程概述

基础版报销单采用**一步式提交**：
- 创建即提交，无草稿状态
- 无删除功能
- 费用确认方式固定为「直接费用化」
- 状态机：`SUBMITTED`（正常提交）或 `OVER_BUDGET_PENDING`（超预算待审）

### 4.2 场景一：手动填报报销单

1. 进入「费用管理 → 费用报销」
2. 点击「新增报销单」
3. 填写表单：
   - 预算科目（手动下拉选择）
   - 报销金额
   - 费用发生日期（默认当天）
   - 备注（可选）
4. 点击「提交」

> **注意：** 基础版不支持映射规则自动匹配、用途标签、物资小类、多币种等高级功能。预算科目需用户手动选择。

### 4.3 场景二：超预算报销

当报销金额超过对应预算科目可用余额时：

1. 系统自动检测超预算
2. 报销单状态变为 `OVER_BUDGET_PENDING`（超预算待审）
3. 部门经理收到审批通知
4. 审批操作：
   - **通过：** 报销单生效，扣减预算余额
   - **驳回：** 报销单作废

### 4.4 场景三：报销审批（部门经理视角）

1. 部门经理进入「费用管理 → 费用报销」
2. 查看待审批报销单列表
3. 点击报销单查看详情：
   - 报销人、部门
   - 预算科目
   - 报销金额
   - 费用日期
4. 审批操作：通过/驳回

### 4.5 预算可用余额计算

```
可用余额 = 预算金额（budget_amount）- 已审批通过的报销总额
```

系统实时计算各科目可用余额，报销提交时自动校验。

## 5. 预算调整

### 5.1 调整流程概述

基础版支持简易预算调整，采用**单级审批、无资金池**模式。

### 5.2 场景一：发起预算调整申请

**操作步骤：**
1. 进入「费用管理 → 预算调整」
2. 点击「新增申请」
3. 填写申请信息：
   - 选择目标预算科目
   - 输入申请金额（调整后的目标金额）
   - 填写调整原因
4. 提交申请

### 5.3 场景二：部门经理审批

1. 部门经理进入「预算调整」审批列表
2. 查看申请详情：
   - 申请人、目标科目
   - 申请金额、当前可用余额
   - 调整原因
3. 审批操作：
   - **通过：** 系统直接将科目预算金额更新为申请金额
   - **驳回：** 必须填写驳回原因

### 5.4 场景三：审批通过后生效

审批通过后：
1. 系统自动将 `budget_preparation_detail.budget_amount` 更新为申请金额
2. 后续报销即可使用新额度
3. 无资金池扣减逻辑

### 5.5 预算调整状态流转

```
部门审批中(DEPT_APPROVING) → 已通过(APPROVED)

部门审批中 → 已驳回(REJECTED) → 可修改重提
部门审批中 → 已撤回(CANCELLED)（申请人主动取消）
```

> **说明：** 基础版无分公司/总公司审批环节，部门经理通过即生效。

## 6. 常见场景操作指南

### 6.1 场景：新公司快速上线

基础版上线极简，仅需两步：

| 步骤 | 操作 | 耗时 |
|------|------|------|
| 1 | 配置预算科目（5~10个常用科目） | 10分钟 |
| 2 | 分配角色（编制人员 + 部门经理） | 5分钟 |

无需配置工作流、资金池、映射规则等，系统即可投入使用。

### 6.2 场景：月度预算编制闭环

```
月初 → 编制人员新建预算（手动填写各科目标金额）
     → 完成编制 → 提交审核
     → 部门经理审批通过
     → 预算生效
月末 → 查看各科目余额执行情况
```

### 6.3 场景：日常费用报销

1. 员工发生费用（如：出差交通费 500 元）
2. 进入「费用报销」→「新增报销单」
3. 选择预算科目「差旅费」
4. 输入金额 500
5. 提交
6. 部门经理审批通过
7. 差旅费科目可用余额减少 500 元

### 6.4 场景：预算不足需要调整

1. 编制人员发现「招待费」科目余额不足
2. 进入「预算调整」→「新增申请」
3. 选择目标科目「招待费」
4. 输入目标金额（如：从 5000 调整为 8000）
5. 填写原因："本季度客户接待增多"
6. 提交 → 部门经理审批
7. 通过后，招待费预算金额变为 8000

### 6.5 场景：超预算报销处理

1. 员工提交报销单，金额超出科目余额
2. 系统自动标记为超预算
3. 部门经理收到超预算审批通知
4. 部门经理判断：
   - 合理支出 → 通过（允许超支）
   - 不合理 → 驳回
5. 若需长期增加额度 → 走预算调整流程
