### 3.7 Flowable 三级审批流程定义

```
开始事件 → 部门经理审批(deptLeaderReview) → 分公司本部审批(branchLeaderReview) → 总公司本部审批(hqLeaderReview) → 结束事件
```

| 节点 | ID | 候选组 | 角色配置 |
|------|------|--------|----------|
| 部门经理审批 | deptLeaderReview | ROLE3 | role_id=3, role_key=dept_leader |
| 分公司本部审批 | branchLeaderReview | ROLE4 | role_id=4, role_key=branch_leader |
| 总公司本部审批 | hqLeaderReview | ROLE5 | role_id=5, role_key=hq_leader |

流转网关条件：
- result=='pass' → 下一级审批（或结束事件）
- result=='reject' → 退回编制人（deptBudgetPrepare）

### 3.8 状态机实现（双字段设计）

```
status: Draft → Completed → Pending_Review（approval_stage: Dept → Branch → HQ → Approved）
任意审批级 → Rejected（驳回，回退到编制人员）
```

| 操作 | 状态变更 | Flowable 动作 |
|------|---------|---------------|
| 完成编制 | Draft/Rejected → Completed | 无 |
| 提交审核 | Completed → Pending_Review + Dept | startProcessInstanceByKey("budgetProcess") |
| 部门经理通过 | approval_stage: Dept → Branch | taskService.complete(result=pass) |
| 分公司通过 | approval_stage: Branch → HQ | taskService.complete(result=pass) |
| 总公司通过 | status → Approved, stage → None | taskService.complete(result=pass) + 流程终止 |
| 任一级驳回 | status → Rejected, stage → None | taskService.complete(result=reject) + 流程终止 |

| 字段 | 内容 |
|------|------|
| **用例编号** | UC-1001 |
| **用例名称** | 新建预算编制 |
| **参与角色** | A1 部门预算编制人员 |
| **前置条件** | 用户已登录，具有编制权限 |
| **触发方式** | 用户在编制列表页点击「新建」按钮 |
| **基本流程** | 1. 系统打开3步向导表单（第1步：基础信息）<br>2. 用户选择年度、月份、组织，系统自动填充编制人<br>3. 系统自动校验同部门同月份是否已存在编制记录（重复校验）<br>4. 校验通过，进入第2步：科目预算明细<br>5. 系统自动查询上月已审批通过数据，填充到对应科目（UC-1008）<br>6. 用户按6种科目类型分Tab录入/调整预算金额<br>7. 系统实时计算预算总额并展示<br>8. 用户点击「下一步」，系统保存明细数据（先删后插），后端汇总更新总额<br>9. 进入第3步：确认提交，展示汇总信息<br>10. 用户点击「完成编制」，状态变为 Completed |
| **后置条件** | 预算编制记录创建成功，状态为 Completed，自动生成单号 BG-YYYYMM-XXX |
| **异常流程** | E1: 重复校验不通过 → 弹出警告，阻止进入下一步<br>E2: 明细数据保存失败 → 提示错误，停留在当前步骤 |
| **业务规则** | 单号自动生成；明细表无数据则新增，有数据则先删后插（全量更新）；金额必须为数值类型 |
| **技术实现** | 单号生成：`String.format("BG-%s-%03d", yyyyMM, seq)`；明细保存：先删后插 + @Transactional；实体：BudgetPreparation + BudgetPreparationDetail；前端：wizard.vue 新建模式（完整3步向导）；接口：POST /system/preparation |
