四、隐私分级原则（总纲）

本章是全文档关于「什么信息对谁可见」的统一依据。后续新增功能若涉及个人信息，按本章原则判断，不需要重新讨论。

4.1　核心原则

一句话：<b>门店信息公开，个人信息默认不公开；需要时由管理端可控释放。</b>

原则

说明

默认收紧

个人信息默认不可见，而不是默认可见再关闭

可控释放

需要公开时由管理端开关决定，不是系统写死

最小够用

只给达成目的所必需的最小信息，不多给

本人优先

涉及个人联系方式，交给本人决定是否公开

集中管理

门店级信息一处维护，不散落在各活动重复填写

4.4　两条配套规则

① 隐藏必须配套补偿

选座页隐藏了姓名，就必须有员工分享座位对照表作为补偿路径（见第十三章）。<b>只隐藏不给出口，等于让顾客既看不到也问不到</b>，是残缺设计。

② 隐私与可用不冲突

员工个人开关可以全部关闭，顾客仍能通过门店联系方式找到人。两个需求同时满足，不需要二选一——这正是分层设计的好处。

4.5　落地检查清单

新增任何涉及个人信息的功能时，逐条确认：

□ 这条信息属于 L1–L4 哪一级？

□ 默认可见还是默认隐藏？默认应取更严格的一侧。

□ 谁有权决定公开？系统写死、老板开关，还是员工本人？

□ 隐藏后，用户有没有替代路径达成目的？

□ 涉及联系方式的，报名页是否已加告知文案？

图标变色的关键做法

图标文件里写 fill="currentColor"，但用 <img> 加载时 SVG 是独立文档，currentColor 会解析成默认黑色。改用 CSS mask 方案：把 SVG 当镂空模板，颜色由 background 决定。这样文件仍是独立 SVG，但颜色能被 CSS 变量控制，切主题自动换色，不用换图。

注意：CSS mask 加载外部 SVG 受 CORS 限制，本地 file:// 打开会被拦截。解决办法是转 base64 data URI（base64 只含 A-Za-z0-9+/=，不含引号括号，可安全放进 HTML 属性与 CSS url()）。

十二、客诉预防

敏感词检查的目的不是内容审查，而是防止客诉。

活动文案里出现「稳赚不赔」「零风险」「国家级」这类夸大或承诺性用语时，客户事后很容易拿文案当依据要求退款、投诉或产生纠纷。本章的机制是在提交前拦一道，把这类表述挡掉，从源头减少客诉。

12.2　拦截日志（只读）

命中即拦截，内容并未提交成功，因此不存在需要复核的待办队列。后台保留拦截日志用于留痕：谁、什么时间、尝试提交什么、命中哪个词。老板无需处理，出事时可追溯。

12.3　图片与用户准则

图片不做技术审核，不接云 API，不做 OCR。理由是：云 API 除调用费用外还有对接开发成本（SDK 接入、回调处理、审核中状态、异常队列），至少数天工作量，对小平台不划算。

兜底已由顾客端投诉入口承担（见 11.0）：顾客发现问题可直接投诉，老板端收到后立即处理。这比图像审核更直接，也更省成本。

若后续确需补充，可在用户准则中写明内容责任归属与平台免责条款，包含内容责任、展示授权、违规处理、举报机制、免责五项。注意准则只能减轻责任，不能免除——收到投诉后必须及时处理。

12.4　技术实现要点

· 前端预检 + 服务端终检：前端只为即时反馈，服务端才是权威，前端可被绕过。

· 变体归一化：繁简转换、全角转半角、去空格标点、谐音与拼音映射。

· 匹配算法：Aho-Corasick 多模式匹配，万级词库毫秒级。

· 词库热更新：后台改词即时生效，不用重新发版。



十三、名单截图分享

把员工"手动截图发微信群"这个动作做成系统功能：前端把报名名单渲染成一张干净的长图，员工点一下生成，保存后发群。

为什么必须要有这个功能（关键）

选座页采用最小信息披露——已占座位只显示「已占」，<b>不显示姓名与头像</b>（见 6.3）。这就带来一个缺口：<b>顾客无从知道谁坐在哪个位置</b>。

本功能是这个缺口的唯一补偿路径：由员工生成座位对照表发到活动群，顾客在群里看这张图就知道自己和同伴坐在哪。

两者是配套的——选座页隐藏信息，分享功能把信息以可控方式释放给群成员。少了分享功能，选座页隐藏姓名就成了残缺设计：顾客既看不到、也问不到。

另一个原因：替代手动截图

员工手动截图有两个问题：一是截的是自己手机屏幕，机型、状态栏时间、电量都不同，发出去不专业；二是可能截到别的顾客的完整信息。用前端生成图，输出的是统一排版的干净长图，且手机号在生成时就已经脱敏。

14.1 设计原则：分成规则挂在员工档案，不在活动里配比例

十八、H5 微信分享能力边界与演进路线

18.1 结论

H5 在微信群里可以显示成带标题、缩略图、描述的卡片，属于微信标准能力，开发量约 1 至 2 人日。但真正的门槛不在技术，而在资质：需要已认证的企业或个体工商户公众号、完成 ICP 备案且启用 HTTPS 的域名、服务端签名。

另外一个硬限制：在微信内置浏览器中，H5 无法主动调起分享面板，无论是否接入 JS-SDK，最后一步都必须由用户手动点击右上角。因此 H5 内做「一键分享到微信」按钮在 MVP 阶段不成立。
